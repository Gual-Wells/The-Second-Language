# 雅思练习协议（第四部分）

第四部分仅申请“完整雅思”或“微缩雅思”，两种均建设听力、阅读、写作、口语全流程。完整听读各四十题；微缩听读各二十四题，写作和口语保持完整组件。产品名称为“雅思练习”，规则见 PRACTICE_SIZES.md。日课仍为三部分、40 主词；第四部分长期保存，不写 `chapter.md`，不占临时页，不改 VIX。原声回答分析沿既有 SPEAKING_PIPELINE 执行，正式 PWA 已接原声录制、上传、采集和 Codex 反馈，文字补充仍只评价文字维度；运行通路见 SPEAKING_RUNTIME.md。

申请、出题与书架顺序为 **听力 → 阅读 → 写作 → 口语**。这采用雅思笔试顺序；口语正式考试可另日安排，产品不强制一次坐完全部。两种申请都必须完整建设四科，不再接受单科或混合听读题量申请。听力和阅读各按申请规格建设，题量和条件明确记录；完整和微缩分别分析，不换算为彼此或官方成绩。

## 雅思规格

- 听力完整：四段、每段十个计分空位，共四十题，完整音频约三十分钟（包含读题和检查停顿）；四种情境、人物数量、题型和题文顺序按官方形式。正式题组的音频、题面和答案证据一起闭合。详见 LISTENING.md。
- 听力微缩：四段、每段六题，共二十四题，约十八分钟；完整题型覆盖与平均及以上难度，见 PRACTICE_SIZES.md。
- 阅读：完整三篇四十题、六十分钟、2150–2750 词；微缩三篇各八题、三十五分钟、1400–1900 词，题型不缩略，排除雅思通常难度分布下段。详见 READING.md。
- 写作：Task 1 与 Task 2 各一题，共六十分钟，建议二十/四十分钟，最低一百五十/二百五十词；反馈按官方四维，综合时 Task 2 权重为 Task 1 的两倍。当前工程支持 Task 1 可见结构化数据表；可使用清楚标为原创假设的数据，必须同表格和范文一致，不能虚构真实统计来源。其他图形后续用同样的可核对数据载体扩展。不因篇幅不足拒收本人真实答案。
- 口语：完整 Part 1/2/3，约十一至十四分钟；Part 1 与 Part 3 各约四至五分钟，Part 2 一分钟准备、最长两分钟陈述及简短跟问。没有官方固定的总问句数，不创造机械题数要求。题量需足以支持各 Part 的自然交流；Part 2 一张主任务卡。考官题音频固定按 VOICE_ROUTING.md 的 Kokoro Bella 生成；Part 1/3 默认只给声音，主动查看原文会记录；Part 2 卡片保持可见。参考答案均为隐藏文本。

上述是内容和作答条件标准，生成练习与估计反馈没有经过官方题库的预试和分数校准，不声称官方认证或复刻真人考官。口语固定问题与后台原声分析也不能冒充实时真人访谈。

## 申请与来源

读者开启默认关闭的申请开关后，只选完整或微缩；默认完整，可选侧重仍可填写。客户端提交 `size=full|mini`，后端生成固定四科的有序 `skills`，以及同规格的 `profiles.listening`、`profiles.reading`，以 `protocol_version=ielts-bundle-v1` 保存；成品仍为已有 `format=ielts-v2` 结构，固定**第一章至当时最新已发布章节**的 ID、日期和正文 digest，以及显式焦点章（默认最新已发布章）。待发布申请不重复创建；超过领取期限后可重新领取，已有工作文档继续使用。申请不领取日课运行、不改 VIX，也不自动触发教材检索。休息按钮仅控制既有每日 03:00 日课；雅思申请由独立处理通路领取。旧版已发布练习继续可读，未发布新申请/草稿应按新规格补齐，不静默改写旧题。

随着章节增加，Codex 可以增量维护逐章主题与可迁移表达索引，但每次出题须看到第一章至申请时最新已发布章的完整章节清单及其 digest；焦点章和经主题筛选入围的其他章须回读正文。主题索引只作导航，不能用摘要替代入围章节。章节修订后，旧练习册保留当时的 digest 和题目版本，不悄悄改题。

## 题目建设

先从真实雅思任务形式与能自然讨论的日常、社会、教育等话题提出多个候选，再用累计课程内容和用户历次反馈寻找有价值的联系。当前焦点章获得显著的**判断注意力**，不设词汇命中配额；本章材料若不适合题目，使用更合适的旧章。题目不得要求使用指定单词、复述第三部分文章或展示课程内部编码。按所选组件和题量完成上述规格，不能为了提高词汇覆盖破坏题目自然性。

在 `work/expression/<request-id>/` 自由保存来源地图、候选题与驳斥、题目定稿、参考答案草稿、质量审阅及续作说明。逐题确认问法真实、应答空间足够、并不依赖专业知识或虚构统计；检查 Part 2 是否可讲个人经历，Part 3 是否较之 Part 2 更抽象；写作题是否要求清楚且容纳不同立场。正式题目为原创，不能复制官方样题全文。生成的每道题至少有一个自然关联的来源章节；关联到 `USE` 时使用复合身份 `章节ID#USE编码`，仅作读书器导航，不当作答题硬指标。无真实关联的强制命中应删除。

每道口语、写作题给出默认隐藏的约 7.5 水平教学示范、立意与替代路线。示范不是唯一正确答案，也没有官方认证的分数。提交前可主动揭示，但记录已提前查看，后续反馈据此说明练习条件。口语示范需保持自然口语长度和语体，不把写作范文改行充当口语；写作示范完整回应题目并容许另一合理立场。展示层不以 CSS 隐藏答案，未揭示前后端不向浏览器发送参考文本。

## 作答、批改与保真

个人作答与批改在独立 `PRACTICE_DB` 中，不提交公开仓库。每次文字提交形成不可变 attempt，绑定题目版本；重答生成新 attempt。后端待批改队列通过发布令牌供 Codex 领取，领取与完成有幂等身份。Codex 先独立阅读题目和答卷，再使用参考答案作为启发而非逐字比对标准；按官方四维标准分析，指出已有优势、最重要的改进点和可操作的重答建议，不因没用课程词汇扣分，也不把练习估计说成正式雅思评分。提交后可从 PWA 查看反馈与先前尝试。

口语提交以原始录音为权威；默认 Whisper、Gemini Flash、Qwen、GPT Audio 各一次完整独立采集，再交由 Codex 全量分析，按 `SPEAKING_PIPELINE.md` 使用 prompt、适配的 Schema/最终 JSON、全部原始返回、来源和故障代偿，允许按具体目标追加 Qwen 补听。腾讯专项可按需补充句子/单词音素资料，使用本人实际原话；未经核验的数值不直接换算 IELTS band。语音识别的文字不能证明发音、节奏或真实停顿；没有声音依据时先在工作文档完成有依据的分析，OpenRouter 缺钱按当前协议停止新增收费调用，仅在用户充值后明确要求继续时处理，不自动跨日重试，不把未完成声音任务标成最终完成；日课与写作继续。录音进入独立私有资产存储，库内只存受控定位、摘要和状态；可通过原文件格式转换和固定多路采集进入 Codex 教学接管，具体见 SPEAKING_RUNTIME.md。

## 索引与版本

文字提交在浏览器先固定答卷 ID 与正文，收到成功确认后才清除草稿。同一 ID 的同一题目、正文、媒介重发只复用原答卷与原练习条件；同一 ID 改写正文返回冲突。真正重答使用新 ID。参考答案揭示顺序同时检查文字与原声答卷，不能将已提交原声后的揭示记为答前查看。

正式音频计划放在本次 `work/expression/<request-id>/claim.json` 的目录或子目录，合成控制携带申请与领取身份。余额不足、提供商失败或计费结果未知时，申请停止自动建设，原成稿、已成功片段与固定练习册 ID 保留，其他任务继续。仅本人明确要求继续后，使用 `practice-job.mjs claim <request-id> --continue` 重新取得身份并继续原计划；普通队列领取不包含停止的申请。未确定计费的片段仍不得自动重复调用。音频脚本成功或失败均执行末尾额度核对与归档排队。

原声评价的当前接入与能力代偿遵循 `SPEAKING_PIPELINE.md`，具体工程接入见 `research/speaking-facilities-engineering.md`；`SPEAKING_ASSESSMENT.md` 保留历史试验。本机/独立云端工具与正式 PWA 上线状态分别记录。每日正文点读采用后台按需生成并复用的 Kokoro Bella；第四部分的听力材料和考官提问单独生成持久音频，不让声音评测阻塞每日文字课程。

长期索引支持练习册、焦点章、任一来源章、题型、题目、复合 `USE` 身份、申请状态、作答状态与反馈状态。题目版本、参考答案版本、来源 digest 与 attempt 绑定；不能拿后来修订的答案默默重评旧尝试。Codex 读取接口和未来 Chat/MCP 只经后端授权，提供必要范围的题目、索引、个人答案和反馈，不直接暴露 D1 或存储密钥。Chat 手动对话不承担唯一可靠的异步批改队列。

## 任务末尾额度更新

执行本协议所涉及的日课、推送、练习建设、批改、声音分析或测试工作时，最后按 `BALANCES.md` 查询各方额度，携带核对时间、核实/估算状态与用户完整学习流程的用量范围，发布更新到余额页；各方仅在不足三次最大消耗任务的预留时提醒。页面显示上一次任务的记录，浏览时不实时查询。不自动付款，不安排余额不足后的跨日轮询/重试；已有材料与未知计费保护继续有效。
