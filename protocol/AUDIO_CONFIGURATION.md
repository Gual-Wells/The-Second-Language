# 章节音频配置

用户决定（2026-10-12）：每日日课默认满配句子音频；2026-10-10 取消词汇点读的决定仍有效。满配仅指第二部分所有英文例句、第三部分范文每个英文句子，固定 Kokoro Bella，不包含第一部分、词汇标题、释义、解析散文或译文。

## 每日日课与一次性调整

- 新正式章节首次 commit 时，D1 在同一个发布事务中创建固定正文 digest 的满配音频申请。独立音频服务在正文发布后处理，文字课程和 VIX 不等待声音，不因音频故障回滚。
- 设置 → 音频配置 → 下一章日课保留一次性调整：默认第二、三部分均勾选，可在发布前修改或全部关闭，直接保存，不额外确认。首次发布消费该次设置后恢复 `["two","three"]`；即使这一次全部关闭，后续章仍恢复满配。
- 休息、领取运行、临时页及已有章节重发不消费下一章设置，也不重复入队。当前章已经发布后调整仅影响下一新章，不静默追加当前章费用。
- 部署迁移 0015 将现有下一章设置初始化为满配。此初始化是用户本次直接指令，不以旧默认空选配继续执行。

## 已有章节申请与执行

- 已有章节选择项目后，后台读取不可变正文并核对 digest，创建十分钟有效计划/报价。页面显示范围、预计费用及确认后不能撤销；确认以前不合成，确认以后无撤销接口。同一 quote 重复确认不生成第二项任务。
- 用户在对话中明确要求补齐已有章时，Agent 可按其范围查询、报价并确认，不重复请求相同授权；通过原申请通路留下计划和进度，不绕开生成账本。本次补齐以当前已发布章节版本为准，完成后逐章核对全部合规句子及下载清单。
- `SecondLanguage-AudioPreparation` 用无窗口 BackgroundTask 每分钟检查队列，本机运行且联网时执行。普通 Node 脚本，不调用 Codex 推理；与答疑、日课、归档独立并有单实例互斥。电脑关机时不承诺执行。
- `scripts/audio-worker.mjs` 用发布身份领取任务，经 Cloudflare `/api/practice/pronunciation` 调用既有 Bella 通路；OpenRouter 不由本机直连。队列只有固定版本、状态、游标与计划位置，完整计划及终态记录在 OneDrive。
- 恢复的是处理租约，不是重复付费权。成功音频复用，正在调用等待状态；HTTP 402 等待充值，仅用户点击继续或明确要求恢复时入队，不自动跨日重试。未知计费、明确失败等进入核对，不借新申请绕过原声音账本。
- 每个成功音频关联固定章节 digest。归档服务将已生成句子打包供预下载；原件暂不可用不当作未生成。不批量写 KV，不建设新的音频数据库。
- 原声已进入永久索引或 ready 故障副本后，后续章节关联/排队报错不能降级成功结果或覆盖其计费元数据。真正没有成功原件的未知调用继续暂停；历史误标只能核对原身份、原字节与完整解码后恢复，不借恢复重新合成。

## 单元与复用

`web/audio-plan.js:audioUnits` 只提取第二部分 `EXAMPLE` 后的英文原句与第三部分 `SENTENCE` 后的英文原句，去除显示强调语法，不朗读中文和编码。第二部分词汇标题仅跳第一部分对应标题，第一部分不发音。

同一文字、模型、音色、格式与声音策略共用既有生成身份；重复例句、跨部分和跨章节均可复用。重复 `EXAMPLE` 仍表示所属用法，不虚构唯一例句编号，不改正式章及摘要。全量提前生成与按需点读使用同一身份，不建设第二套音频原件。

章节请求核对固定原件及完整句子；碎片、杂文、单词请求拒绝后才进入收费身份。预下载清单用 `pointAudioPolicy=chapter-sentences-only-v2` 标记范围，打包与浏览器均筛选正文内的 Bella 完整句子。清洗只重建清单及包指针，已付费原件、完整生成记录、旧包及不可变成功关联保留。

历史词汇/音标描述、Misaki 音素转换和旧 hash 继续用于读取历史付费资产；它们不再构成新词汇生成入口，也不作为满配的一部分。旧申请里的词汇单元由执行器跳过，不重新收费。原高光跳义项、长按答疑、非英文区双击纯净模式、切章停止、私有读取与 Range 保持。

## 费用与完成

设置分别标注第二部分与第三部分人民币估算。已有章节按定稿文本、真实合成输入及已成功缓存计算；联合选择跨部分去重。下一章无定稿时按最近三章同项目字符范围估算，明确为样本而非硬上限；无样本显示待定稿。

`audioPrice` 使用当前路线规划区间 $0.62–$0.99 / 百万字符、7 元/美元预算换算，不冒充实时价格或汇率。实际收费与异常核对以提供商结果为准；不购买新套餐、不自动充值、不重复收费。复播和传输不调用 TTS。

任务完成按 BALANCES.md 更新额度与存储用量，排入既有永久归档。音频原件 ready、章节关联及合规清单全部覆盖后才宣称补齐；入队不是完成，待核对不是完成，界面/原声质量的人工验收也不能被计数取代。

## 入口与验证

- 前端：设置 → 音频配置，沿用同一原生弹层。
- API：audio-config 的 next / estimate / quote / confirm / resume；jobs/claim / jobs/progress 仅发布身份。
- 数据：主库 0009_audio_requests.sql、0015_daily_full_audio.sql；成功音频紧凑索引不变。
- 验证：check-publishing-closure.mjs（连续章默认、单次调整、空调整、重复发布、休息）；check-audio-config.mjs（确认、权限、去重、原件复用与故障保护）。
