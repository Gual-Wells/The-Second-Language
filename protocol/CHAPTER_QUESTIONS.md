# 章节答疑

前端入口及异步草稿遵循 [READER_INTERACTION.md](READER_INTERACTION.md)：顶栏入口持续可见；历史新回复按日期与版本直接定位；发送成功不能清空等待期间输入的下一问；模型文本安全排版，不执行返回的 HTML。

正文标题上方的章节答疑入口提交问题；默认携带当前章的固定摘要身份。服务端从该身份读取整章原文，全部会话交给独立本机 API 运行器。历史会话保留原版，不随改章漂移。答疑不参与 VIX 标记、日课推荐或雅思申请。

新默认 `usage-context-v1`／`authentic-context-v1` 是单正文。词汇标题长按、英文语境整句长按、句中词双击均走原答疑通路。句子问题携准确原句、词条标题、contextId、SENTENCE身份及实际USE引用，并附所在英文语境；句中词额外指明同形词第几处，要求解析所有实际使用的相关用法，不附会未使用义项。每份语境的中文是一个整块译文，不虚构逐句中文配对。无需新增上下文数据库或在请求中再复制整章：后端已按固定digest核对并提供全文与完整会话。无弹窗、无自动改章、无额外确认；仅提交状态提示，回复继续通过既有入口及红点读取。

已冻结的旧三部分版本继续按原格式定位：第一部分词汇标题长按、第二／三部分整句长按及句中词双击；多篇第三部分保留篇目标题、全章句序及SENTENCE标记。共享语境不把同一文本的所有出现当成同一词义；新旧格式都交付完整固定版本，不截成某个词族、不重指到新版。旧章封存及任务资格仍按CURRENT_AFFAIRS，不因保留旧格式读取而恢复封存任务。

快捷提交不复用手工编辑器状态，不改变未发送草稿或当前会话选择。并发提交同焦点受保护，成功后短时间去重；失败或失联保留该问题的幂等编号，仅用户重做同一手势才重试。切章前发起的请求保持原章身份，不受后来页面切换影响。不对临时页、演示、未登录或离线情况自动提交。

独立 Windows 任务每分钟由普通脚本检查队列，没有问题不启动模型，也不查询收费服务余额。有待办时隔离工作目录 `work/questions/<message-id>/` 保存全文、会话与回答；问答通过 OpenAI Responses API 的 gpt-6.1-sol／xhigh 分析，使用同系列共用密钥路径而不复制密钥，不读取发布凭据，不采用用户配置中的外部连接器。2026-10-30用户暂调API问答为xhigh；Codex出版及其他任务档位不变。确定性脚本负责续租、幂等回推；已生成答案优先回推复用，不再次生成。

本机通过 OPERATIONS.md 所述无窗口启动器运行，不创建可见 PowerShell 控制台，不为每次空检查发通知。异常写入私有日志并保留非零计划任务退出码；实际答疑失败仍由产品展示重新处理入口。个人全访问配置不改变这个只读教学进程的隔离范围。

整章与完整会话直接随本次分析输入提供，不依赖模型额外读取文件。问答使用 HTTPS Responses API，不提供工具，不发送发布凭据；新客户端以本机已确认密钥调用；按 JSON schema 提取回答，过程资料与结构化结果在任务目录保留。

同章问题按提交顺序处理，后续问题包含已完成回答。中断或失败保留所有资料并显示重新处理按钮，不安排额度不足后的跨日自动尝试。每个完成或失败的实际分析任务末尾按 BALANCES.md 更新额度；纯队列检查不消耗模型额度。

回复永久保存，前台检查新回复并显示红点；打开入口即按同一事务快照确认全部会话当时的回答已读，并保留原未读边界，定位第一条未读问答的问题，显示临时“未读消息”分隔线；事务之后的新回复仍未读。离线草稿保存在当前设备，重复提交用固定请求编号去重。账户退出清空页面会话；重新登录后可再读取。设备需开机、Windows 用户会话可运行、网络及 API 凭据有效；云端排队不等于本机始终在线。

## 配对与共用监测（2026-10-10）
接口显式返回 `replyTo`，前端按提问顺序逐组展示，每条答复插入它所回复的问题下方；不按全部消息到达顺序堆叠。晚到回复保持读者当前消息锚点、未读状态与手工输入。
原答疑领取通路也监测章节测试，按可执行申请时间先后领取。`kind=chapter-test` 走独立出题 schema 与完成接口，不能写成聊天答复。版本全文、工作租约及任务末尾额度/归档保护保持。对应协议 CHAPTER_TESTS.md。

## API 接手问答（2026-10-30）

question-api-worker.mjs仅领取questionsOnly；服务端API_QUESTIONS_ENABLED启用后，旧共享运行器不再领取普通问题，仍处理原章节测试、口答核对和质检。日课、雅思建设、质检与认证出题继续既有Codex流程，不随本次改为API。旧运行器的工作树及既有成功结果保留；固定原件与完整会话一致时可复用旧答案。新任务目录work/questions-api仅保存本任务原件、请求、响应和结果，不入Git。

所有新API调用先落盘不可重复的发送标记，保存原始返回及usage，成功回答先保存后回推；网络中断、服务端5xx或不完整返回不自动重发。明确4xx拒绝只在用户重新处理后允许新的调用，不做SDK重试或跨日续跑。API额度登记发放与已核余额分开；本机token记录不是官方钱包余额。没有任务仅查询自有队列，不调用OpenAI。

2026-10-30故障修复：本机API运行器使用Node 24.14或以上。代理配置在任何请求之前调用Node官方setGlobalProxyFromEnv，重新配置fetch及HTTP/HTTPS代理；仅在进程启动后修改环境变量不足以更新已经初始化的请求分派器。失败只保存安全错误码、阶段和耗时，不记录凭据或原始网络异常。网络结果未知仍停止自动重发；更换档位不绕过发送标记。

长分析使用Responses官方SSE流式传输（stream=true），保留store=false、完整上下文及原结构化输出。只采用response.completed的完整结果，先持久化响应头和原始事件；连接中断或缺终态即使HTTP200也作为未知结果停止，不自动重发。SSE分帧复用固定MIT eventsource-parser 4.1.3，不自行实现通用协议、不引入其重连行为。仅stream开关变化时可复用已有完整响应，其他语义输入变化仍拒绝；旧未知请求仍须授权处理。

## 答复提醒与交互保护（2026-10-30）

完整答案、完成状态及question_push_outbox在同一事务写入；每问题每已订阅设备唯一，通知失败不回滚已保存答案，也不重新调用模型。复用原设备订阅/VAPID及既有cron；成功回推后尽力立即发送，失败由既有检查有界重投，最多四次。锁屏只显示通用答复提示，不含问答正文。已读或账户epoch变化时停止旧待发提醒；30天仅清理投递元数据，问题与答复不受影响。提醒设置同时核对浏览器订阅和服务端登记；iPhone原生权限保持在真实用户点击中发起。

通知携带精确questionId/chapterId/digest；点击从真实匹配的问题打开固定历史会话并定位，不借历史通知恢复封存正文或付费资格。普通入口继续跨章未读优先与打开快照；晚到回复不被旧快照吞掉。手工发送的幂等编号在发请求前持久保存，丢ACK后关窗/重载仍复用；旧草稿保留。明确未知计费及API过期租约状态不显示普通重做、不借retry重新排队，保留原件供核对。

## 云端章节答疑（2026-10-31，先部署代码后切换）

用户授权章节答疑的ChatGPT API执行迁到项目自身Cloudflare Worker，使电脑关机不影响新问题处理。本节取代前文普通API答疑必须本机在线的限制；日课出版、章节测试、质检、VIX、声音与旧Codex运行器的其他任务不变。默认`API_CLOUD_ENABLED`关闭，不因安装代码自动启用或领取旧任务。先执行0023、0024迁移并配置运行时绑定，再由显式部署步骤打开开关。

0023为原问题加`execution_route`，全部已有行留作`legacy`；只有开关开启后新提交的问题记`cloud-v1`。同ID提交重发保留原路由。本机HTTP领取及其过期检查只处理legacy；云端只处理cloud-v1，保留同会话前序阻挡与固定digest全文、完整会话。旧pending/running/failed、旧本机发送标记与成功答案不自动迁移、不重新生成。唯一显式例外是用户对已知失败点击重新处理：开关开启时这次新请求CAS切为cloud-v1；无开关仍沿legacy。retry守住读取时的attempts、error及route快照，不能由并发旧请求清除后来出现的未知保护。旧未知结果必须继续核对，不借切换清除保护。

独立系列api-clock每分钟通过固定Service Binding调用`LanguageAPIExecutor.run()`；时钟不持项目数据库、私文或模型密钥，入口不接收任务参数、不返回私人内容。项目原提醒/维护Cron保持原逻辑，API RPC有独立D1调用预算。云端直接调用内部领取/续租/完成函数，不模拟发布者请求、不读取发布凭据。使用`worker/src/shared/cloud-responses.mjs`的项目级14分钟持久singleflight；模型、xhigh、16384结果token上限与10分钟时限保持。运行时每60秒通过单条正式版本/claim/lease CAS续业务租约。最坏离线夹具10次续租、16份原始流片段、答案事务与本源用量同步共48次D1操作；这不等于线上CPU或实体设备验收。仅Worker执行时取得`SECOND_SERIES_OPENAI_KEY` Secrets Store绑定，兼容已有`OPENAI_API_KEY` Worker secret。开发工具不读取密钥值，也不复制到代码、D1、日志或前端。

共享runtime先在项目D1持久化不可重复的发送身份`(second-language,question-id,attempt)`和请求摘要，再发送唯一Responses POST。保留store=false、SSE、原始事件、完整终态及usage；未取得完整终态、连接中断与未知计费停止重发。只有用户明确重新处理的已知失败才增加attempt；时钟重入与完成恢复不增加。完整响应已保存而业务提交中断时，后续时钟只恢复同attempt答案、完成状态及通知outbox事务；即使凭据暂不可用也可恢复已保存答案，不再次调用模型。

答案与通知outbox继续同事务提交；云端答案正常由下一轮原提醒Cron投递，避免API调用预算随设备数量增加，旧HTTP完成接口仍可尽力立即提醒。推送失败由原有最多四次投递维护处理，不能退回模型队列。云端usage是实际返回token记录，仅以聚合metadata同步给第二语言服务额度页，不冒充官方钱包余额；本次接入不触发本机任务末尾余额/归档脚本，也不改变原日课、休息和永久存储合同。离线验证：`node scripts/check-chapter-questions.mjs`、`node --test scripts/check-question-notifications.mjs scripts/check-cloud-questions.mjs scripts/check-series-usage.mjs`，仅内存SQLite和模拟HTTP，不领取真实任务、不调用收费API。
