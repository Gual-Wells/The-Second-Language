# 纪念币协同设计：临时约束协议

版本 1.1 · 2026-10-12 · 当前立即生效。

本协议替代 1.0。它不是制作教程，也不是逐节检查表，而是第二语言认证币在当前研究阶段的**防漂移护栏**：保护作品设计质量、完整资产谱系、二维—三维协同和人类审美权威，同时避免协议本身把创作重新锁成僵硬流水线。

配套关系：

- `protocol/COIN_CRAFT.md`：长期制作基线。
- `research/certification-coin-design-system-2026-10-12.md`：大型研究母本，解释设计、材质、碎裂、二维—三维协同、人类偏好等为什么。
- `research/certification-coin-temporary-protocol-redesign-2026-10-12.md`：本临时协议的重构与研究依据。
- `research/certification-coin-execution-state-2026-10-12.md`：当前作品事实、已采用/否决、未解决问题和工具实证。
- 本文件：当前阶段真正约束“怎样推进”。

大型研究报告不是执行清单；执行状态也不是永久协议。只有可复用的方法原则真的改变时才修订本文件。

## 1. 总目标：保护设计关系，不替代设计判断

认证币制作的目标是得到高质量完整作品，而不是完成规定动作。

本协议冻结以下最低原则：

1. **设计质量优先。** 不因工具方便、已有低质量模型、已投入时间或协议形式而牺牲作品。
2. **初始化非对称，迭代才双向。** 没有同谱系有效设计承载模型时，第一份具有审美权威的 3D 必须由完整视觉设计状态引导；有效模型建立后，AI视觉设计与真实三维才进入双向协同进化。
3. **不同表示只对自己擅长的事实拥有权威。** AI图不是隐藏面和厚度真理，3D也不是构图和审美真理。
4. **局部可以局部编辑，但不能脱离完整母体建立新的局部设计世界。**
5. **原件、父版本、来源和关键设计变化必须可追溯；高风险修改必须可回退。**
6. **技术成功不能冒充艺术成功。** watertight、高面数、导出成功、仿真成功、材质“看起来像”都不能代替作品质量。
7. **用户对主观审美和已认可设计拥有最终决定权。** Codex先处理明显客观缺陷，只把高价值设计不确定性交给用户。
8. **协议约束停止错误，不规定唯一算法。** 顺序、工具、候选数、桥接表示按问题选择，不为了“合规”制造无价值工作。

## 2. 工作对象：K / C / M / F / A

### 2.1 K / Design Kernel 必须最小化

K 只保存作品身份和真正需要跨迭代保护的设计事实，不是把当前版本的所有细节都冻结进去。

K 分两类：

- **K-fixed**：用户明确要求、已经采用的关键优点、系列级硬要求、不会因普通迭代而改变的作品身份。
- **K-open**：仍在探索的假设、比例、局部设计、材质倾向、候选关系。它们不能被伪装成硬约束。

若一个细节还存在真实设计分歧，就应留在候选/状态中，而不是写进 K-fixed。

这样既防漂移，也防止协议本身造成设计固着。

### 2.2 C / Concept State

当前完整视觉设计状态，可以是：

- AI完整设计稿；
- 在原完整图上的非破坏编辑；
- paintover；
- 组合草图；
- 其他能表达完整作品视觉意图的表示。

C 擅长：

- 构图；
- 气势；
- 视觉重心；
- 负空间；
- 形面语言；
- 碎片视觉节奏；
- 材质审美意图；
- 整体收藏品感。

### 2.3 M / Model State

M 分成两种，不能混淆。

#### M-tech / 技术脚手架

包括：

- 空白币坯；
- 标准圆片；
- 尺度/相机/坐标框；
- 材质球；
- boolean/碎裂/导出测试件；
- 与当前作品无关的校准模型；
- 只按文字由程序自由拼出的粗糙占位体。

M-tech 可以测试技术，但**没有作品审美权威**。

除非经过明确批准，M-tech 不得作为下一轮 AI 视觉设计的审美参考，避免把工具默认几何和低级 blockout 反向冻结成作品风格。

#### M-design / 设计承载模型

只有以下来源通常能获得 M-design 地位：

- 从当前或历史认可 C 转译/生成/建模得到，并经过完整作品验证；
- 当前作品上一版 Canonical M；
- 与当前作品同谱系、仍保留关键设计身份的旧模型；
- 真实扫描/已有实体模型等本身已经承载作品设计事实的来源。

M-design 擅长：

- 厚度；
- 隐藏面；
- 正侧背连续；
- 掌指接触；
- 空间遮挡；
- 真实断口；
- 碎片来源；
- 可绕看关系。

### 2.4 F / Finish State

负责：

- 基材；
- roughness；
- micro-normal；
- finish分区；
- 氧化；
- 抛光；
- 拉丝；
- 真实PBR表面。

### 2.5 A / Aura State

负责：

- emissive；
- bloom；
- 局部雾；
- 粒子；
- 数字动态。

A 永远是附加表达，不能承担主形、结构或收藏品质。

## 3. Bootstrap：新艺术对象必须 C-first

“C 与 M 可以轮流领先”只适用于**已经存在有效 M-design 的同一作品谱系**。

对于尚无有效三维母体的新艺术对象，推荐关系是：

**K₀ + 项目资源/参考 → C-anchor → M₀-design → C₁ ↔ M₁ ↔ …**

### 3.1 C-anchor 不是“最终效果图”

C-anchor 不需要把所有隐藏面、厚度、断裂物理和最终材质都解决。

它只需要成熟到足以给第一份 M-design 提供真正的视觉设计依据，例如：

- 完整作品上下文；
- 主体身份；
- 主构图；
- 主剪影；
- 视觉焦点；
- 关键动作；
- 大尺度比例；
- 主要形面语言；
- 重要跨币缘关系；
- 足够明确的审美方向。

如果这些仍然模糊，继续完善 C，而不是让 Codex 用低级几何替代设计。

### 3.2 高不确定新题材可先探索小型 Concept Set

第一张 AI 图不自动获得 C-anchor 地位。

当新题材设计空间很大、第一方案明显可能造成固着时，可以先探索少量**完整作品级**概念候选，再基于设计价值、项目身份和必要的人类偏好选择 C-anchor。

这是为了避免：

- 第一张生成图；
- 第一个 blockout；
- 第一个工具默认结果

因为“先出现”而获得不应有的设计权威。

不要求每次都多方案；只有真实设计不确定性值得时才使用。

### 3.3 第一份 M-design 必须受 C-anchor 条件化

可接受方式包括：

- image-to-3D；
- 多视图/参考图建模；
- 雕塑师式参考转译；
- 以 C-anchor 轮廓、形面和关键部件为约束的 blockout；
- 其他明确受 C-anchor 约束的实现。

禁止把“从文字规范自由手搓一个英雄模型”当作 M₀-design，再让后续 AI 稿去迁就它。

如果当前工具无法把 C-anchor 转成足够好的 M₀：

- 改进/重解释 C；
- 更换成熟工具或建模路线；
- 做参考引导的手工/程序协同建模；
- 必要时向用户确认关键形体；

而不是把无约束的低质量模型升级成设计源头。

### 3.4 Bootstrap 按设计对象判断，不按“文件里有没有mesh”判断

例如：

- 已有统一币背 M，不代表新的正面主题已有 M；
- 已有币坯，不代表龙头、爪和碎裂已有 M；
- 已有龙头，不代表新增加的独立角色/装饰自动继承 M 权威。

只有当前设计对象本身已有同谱系 M-design，才进入双向领先。

### 3.5 重大设计变化后允许 Re-bootstrap

如果 K-fixed 或 C 的核心身份发生重大变化，使旧 M-design 不再代表当前作品，则该 M 对受影响部分进入 **stale** 状态。

stale M 可以继续作为：

- 工程参考；
- 尺度参考；
- 对比对象；

但不能继续主导受影响部分的审美设计。

应从新的 C-anchor 或已确认设计重新建立/重构对应 M-design。

## 4. Co-Evolution：有效 M 建立后才进入真正双向协同

一旦 M-design 存在，C/M 可以轮流领先。

目标不是：

`Render(M)=C`

而是：

> **C 与 M 对 K-fixed 和当前被接受的设计意图逐步收敛，同时各自纠正对方不擅长的部分。**

典型关系：

- C 提出更好的构图、形面、负空间或碎片节奏；
- M 判断其空间、厚度、接触和来源是否成立，并做三维翻译；
- M 暴露隐藏面、侧背、真实受力和透视问题；
- C 根据这些真实结构继续优化完整视觉；
- 两边反复收敛。

### 4.1 权威按“事实”获得，不按“整个文件”获得

大致原则：

- 构图、气势、视觉重心：C 优先；
- 厚度、隐藏面、空间接触：M 优先；
- 主剪影、头向、眼神、关键比例：C/M 共同；
- 真正高光、环境反射：渲染器/材质系统；
- 碎片是否来自母体：M；
- 碎片节奏和整体负空间：C/M共同；
- 用户明确认可的视觉优点：高于任一自动表示。

当 C/M 冲突时，先判断冲突属于哪类事实，再决定谁纠正谁。

## 5. 局部编辑：局部是范围，不是新世界

允许：

- 原完整图上的 mask/inpaint/layer；
- 原完整模型上的 sculpt mask、modifier、boolean、局部remesh；
- 局部放大、crop、剖面；
- 内部计算时裁ROI；
- 在完整模型里只修改某个爪、眼、破口或碎片群。

禁止：

- 单独生成“新爪图”“新眼睛图”“新碎片图”并升级为设计权威；
- 单独建立一个脱离整币的漂亮局部模型，再硬粘回主模型；
- 用局部特写通过审美判断后跳过整币复核。

### 5.1 Collateral Drift Rule

局部修改的授权只覆盖目标变化。

若 AI 编辑或三维修改同时改变了：

- 未授权区域；
- 已认可主形；
- 构图重心；
- 其他部件比例；
- 材质身份；

这些变化默认视为**collateral drift**，不是“顺便优化”。

只有重新审查并主动接受后，才可保留。

局部编辑完成后必须回到完整作品检查全局影响。

### 5.2 Delta 记录设计意图，不要求逐像素/逐顶点复制

接受的增量应描述为：

- “破坏范围更小”；
- “主碎片形成更清晰斜向力量”；
- “保留A的完整币感，吸收B的撕裂方向”；

而不是：

- “把AI图第x像素位置的碎片逐点复制”。

这保留设计关联，又避免强映射。

## 6. 候选探索：Set-based，但不候选泛滥

存在真实设计分歧时，可以并行保留多个**完整作品状态**。

原则：

- 候选数量由问题决定，不固定；
- 候选要代表不同设计假设，不是机械改参数；
- 每个候选仍属于同一完整母体谱系；
- 有充分证据说明较差/不可行时就淘汰；
- 不因沉没成本继续修失去价值的路线；
- 不为了“多方案”制造无意义分支；
- 不过早把第一个看起来可用的方案冻结成唯一答案。

若问题客观上已有明显最佳解，就直接修，不需要强制A/B/C。

## 7. 用户介入：解释性与审美性分开

用户不是只在最后投票，也不是每一步都审批。

### 7.1 解释性介入

如果 Codex 无法可靠判断：

- 某个形体究竟是什么；
- 某处原设计是否有意；
- 某个用户已认可优点是否必须保护；
- 继续自动推断会造成高代价漂移；

应尽早询问。

这不是把基础 QA 外包给用户，而是避免错误前提扩散。

### 7.2 审美偏好介入

当多个完整候选：

- 客观结构都成立；
- 明显bug已内部消化；
- 剩余差异主要是力量感、收藏品感、华丽/克制、负空间、构图等主观取舍；

再向用户展示少量高质量完整候选。

优先问：

- 更倾向哪一个 / 都不行 / 难分；
- 最佳候选是否已经足以继续；
- 真正喜欢或不喜欢的属性；
- 是否希望 A 的某一点 + B 的某一点。

不把审美伪装成高精度绝对分数。

### 7.3 候选展示条件一致

为了避免把灯光当成设计：

- 完整作品；
- 相同相机/尺度/背景；
- 3D相同中性材质与照明；
- 同样的必要旋转/侧背；
- 局部特写只作为辅助。

## 8. 研究成熟方案：风险触发，不做形式化市场调查

以下情况应先查项目资源与行业成熟方案：

- 方法陌生且失败代价高；
- 需要新工具、模型、订阅或大规模算力；
- 连续失败，怀疑路线本身错误；
- 资产转换难回退；
- 已知有成熟专用解法；
- 当前技术瓶颈已经限制作品质量。

优先级：

1. 项目现有资产和已成功环境；
2. 官方原生功能/文档；
3. 维护中的开源项目/成熟插件；
4. 必要社区实战与论文。

目标是回答：

**复用、适配还是定制。**

普通可逆小编辑不重复做完整市场调研。

### 8.1 工具能力状态

只用简单四态：

- VERIFIED：当前环境、当前目标用途已实测；
- WORKING：有可靠证据，但尚未在目标资产完成；
- UNKNOWN：资料存在，实际能力未证实；
- REJECTED：已有证据说明本用途不适合。

宣传页、按钮或论文存在不等于 VERIFIED。

## 9. Bridge Evidence：只生成解决当前分歧所需的证据

C/M之间需要互相反馈，但不固定要求每轮输出全部通道。

按问题选：

- silhouette/clay：轮廓、构图；
- depth/侧视：空间前后、厚度；
- normal：表面方向；
- ID mask：对象归属；
- neutral beauty/finish：材质；
- 剖面/转台：接触、断裂、隐藏面。

Bridge 的目的只是减少信息损失。

如果一个通道不会改变当前判断，就不为了“协议完整”生成。

使用任何结构控制模型前，先确认它真正接受对应格式；不能把任意 world normal、Z-depth 或自制mask只改名字就假定兼容。

## 10. 上下游可以并行研究，但不能互相代替验收

研究可以异步：

- 几何尚未最终定稿时，可以用中性校准资产研究材质；
- 碎裂算子可以先在普通金属圆片上验证；
- viewer/导出/性能可以提前测试。

但验收依赖不可倒置：

- F 不能证明 C/M 已经成立；
- A 不能证明 F/M 已经成立；
- 烟、光、bloom 不能补救主形；
- 技术校准件不能升级成艺术候选。

**允许并行学习，不允许下游美化替上游过关。**

## 11. 当前领域质量底线

### 11.1 币章核心

认证币首先要在静态器物状态成立。

颜色、光、雾、粒子可以存在，但不能代替：

- 构图；
- 雕塑；
- 材质；
- 表面工艺。

### 11.2 金属 Finish

裸金属的磨砂/霜面主要通过：

- metallic保持真实金属属性；
- roughness；
- micro-normal；
- finish分区；
- 必要anisotropy；

形成。

不能靠降低 metallic 得到灰塑料，也不能用全图随机noise代替工艺因果。

### 11.3 损伤与碎片

普通延性金属优先遵守：

**受力/塑变 → 撕裂 → 分离。**

重要碎片应来自同一受损母体，有：

- 来源；
- 厚度；
- 旧币面；
- 侧缘；
- 新断面。

微屑可以用粒子，主碎片不能。

若作品明确设定为脆性/超自然材料，可偏离，但必须是主动设计。

### 11.4 Digital Aura

emissive、bloom、局部雾和粒子属于附加表达。

关闭它们后，作品身份仍应成立。

### 11.5 统一币背

统一币背是系列级要求。

具体纹样尚未冻结。

`web/icon.svg` 等现有项目身份资源必须被实际查看，并作为设计输入之一，但不预设“开卷、40微刻、某套铭文”已经成为不可修改答案。

统一币背应：

- 长期可识别；
- 克制；
- 可扩展；
- 不抢正面；
- 能与真实跨币缘结构共存；
- 不退化成第二幅主题画；
- 不退化成UI模板。

## 12. 谱系、Canonical 与 Authority Freshness

### 12.1 重要修改必须可追溯

改变拓扑、主形、构图或已认可特征时，要能回答：

- 从哪个完整版本来；
- 改了什么；
- 保护了什么；
- 失败怎样回去。

普通小型可逆编辑不要求行政式日志。

### 12.2 Canonical 周期性 Rebase

若干接受的 delta 累积后，应生成新的 Canonical C / M，避免在同一文件上无限堆修导致隐性漂移。

晋升前检查：

- K-fixed 是否仍满足；
- 已认可优点是否保留；
- 完整剪影/重心是否改善；
- 局部修复是否造成全局副作用；
- C/M重要分歧是否有解释；
- 需要用户决定的审美分歧是否已经处理；
- 当前 M 是否仍然“fresh”，还是已因重大C/K变化变成 stale。

旧 Canonical 保留。

### 12.3 Authority Freshness

模型、概念或候选的权威不是永久的。

如果其依赖的 K-fixed、核心构图或主体身份已经改变，则相应权威失效或降级，必须重新验证。

这样避免“因为这个模型以前是Canonical，所以现在仍然天然正确”。

## 15. 反模式

出现以下情况应停止该分支并回到最近可靠母体：

- 新艺术对象在没有完整视觉设计依据时，被低质量程序 blockout 抢先获得审美权威；
- 把 M-tech 当 M-design；
- 第一张AI图/第一个模型只因为先出现就被冻结；
- 为修局部生成脱离整币的局部成品；
- AI编辑无意改变大量非目标区域却被当作“顺便优化”；
- 因AI图漂亮而复制明显不可能结构；
- 因模型技术正确而继续明显缺乏设计的方案；
- 用材质、烟光、bloom、面数或高分辨率遮掩主形失败；
- 同一失败路线只靠增加算力/分辨率/迭代次数继续堆；
- 因当前工具不方便而跳过明显成熟的专用方案；
- 为满足协议而生产无价值日志、候选或测试；
- 把一次作品反馈误写成永久规则；
- 重大设计已经改变，却继续让旧 M 反向约束新 C。

## 16. 什么时候可以认为一个问题已经收敛

不要求 C/M 像素/顶点一致，也不要求“所有细节再也不能改”。

一个局部或阶段可以暂时收敛，当：

- K-fixed 无冲突；
- 主要设计意图在完整作品中稳定；
- C/M在各自权威事实上没有高价值未解矛盾；
- 继续修改的预期收益已经明显下降；
- 没有靠下游效果遮掩上游问题；
- 如存在关键主观分歧，用户已经给出足够偏好或明确允许继续；
- 资产仍保持可回退和可追溯。

“达到最低技术指标”本身不是收敛。
