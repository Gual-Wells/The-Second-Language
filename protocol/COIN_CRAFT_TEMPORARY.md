# 纪念币协同设计：临时约束协议

版本 1.0 · 2026-10-12 · 当前立即生效。

本协议替代旧版“纪念币设计与制造：临时动态约束协议”0.3。它的目的不是把研究报告改写成更长的检查表，而是给仇视之龙、统一币背及后续认证币建立少量、明确、可执行的防漂移约束，同时保留设计与建模自由。

配套关系：

- protocol/COIN_CRAFT.md：长期制作基线。
- research/certification-coin-design-system-2026-10-12.md：大型研究母本，解释为什么。
- research/certification-coin-execution-state-2026-10-12.md：当前作品事实、已采用/否决、未解决问题和工具实证。
- 本文件：当前阶段真正约束“怎么推进”的临时规则。

大型报告不是逐节执行清单，当前状态也不是永久协议。用户新反馈若只改变某一枚币、某一部件或某一候选，只更新当前状态；只有可复用规则真的改变时才修订本协议。

## 1. 目标：约束漂移，不规定唯一流程

认证币制作的目标是得到高质量完整作品，而不是完成规定动作。

本协议只冻结以下最低原则：

1. 保持用户已经明确的设计意图与已采用优点，不用工具便利性重写作品。
2. AI视觉设计与真实三维共同进化；二者互相提供证据，但谁都不是另一方的逐像素/逐顶点真理。
3. 局部问题可以局部编辑，局部候选不能脱离完整作品成为新的权威资产。
4. 原件、父版本和来源关系必须可追溯；高风险改动先保留可回退状态。
5. 只把真实验证过的能力、结果和采用状态写成事实；技术成功不能冒充艺术采用。
6. 用户对主观审美有最终决定权；Codex负责先消化明显客观缺陷，不把基础质检外包给用户。

除此之外，允许根据问题自由改变顺序、工具、表示和研究方法。不存在“读完某几节才能进入下一关”的形式门槛。

## 2. 当前工作模型：K / C / M / F / A

为了维持连续性，只保留五个简单概念：

- K / Design Kernel：作品身份和必须保护的设计事实，例如主题、动作、视觉焦点、已采用优点、系列身份。
- C / Concept State：当前完整视觉设计状态。可以是AI设计稿、编辑后的完整图、paintover或其他能表达视觉意图的完整表示。
- M / Model State：当前完整三维状态，负责厚度、空间连续、隐藏面、接触、真实结构和可绕看关系。
- F / Finish State：材质与表面工艺状态。
- A / Aura State：施彩之外的发光、雾、粒子、数字动态等附加状态。

它们是职责，不是强制线性阶段。

### 2.1 C 与 M 可以轮流领先

禁止把流程固化成“必须先有最终AI稿，再建模”。

允许：

- C先提出完整构图，M去解释空间；
- M先用可逆blockout或结构修改发现问题，再把真实渲染反馈给C；
- C根据M的真实结构继续改整体视觉；
- M再吸收被接受的设计增量。

对涉及强审美的新造型，不应在完全没有视觉/作品上下文时由程序随手造最终形；但探索性blockout、结构验证和真实模型反馈本身可以参与设计，不需要等一张所谓“最终设计稿”批准后才开始。

目标不是 Render(M)=C，而是 C 与 M 对K中真正重要的事实逐步收敛。

### 2.2 不同表示对不同事实拥有不同权威

大致原则：

- C更擅长：构图、气势、视觉重心、形面语言、负空间、碎片节奏、材质审美意图。
- M更擅长：厚度、隐藏面、掌指接触、正侧背连续、真实断口、碎片来源、空间遮挡。
- C/M共同保护：主剪影、头向、眼神、关键比例、动作和已采用优点。
- 渲染器负责：真实高光、环境反射和固定视角下的光照结果。AI图中的白边、AO和阴影不自动成为几何事实。

当两边冲突时，先判断冲突属于哪一种事实，不默认“照图”或“以模型为准”。

## 3. 每次迭代的真实单位：完整母体上的可逆增量

典型循环可以是：

发现问题 → 选择最适合解决它的表示 → 在当前完整母体上建立可逆修改 → 输出必要的桥接视图 → 回到完整作品比较 → 保留、继续、分支、询问用户或丢弃。

这只是工作模型，不要求机械走完每一步。

### 3.1 局部是编辑范围，不是新的设计世界

允许：

- 原图上的mask/inpaint/layer；
- 原模型上的sculpt mask、modifier、boolean、局部remesh；
- 局部放大、crop、剖面；
- 为计算效率临时裁出ROI；
- 在完整模型中只修改一个爪、一处破口或一组碎片。

禁止：

- 单独生成一张“新爪图”“新眼睛图”“新碎片图”并把它升级成设计权威；
- 单独做一个与整币脱离的新局部模型，做漂亮后再硬粘回；
- 因局部视图看似合理就跳过完整币、侧背和视觉重心复核。

局部视图是检查窗口，不是新母稿。

### 3.2 保留谱系

重要修改使用父版本/分支/delta思路，避免覆盖唯一母版。

改变拓扑时可以建立新的完整模型版本；不改变拓扑时优先使用非破坏方式。无论工具为何，必须能回答：

- 它从哪个完整版本来；
- 改了什么；
- 哪些保护内容没有动；
- 如果失败怎样回去。

不要求为每一个微小操作写表格；版本和关键变化可追溯即可。

## 4. 候选探索采用“集合收敛”，不是单一路线死磕

当问题存在真实设计分歧时，可以同时保留多个完整候选，而不是过早锁死一个方案。

原则：

- 候选数量按问题决定，不固定为2个、3个或某个数字；
- 候选必须解决真实差异，不能只是机械改参数；
- 弱方案一旦有充分证据说明不成立就淘汰；
- 不因为已经投入很多时间就继续修一个失去设计价值的分支；
- 也不为了显示“多方案”而制造无意义分支。

对局部问题，A/B/C仍然必须是完整作品状态中的不同delta，例如 M6+ΔBRK-A、M6+ΔBRK-B，而不是三个孤立碎片。

## 5. 用户何时进入工作流

用户不是只在最后投票，也不是每一步都要审批。

优先在以下高价值时刻插入问答：

1. 多个客观上都成立的完整方案之间主要剩审美取舍；
2. Codex无法可靠判断某个形体究竟是什么、用户原意如何，继续猜会放大漂移；
3. 修改可能牺牲已经被用户认可的优点；
4. 某个主观方向一旦选定会显著影响后续大量工作。

明显断指、穿模、错误来源、材质通道错误等客观问题应先内部处理，不需要让用户替系统筛垃圾。

### 5.1 问答方式

展示候选时尽量统一：

- 完整作品；
- 相同相机/尺度/背景；
- 3D用相同中性材质、照明和转台；
- 局部特写只能作为补充说明。

问题优先询问：

- 更倾向哪一个或都不行；
- 最佳候选是否已足以继续推进；
- 真正喜欢/不喜欢的属性是什么。

允许：

- 难分；
- 无偏好；
- A的某一点+B的某一点；
- 对某一候选有低置信偏好。

不要把审美伪装成8.7分一类高精度测量。

用户反馈先更新当前设计状态和下一轮delta；除非反馈明确形成可复用规则，否则不修改协议。

## 6. 成熟方案研究：按风险触发、按问题适量

保留“陌生高难度操作不要先手搓造轮子”的原则，但不把它变成每次编辑前的审批流程。

以下情况应先做行业/项目方案核查：

- 方法陌生且失败代价高；
- 需要新工具、模型、订阅或大规模算力；
- 已连续失败，怀疑路线本身不对；
- 涉及难以回退的资产转换；
- 已知行业可能有成熟专用解法；
- 某个技术瓶颈正在限制艺术质量。

核查优先级：

1. 项目现有资产和已经成功的环境；
2. 官方原生功能/文档；
3. 维护中的开源项目或成熟插件；
4. 必要的社区实战和论文。

目标是回答“复用、适配还是定制”，不是为了形式列出所有工具。

日常小型、可逆、低风险编辑不必重复做完整市场调研。纯技术算子可以在与作品无关的校准资产上快速验证；只要不把它冒充艺术成果，就不受“必须先有作品设计稿”的限制。

工具能力只用四种简单状态：

- VERIFIED：当前环境和目标用途已实测；
- WORKING：已有可靠证据可用，但尚未在目标资产完成；
- UNKNOWN：资料存在，实际能力未证实；
- REJECTED：本用途已有证据说明不适合。

论文、宣传页、按钮存在都不能直接升级为VERIFIED。

## 7. 设计与技术不得互相冒充

以下几条始终有效：

- AI设计稿是视觉证据，不是隐藏面、厚度、接触和断裂来源的真值。
- watertight、高面数、导出成功、模拟成功不是艺术质量。
- 真实三维结构正确，也不能证明构图、气势和收藏品感已经成立。
- 材质截图不能证明PBR数据正确；最终要看真实参数、实际渲染和必要的真机表现。
- 任何“看起来像”的效果如果主要来自固定高光、烟、bloom或背景，都不能掩盖主形失败。

## 8. 领域质量底线

这些是当前研究得到的通用质量原则，不是固定工具配方。

### 8.1 币章核心

最终认证币首先要在静态器物状态成立。颜色、发光、雾和粒子可以存在，但不能代替构图、雕塑和表面工艺。

### 8.2 材质

对裸金属，磨砂/霜面主要通过金属反射的roughness、微表面和finish分区实现，不应简单降低metallic得到灰塑料。

roughness首先服从工艺因果：底场、主浮雕、高点、凹处、侧缘、新断面可以不同；全图随机noise不能替代设计。

### 8.3 损伤与碎片

当基材按普通延性金属表现时，优先遵守“先受力与塑变，再撕裂与分离”。

重要碎片应来自同一受损母体，并有真实厚度和来源关系。微屑可以用粒子，主碎片不能。

如果某枚币明确采用脆性、超自然或其他材料行为，可以偏离这一规则，但应是有意识的设计，不是随机石块式破碎。

### 8.4 数字Aura

emissive、bloom、局部雾和粒子属于附加表达。关闭这些效果后，作品身份仍应成立。

### 8.5 统一币背

第二语言认证币需要统一的系列币背，这是当前系列级要求。

具体纹样仍未冻结。web/icon.svg 等项目身份资源必须被实际查看并作为候选设计输入之一，但不强制最终币背逐字复制某个图标，也不预先把“开卷、40微刻、某套铭文排版”写成不可修改答案。

统一币背应长期可识别、克制、可扩展，并给真实跨缘结构留空间；不能退回“第二幅主题画”，也不能退回纯UI模板。

## 9. Bridge Render 只在有信息价值时生成

C/M之间需要互相反馈，但不要求每轮固定生成全部clay/depth/normal/Object-ID/Material-ID。

按问题选最有信息价值的表示：

- 轮廓问题：silhouette/clay；
- 空间前后：depth/侧视；
- 表面方向：normal；
- 对象归属：ID mask；
- 材质审查：neutral beauty/finish render；
- 复杂接触：剖面/真实旋转。

使用结构控制模型前，要确认它真正接受对应格式；不能把任意world normal或Z-depth名字一改就宣称兼容ControlNet。

桥接包的目的，是减少C/M之间的信息损失，而不是完成一套固定文件清单。

## 10. 当前状态与协议分离

下面这些内容不写死在本协议：

- 当前哪张B图被采用；
- 原眼是否保持；
- 哪个GLB是当前基线；
- 哪个AI三视图被叫停；
- 哪个coupon被隔离；
- 当前工具余额、机器、运行状态；
- 当前具体问题排序。

它们全部记录在 research/certification-coin-execution-state-2026-10-12.md。

这样用户改变某一枚币的决定时，只更新状态，不需要重写整个方法协议，也避免旧资产状态被错误升级成永久规则。

## 11. 记录最小化

取消旧版“任何动作前必须写六项记录”和“每次反馈先改协议再行动”。

只在以下情况下更新执行状态：

- 用户采用/否决改变了当前设计；
- K中的保护事实发生变化；
- 新工具能力被真正验证或证伪；
- canonical版本晋升；
- 出现足以改变下一步策略的新失败；
- 需要跨会话交接的重要开放问题。

普通可逆编辑、同一路线的小测试不需要额外文书。

如果一次改动高风险或难回退，只需留下足够的父版本、改动目的、结果和回退路径；文档服务于继续工作，不反过来支配工作。

## 12. Canonical晋升与全局复核

若干接受的delta累积后，应周期性形成新的Canonical C / M，而不是在一个文件上无限叠修。

晋升前检查：

- 是否仍符合K；
- 已采用优点是否保留；
- 完整剪影和视觉重心是否改善；
- 局部修正是否造成新的全局问题；
- C/M之间的重要分歧是否已经解释；
- 需要用户审美决定的地方是否已经得到反馈。

旧Canonical保留。

不同层可以异步探索：例如几何未最终定稿时可以用中性校准件研究材质；但技术试验不能反向声称上游艺术已通过。

不存在全局“全部暂停/全部解锁”。只对具体缺失依赖的动作暂停；其他有价值、可逆、不会伪造结论的工作可以继续。

## 13. 反模式

出现以下情况应立即停止该分支并回到最近的完整母体：

- 为修一个局部重新生成脱离整币的局部成品；
- 因AI图漂亮而复制明显不可能结构；
- 因模型技术正确而继续一个明显缺乏设计的方案；
- 为满足协议而生产文档、候选或测试，而没有改善作品；
- 同一失败路线只靠提分辨率、面数、迭代次数继续堆；
- 用烟光、材质或后期遮掩主形；
- 因当前工具不方便就跳过明显成熟的专用方案；
- 把一次作品反馈误写成永久通用规则。

## 14. 当前临时协议何时结束

本协议是当前认证币研究和样币制作阶段的防漂移层。

当正式协议拆分并稳定承接以下内容后，可删除本文件：

- 系列设计/统一币背；
- 雕塑与C/M协同；
- Surface Finish；
- 损伤与Fragment Provenance；
- Digital Aura；
- Human Preference / Canonical晋升。

在此之前，本协议优先解决“怎样不把研究误读成形式流程”，而不试图成为所有纪念币知识的重复副本。
