# 语音扩展预留协议

状态：**每日预生成音频保留扩展；设备原生朗读已启用**。设备点词/点句用 Web Speech，不进入服务器、每日生成或本清单；声音和语速本机保存，高容错发音不宣称音标强制一致。以下规定针对将来的持久日课音频。每日课程仍以完整的三部分文字正文为必交付内容；本文件不要求定时任务调用 TTS、不指定供应商、不改变现行章节格式或发布命令。启用语音前，须先用同一份教材样本确认实际音色、发音、长文忠实度、句子定位和账户支付均可用。供应商由届时的实测质量、支付与成本决定。

## 内容与身份

- 第一部分的 `WORD` 和 `USE`，第三部分的 `SENTENCE` 是语音与正文关联的现有锚点。一个词形可能有多种读音；朗读单元按**实际词形、具体用法和上下文**确定，不对全章相同拼写一律套用同一音标。派生词、短语和细用法可各有朗读单元。标题中核实过的美式音标是发音校正依据，不作为要念出的文字。
- 第二部分现行 `<!-- EXAMPLE:U001 -->` 可在同一用法下重复，只表达所属用法，**不具有单条例句身份**。在实施例句音频前，先协调升级校验器、阅读器、复习页提取和章节打包，使新正文可使用 `<!-- EXAMPLE:E001 USE:U001 -->`；旧格式继续可读。`E` 在章节内唯一，新增例句领取新编号。不得仅用“该用法下第几句”作为持久音频键，也不得先让定时任务输出新语法而让现行校验器拒收。
- 正文的 `USE`、`E`、`SENTENCE` 编码只表达内容身份。供应商、音色、文件位置、播放时间和合成状态属于正文外的语音清单，不写入释义、例句或文章，不产生第四部分。旧章节无需为预留协议重新生成。

## 未来的语音清单

音频作为章节的**可选附属版本**独立发布，例如 `chapter.audio.json`。清单至少关联当前 `chapter.json.digest`、清单版本、语言和音色版本，并分别映射 `USE` 朗读单元、`E` 例句和第三部分 `SENTENCE` 到音频资产及时间区间。每个映射保留实际送入 TTS 的英文文本摘要；发音覆盖、语速等影响输出的参数也参与资产身份。正文摘要改变后，旧清单不得冒充新章语音；内容和参数均未改变的资产可以按摘要复用。

同一接口允许不同供应商、模型和音色完成不同章节或不同内容层；不假设所有提供商都支持 IPA、SSML、词级时间戳或同一长文长度。接入层需把“指定发音、取得句子位置、合成英文语音”转为该提供商真实支持的请求和结果；缺少必需能力时不能默默忽略发音覆盖或伪造时间点。美式 IPA 若需转为 CMU 等格式，应逐条核实转换结果。文章优先保持自然段连续朗读，用书签或可靠对齐数据定位句子；逐句独立合成可以作为跳播补充，不能未经听审就充当连续文章。

## 生产与发布边界

1. 先按现行协议完成教材保真、文章、逐句译文和语义审阅，照常发布文字章节。语音失败、超出预算或账户不可用时，文字课程照常可读，日课运行与 VIX 标注不回滚也不重做。
2. 未来启用语音的运行读取**已定稿的当前章节版本**，从编码单元提取纯英文朗读文本；排除 Markdown、中文释义与译文、编码注释。记录特殊读音和上下文判断，按单元或自然段合成。例句身份升级之前，不宣称已有稳定的逐条例句音频映射。
3. 音频文件先以内容摘要形成不可变资产，完成听审及时间点核对，确认文件可取回，再发布指向它们的清单。正文更新使清单摘要不匹配时，阅读器不显示旧播放入口；语音可稍后补发，不能覆盖已发布文字。具体对象存储服务和后端路由待实施时选择；正文与音频分离，音频不内嵌 Markdown 或章节 JSON。
4. 合成前按预计字符、音频时长、重复尝试和已缓存资产计算本次及当月支出；设置可停止的预算边界，超限保留文字课程并等待处理。价格、免费额、地区和支付在启用时重新核实。不要为了节省费用取消必要的发音校正或成稿听审。

## 阅读器与临时页的后续接口

阅读器只在清单与当前正文匹配且资产可用时显示播放控件；点按后按需取音频，iPhone 不因打开章节或收到通知而自动播放。第一部分的播放入口属于具体 `USE` 及其实际词形，第二部分属于唯一 `E`，第三部分的全文朗读与 `SENTENCE` 句子跳播共用可定位的文章资产。播放状态不得占用现有用法高光、译文吸顶按钮或点句跳用法手势。

临时测试页与复习页继续只发布文字，直至独立语音通路完成。以后可复用**相同正文版本、相同朗读文本与相同音色参数**的正式章节资产；重新排版和重编号不得把旧清单的章节内编码直接套到临时页。临时页独有语音跟随 48 小时生命周期失效并清理，不写正式日课或 VIX。语音缓存、退出登录清理和范围请求在实施阅读器与存储接口时一并完成。
