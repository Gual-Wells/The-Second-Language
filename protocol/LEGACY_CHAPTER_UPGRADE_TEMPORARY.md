## 3. 内容改造顺序

1. **读教材和原章。** 先获取相关完整条目、重复/编号标题、嵌套派生和必要交叉引用，结合原章检查各项去向。旧质检报告是定位线索，不能将其全部发现当作已成立事实；同根因多处定位不算多个独立错误。不要求先对每个旧章额外跑一遍完整自动质检再开始修订。
2. **统一讲解并纠错。** 同一用法融合重复定义，保留互补语法、搭配、对象、标签和区别。生僻、古义、历史、口语、书面等按实际教材及作用范围说明。真正不同的义项不硬并；不因想少改文章而删难义。
3. **添加一级词源。** 每个主词一个简洁区块，复杂关系同块分点；不要求逐 USE、逐现代义项对齐，不扩展为古词形记忆考试。保留基本史实可靠性，清楚区分助记联想和历史来源。
4. **补齐第二部分。** 核对全部相关原例句及片段，真正重复可以合并；不能仅保留搭配而丢掉原例语境。片段不能冒称原书完整句子，必要的补全在工作材料中区分。已有准确例句和译文保留；确实缺例的用法再补写。
5. **修补第三部分。** 先检查原文实际覆盖，再对缺项、错用、错译及连续性做必要修改。只改中文译文时不改正确英文；新增必要用法可以局部增补或调整，局部无法形成合格作品时允许重构受影响段落，需说明原因，不为风格整齐整篇重写。
6. **独立审阅新版。** 按第 6 节完成语义与工程验收，未闭合章不替换线上旧版。

## 4. 编码与历史记录

- WORD 保留；语义身份未变的 USE 保留；只是中文讲解融合不需要重新分配 USE。
- 确需合并两个重复 USE 时选一个旧 ID 为主 ID，修改新版例句与范文引用，简记被合并关系；旧 ID 不再分配给别的意义。新增、拆分或实质替换的用法使用未用过的新 ID，不全章重编号。
- 未变的 SENTENCE 保留；新增句使用新 ID，不为了连续数字重排后面各句。原句的一般修正可保留句子身份，但要记录实际文本变动；不可用旧 ID 冒充完全不同的新内容。
- EXAMPLE 的同一 USE 可有多条例句，不以出现序号作为跨版本永久身份。定位始终带章节 digest。
- 旧答疑、试卷、参考答案、答卷、成绩、原声、质检报告、雅思来源快照继续指向旧摘要，原样可读；不重判旧成绩、不把旧通过记录等同于新版掌握或认证。
- 阅读难度、笔记及完成标记目前按 chapterId 保存，保留这些学习者记录，不静默清空，也不将其包装成新版认证。阅读像素位置按 digest 保存，不把旧 scrollTop 百分比硬迁到新增内容；保留现有阅读器恢复规则。
- 用户已经打开的旧页可读完，不强制刷新或抢滚动。下次联网打开默认取得新版，旧记录的版本链接仍打开原版；离线旧缓存不冒称新版，不清空用户全部下载。

## 5. 句音：先复用，再补差额

继续仅允许第二部分例句和第三部分英文整句点读，固定原 Kokoro Bella 路线；第一部分、词源、杂文、译文及词汇标题不产生音频。

当前生成身份由模型、音色、规范化英文输入、格式及声音策略构成，不含章节 digest。因此只增加词源、融合中文讲解、修正译文、调整编码，通常不会产生新的声音身份。7 章内存结构探针已验证：只在一级标题下加入词源区块，第二/三部分字节及全部音频 descriptor 均不变；这不证明实际内容升级一定零新增音频。

**同一声音身份可复用，不等于新版已经有音频关联。** 对新版逐句生成清单，核对 `pronunciation_results`、兼容旧索引与实际原件；为新 digest 增加合法的 scope/clip 关联及新的预下载清单/包，复用原内容摘要，不改旧关联和付费原件。

- 不变的英文句子复用；仅译文改动也复用。相同拼写在本批不另启词汇/音标合成。
- 规范化后的英文确实变化、新增例句或新增范文句，才进入缺额；不为了缓存命中保留错误英文，也不为了整齐改变模型、音色或策略版本。
- 对 ready 原件不可读、上传失败或未知计费状态，先恢复/核实，不当作“未生成”再次收费。原请求不改绑为新版，不删除旧请求；新版任务引用自己的摘要和清单。
- 入队、ready 索引存在与实际可播放分别验证。文字升级和新音频完成分别报告；不以等待音频为由覆盖保护，不因音频未齐把旧原件删除。

**建议批准范围包含本批新增 TTS 最高人民币 5 元的规划预算**，与 Codex 既有额度区分；这是待批准提案，并非已经授权。执行时按原 AUDIO_CONFIGURATION 报价、确认和永久复用通路办理；用户对本协议及该上限的明确批准可以作为批次确认依据，不逐章重复询问。开始收费前汇总已复用/待核实/新增字符和实际路线报价；报价超出上限、路线变化或未知计费需重试时再提出具体事项。按当前仓库规划费率，198,143 字符全部重合成也仅约 ¥0.86–¥1.37，但它既不是必要支出也不是新增量上限；补足教学内容可能增加字符，最终以差额清单为准。达上限只暂停新增收费，保留成果及可复用声音，不安装自动跨日充值轮询。

## 6. 完成标准

每章至少满足：

1. 40 个原主词、字典序和一二部分对应不变；每个主词有合格词源区块；原教材的内容及相关例句去向明确，正确处理标签和融合。
2. 全部新 USE 都有相应例句和真实范文运用；范文整篇与译文通读正确。结构校验通过不能替代这个判断。
3. 对候选新摘要执行 CHAPTER_QUALITY 的完整来源、用法、例句、译文、全文及必要反证检查。只复用章节/资料/提示/策略相同且仍有效的结果，不把旧摘要报告改名为新版报告。新版来源和词源资料必须实际进入证据包。
4. 新版完整质检完成，当前固定策略下没有未解决的阻断或必检证据疑义；仍未解决则保留旧版，该章标为待处理，不以其他章通过或人工口头保证冒充闭合。一般问题亦需逐项判断，能纠正的实质缺陷应修正；学术完备和已接受文风取舍不升级成阻断。
5. 新旧版本分别可回读，历史记录无漂移；音频清单准确，新关联不重复收费；iPhone 原版排版、跳转、点句、纯净阅读及答疑/测试入口不因新内容退化。

不重复堆多个相同模型来投票；不设固定每批词数、稿长、缺陷数量或“必须有提升”的形式指标。一次质量失败先看具体证据和阶段，复用未受影响的工作，不把整章从头生成。

## 7. 批准后才建设的最小工程

下列能力是研究结论，**当前还未实现，不能直接运行旧 publish 脚本冒充支持**：

- 继续使用 `chapter_revisions`、OneDrive 内容存储、现有正文读取、检索、质检及音频服务；仅增加小型旧章升级状态/清单引用与发布控制，不建通用迁移平台或额外模型监测器。
- 增加明确的发布者修订通路：绑定 upgradeId、chapterId、baseDigest、targetDigest、来源/批准范围及验证清单；候选暂存校验内容后写不可变版本。独立 upgrade runId 不伪造 `run_claims`，不借日课领取越过休息机制。
- 候选尚未成为当前版本时，必须能按 digest 回读并完成真实质检；现有同章版本读取及质检查找可复用，候选身份另由升级状态明确区分，不能声称已发布。
- 发布前将正文/资料清单存入永久基座并回读；切换用 **baseDigest 的条件更新**，确认当前仍是制作候选所依据的版本。并发更新、过期批准或不匹配报告应拒绝，不能自动强覆盖。相同 upgradeId/targetDigest 重试幂等。
- 升级不更新原 `daily_runs`、原选词、休息/下一章音频设置、原标题日期和已记录的原发布时间；升级时间单记。不新增一个日历章节，不默认逐章发送“今日日课”推送。
- 普通 `/api/publish/commit` 对已进入升级管理的章也必须遵守修订控制，拒绝改变当前摘要的旧日课重发，不能只保护新接口而留下旁路。原样重发可幂等返回；不得重复入音频队列或推送。
- 回退是显式的、留记录的条件切换：核实目标旧版本存在、当前摘要与预期一致，再通过同一修订控制恢复。不能依赖现有按暂存 rowid 排序的日课提交强行回退；回退后仍须阻止旧日课或旧升级请求重新覆盖。

需做的针对性验证：两次并发修订只允许一份生效；旧日课重发及回退后旧请求均不能覆盖；同次重试不改发布时间/不重复推送或收费；候选质检/历史记录和音频复用正确；分步上传中断不切换半成品。沿用现有发布、质检、音频和 iPhone 检查，按实际风险补夹具，不作大型重构。

## 8. 批次执行、交付与退出

批准后先补齐上述最小工程并用隔离数据验证，再以 2026-10-02 为首章贯通内容修订、候选质检、发布、复用音频和回读。首章成功后按旧日期依次推进其余 6 章；不一次替换全部章节再检查。10-14 原有 473 USE，按实际材料拆工作块，不能为追求速度缩成和首章同样大小。

只在获批批次范围内执行；某章当前版本已被其他任务改变或资料前提失效时，停该章并报告，其他已核实章节可以继续。正常日课、答疑和测试不被本批全局冻结；长分析分块并为既有短任务让出，不另装常驻模型调用或自动重试。

本机资料留 D 盘、按现有 STORAGE 归档；大清单、工作文档及报告留永久文件基座，D1 只放关系/摘要/状态。每章交付明确原/新摘要、内容变化、尚未闭合项、音频复用与新增情况、质检记录、发布状态及实际支出。按 BALANCES 在实际升级任务末尾查询各方额度和存储，更新产品记录；协议研究轮不为形式化收尾启动模型或收费任务。

批次完成后报告并归档清单，本临时协议停止自动扩用；后来的旧章修订仍须明确指定范围，不把本协议变成永久的“全部历史章随时重写”授权。
