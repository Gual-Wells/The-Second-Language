# 临时页运行协议

临时页与每日 40 主词课程是独立发布流。Codex 可在定时运行中响应阅读器的一次性需求，也可被单独唤醒，直接推送已有测试文档或制作复习页。**测试临时页不得修改生产数据：不占日历日期、不写正式章节或 `daily_runs`、不领取日课运行、不改变 VIX 辅助索引及 YY-MM-DD 真实日期标签、不重新查询教材或创作正式课程。** 只在临时页存储和临时通知队列内增删，并在发布前后回读核对正式章节数量与 VIX 仓库状态。每页从服务端发布时刻起存活 48 小时；过期即时拒绝读取，后台清理正文、索引与待发通知。阅读器不离线缓存临时正文。

## 领取需求

定时任务先按 `DAILY_RUN.md` 领取当天控制状态。若 `rest=true`，此次不执行任何推送，临时需求继续保留。否则读取 `temporaryRequest.id/text`，结合学习目标和已发布章节判断应走测试还是复习路径。把理解与选择写到 `work/runs/<date>/temporary/` 或独立的 `work/temporary/<id>/`；已有同 ID 产物则续作。发布时传原需求 `requestId`，后端仅在 ID 仍匹配时将需求开关与文本清空；若读者后来改写了需求，新需求不会被误清除。无需需求也可由 Codex 独立发布测试页。

## 路径 A：直接推送已有测试文档

确认要推送的文档确为现有完整正文，符合 `protocol/ANNOTATIONS.md` 的章节内编码、例句对齐和文章逐句译文要求；旧文档若底层没有配对数据，应另写独立测试稿，不修改正式章节或 VIX。用 `node scripts/publish-temporary.mjs --file=<已有文档.md> --kind=test --id=<唯一编号> --title=<标题>` 发布；如响应阅读器需求，再加 `--request-id=<领取时的ID>`。已有测试文档的词量可沿用原文件，且只进入临时页；新正式日课始终恰有 40 个主词。

## 路径 B：从已发布章节制作复习页

根据需求和学习反馈选择 **1–40 个**要复习的词，按词汇顺序排列。来源只取已发布的正式章节。对每个词，从其来源章节原样取出第一部分该词下全部内容、第二部分该词下全部内容，并在第三部分中找出直接对应、带该词 `USE` 编码的原有语句及其逐句译文。只有 `SENTENCE` 而无 `USE` 的承接句不作为该词的复习摘句。保留来源句与译文的原词、标点和语义；同一词有多句可全部列出。第三部分按词汇顺序把各词独立成段，摘句各自占行。不新写第三部分，不改写来源，不用另一个词的句子充数。不同来源章节的编码可能相同，排版脚本会在临时页内重新分配唯一编码，同时保持第一、二、三部分的对应关系。

在 `work/temporary/<id>/plan.json` 写下 `id`、`title`、`subtitle`、可选 `requestId`、`entries`。每个 entry 写 `word`、`chapterId` 和从该章第三部分原样复制的 `thirdSentences` 原句数组。Codex 负责语义判断和摘句，并确保所选句覆盖该词第一部分的全部编码用法；`node scripts/build-review.mjs work/temporary/<id>/plan.json` 再从线上已发布章节抓取原文、完整截取第一和第二部分词条、校对摘句及其原有译文，生成 `page.md` 与 `page.json`。检查排版后运行 `node scripts/publish-temporary.mjs --page=work/temporary/<id>/page.json`。

## 发布确认

用发布命令输出的临时页 ID 在 PWA 临时页书架回读第一、二、三部分，确认文字、排列、48 小时到期时间与通知入口。临时页发布同样等待正文 KV 传播后再发系统通知。复习原章可继续正常按日期阅读；临时页到期后只能重新从正式章节提取并另发新页。
替换测试稿时，先用 `node scripts/delete-temporary.mjs <旧ID>` 删除旧页，再发布新页；核对旧页不可读、新页可读，且正式章节与 VIX 标注保持原状。

## 任务末尾额度更新

执行本协议所涉及的日课、推送、练习建设、批改、声音分析或测试工作时，最后按 `BALANCES.md` 查询各方额度，携带核对时间、核实/估算状态与用户完整学习流程的用量范围，发布更新到余额页；各方仅在不足三次最大消耗任务的预留时提醒。页面显示上一次任务的记录，浏览时不实时查询。不自动付款，不安排余额不足后的跨日轮询/重试；已有材料与未知计费保护继续有效。
