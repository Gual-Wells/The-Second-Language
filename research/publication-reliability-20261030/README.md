基线：`0f8f178f556f6b36e890b0b29bd6bf571b80a643`，2026-10-30。

本轮落实已采用的authentic-context-v1／usage-context-v1，不新建出版框架、不改章节教学范围。保留50主词、完整双教材/词族/全义、1–5份取优、默认休息、空音频及未知计费保护。没有生产新课程或将工程fixture发布成正式教材。

## 实际补齐

1. **固定采用证据**：pack-current-affairs在取得原件仍可核对时，验证作者与采用来源读件的实际摘要，封存原文、凭据原字节、新取得HTML、完整作者稿及教材材料。章级公开来源包只增加evidenceDigest；私有manifest绑定正文、运行、选择和VIX输入。按约8MiB批次进入现有OneDrive内容寻址文件基座，D1不新增逐义表。作者/来源批次分开，同章同原文和HTML去重；跨章只完全相同批次物理复用，不声称全局逐件最优去重。
2. **可靠恢复与发布**：本机证据对象先完成临时写入、同步，再以不覆盖旧对象的方式落到摘要路径。publish-chapter在stage之前上传并回读，丢ACK后以同摘要继续。新单正文stage缺证据则拒绝；commit实际读取分包并核SHA，不仅看长度。旧已存在digest的来源绑定、发布时间和收费身份不重写。
3. **质检证据适配**：chapter-quality-v3-evidence先独立读教材，随后对照同版作者去向、取境与增量。允许原例留存而不全展示，仍检查独有信息。缺/错版证据保持needs_evidence，不用当前新稿或重新抓取替代。旧报告/检查点不升级冒称完成；同身份已有合法模型结果仍复用。私有取舍不打印到读者报告。
4. **成熟提取路由**：新HTML默认Trafilatura2.3.1；既有问题模板KFF/CNRS使用Readability0.6.0＋jsdom30.1.3。固定版本及D盘配置，缺失明确失败、不退回旧正文启发式；已有读件离线复用和web/PDF原文导入保持。新native GET保留观察到的HTML原字节及摘要。工具仍不能认证正确语义、图注完整性、实际已读或采用权。
5. **原生客户端兼容**：v58只更新质检策略协商及缓存版本，版面、字体、动效、手势和声音不改。v50–v57客户端仍取得其认识的v2传输别名，新申请实际记录v3及真实digest；旧任务不借别名换标准，避免更新期间按钮失效。

## 独立审查后的修正

- 封存后repack曾先读旧readRecord缓存；现以固定包核正文和当前作者对象，不再依赖历史绝对路径。首次封存仍严格验证作者实际读件；同版不同凭据合法，错版不合法。
- 同长度破坏曾能通过commit的HEAD检查；隔离复现后改为提交前读取SHA。测试要求损坏返回503且不产生正式指针，恢复原字节后同stage正常提交。
- 当前作者去向改变但正文未变，也不能默默沿用旧包；重新核对后才可形成新的来源身份。已经绑定的历史正文不静默改绑。
