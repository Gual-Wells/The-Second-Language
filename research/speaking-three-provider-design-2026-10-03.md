# 三路完整原声采集与 Codex 接管：设施建设前讨论

日期：2026-10-03。本文件保留设施建设前的设计建议与真实补测记录。同日后续建设已建立采集核心与运行协议，见 `protocol/SPEAKING_PIPELINE.md` 和 `research/speaking-prompt-schema-test-2026-10-03.md`；正式 PWA 原声入口仍未启用。

## 判断

建议采用每份口语作答 Whisper、Gemini、Qwen 各一次完整原声调用，独立采集后完整交给 Codex。按申请运行第四部分，现有实测费用支持这项投入。GPT Audio 暂不加入常规通路，保留今后专项比较或替换的接口；现有结果不足以证明它在所有声音任务中完全可替代。

三家共同确认只能增强某项结论的可信度，不能证明某个音素错误。Whisper 的识别时间、生成模型的声音观察、供应商量纲的评分、Codex 的教学判断分别保留。

## 每路任务

| 通路 | 获取内容 | 使用边界 |
|---|---|---|
| Cloudflare Whisper large v3 turbo | 完整原生返回、转写、句段和词级时间、实际返回的识别统计 | 提供文字底稿和近似回听位置，不要求它产生音素诊断或任意 JSON Schema |
| Gemini 3.8 Flash | 忠实转写；重复、填充词、重启、自我修正、听不清处；清晰度、重音、节奏、语调等可听观察；语言意见和不能判断的部分 | 具体声音意见须有片段依据，模型观察不变成已测量的声学事实 |
| Qwen 3.8 Omni Flash | 同样覆盖完整原声，独立转写及观察，允许和 Gemini 不同 | 不在首轮提供另一模型的转写、确认稿或范文，避免复制共同错误 |

两款生成模型保留同一基础数据要求，同时允许自由补充观察。覆盖整段，不设置“必须找出几个错误”或只输出三条建议的目标。供应商提供的语言建议也完整保存，最终是否采用由 Codex 决定。

原录音不可变；为接口转换 WAV 等格式时另存副本，记录原件与转换件摘要、采样率、时长和时间映射，不删停顿、不改播放速度。三路必须覆盖同一完整作答。

## JSON Schema 的用途

本轮实际读取 OpenRouter 两款模型的公开 endpoints API：Alibaba 的 Qwen 端点，以及 Google/Google AI Studio 的 Gemini 端点，均声明支持 `response_format` 和 `structured_outputs`。这证明当前能力声明；尚未实测原声加新 Schema 的组合。

设施建设时使用 `response_format.type=json_schema`，配合 `provider.require_parameters=true`；具体 Schema 仍须符合所选端点支持的子集。Schema 主要组织：

- 完整逐字转写，包括可辨认的重复、填充和未完成词；听不清的片段及候选内容。
- 逐项声音观察，关联原话或片段索引，区分可听观察、解释推断和练习建议。
- 语言层意见，保留产生意见所依据的原话，便于排除 ASR 改词造成的误批。
- 其他发现、模型自述局限和无法判断的项目。

没有依据的时间、音素、音高、信心数字或评分允许为空。不要求每个词必须获得音素诊断，不把模型自报 confidence 当成校准概率。生成模型给出的时间另记为模型估计，不覆盖 Whisper 的 ASR 时间；精确回听需后续核对。严格结构只约束格式，不能保证内容为真。

请求参数、实际模型/provider、HTTP 状态、返回 ID、finish reason、usage 和费用由后端记录，不要求模型自报。原始响应体完整另存；解析结果是派生产物，不覆盖原件。解析失败或输出截断也保留原始返回并说明状态。

## 保真交接

建议私有交接目录包含：

```text
attempt/
  manifest.json                 # 题目/作答版本、录音摘要、三路状态和文件索引
  audio/original + converted    # 私有原声与实际评测输入
  providers/whisper/raw.json
  providers/gemini/raw.json
  providers/qwen/raw.json
  observations.json            # 全部可解析条目、来源指针、冲突；不取代 raw
  transcript-working.md        # 校对中的底稿；原转写保持不动
  codex-notes.md               # 可自由建立的接管中间文档
  feedback.json + feedback.md
```

每份返回保留全部内容；不能仅把预先压缩的共识摘要交给 Codex。自动整合只建立关联和标记分歧，不用投票选出“唯一正确稿”，不删除未采纳的意见。原始接口数据能够保存什么就保留什么，不宣称取得供应商未返回的内部数据。

Codex 读取完整三路数据、题目及其来源快照、参考答案、本人历史作答与反馈。先核对本次实际表达，再按雅思方向分析流利度与连贯性、词汇、语法、发音；参考答案用于展示更好的表达，不要求复制其观点或词汇。具有实际依据的声音结论和待回听项目分开。

正文反馈突出本次已有能力、最值得改进的项目、具体练习及重答建议；详细证据和其他意见可展开阅读。全面审阅不等于把所有可能问题同时推给学习者。对于仍影响结论的识别分歧，可让本人回听核对，确认稿另存版本。资料不足的声音项目明确待确认，不能因三路意见相同而补造确定结论或完整 band。

## Cloudflare 与项目闭环

```text
PWA 提交原声
  → 私有对象存储 + PRACTICE_DB 作答索引
  → 后台任务分别调用三路完整录音
  → 保存全部原始返回 + 建立可回读的交接目录
  → Codex 领取该作答，完成教学分析
  → 回写反馈、回听关联和练习建议
  → PWA 查看反馈 / 重答形成新 attempt
```

沿用独立练习库；数据库存关系与状态，大录音和返回文件存私有对象存储。手机上传完成即可离开，不需要等待三路接口和 Codex 批改一直保持网页连接。

优先研究已验证的 Cloudflare Cron 后台调用方式，读取待处理作答。它与每日北京时间 03:00 的课程任务分开；口语提交不需要等待次日日课。此前成功的是 Cron 通路，普通 HTTP Worker 出口尚未通过相同实测。Cron 也不承诺固定国家；新任务记录实际成功或地区错误，不能把未知路由当作成功。

三路并行，每路分别保存完成状态。已完成请求不因另一请求失败而重跑；针对失败路做有限重试，保留每次调用和费用。三路不齐时让用户知道缺哪一路，保存已取得的数据，不悄悄称为完整三路分析。具体重试等待与后台频率留待设施建设根据真实运行选择，不增加当前用不到的工作流框架。

## 费用依据

采用预算汇率 ¥7/$，不是即时汇率。相同 76.796 秒录音，此前 Qwen 实际返回费用 ¥0.00458955，Gemini ¥0.0267855。Cloudflare 当前 Whisper large v3 turbo 标价 $0.000513/音频分钟，此录音标价折算 ¥0.00459624；这项是标价估计，不是本轮账单。

三路合计基准约 ¥0.03597/份；30 份同规模同输出约 ¥1.07914。新设计输出内容更多、录音长度和路由价格可能不同，因此不能承诺此为正式固定价格。可先按每份约 ¥0.1–0.5 留模型费预算，30 份约 ¥3–15，属于规划余量，不是支出硬上限或实测新 Schema 费用。存储/Worker、重试及已有 Codex 订阅用量另计。

主要新增 Codex 工作是阅读和核对三路材料。保存可回读文档并从完成处续作，比反复塞入整段对话或让模型记住所有分歧更适合本项目。

## 腾讯复测：完成两个有明确目的的调用

### 完整自由说复测

同一 76.796 秒 WAV，PCM 16kHz/16bit/mono；`eval_mode=3`、`score_coeff=4`、实时流式发送、无参考稿，正确 AppID。最终完成，转写和首次逐字相同。

以同一规范化方式与本人确认稿比较：149 个参考词、147 个返回词、74 次词级编辑，约 49.66%。它混合识别差异，不是发音错误率。供应商准确度 45.4673、流利度 0.929062，与首次相同；本模式没有返回音素条目。没有把降低苛刻度当作质量优化。

结论：本人的这份完整作答上，没有显示自由说可用性改善，不加入默认三路通路。

### 有原话参考的句子模式

为了核查腾讯是否提供独特的数据，而非只增加另一次错误转写，从原声 5.15–13.05 秒提取 7.9 秒实际句子；参考文本来自本人确认的实际原话，不来自 7.5 范文。`eval_mode=1`、成人苛刻度 4，完整终态收到。

返回 13 个词、68 个音素条目，含音素准确度和片段内毫秒起止；所有音素边界在 7.9 秒内。供应商整体准确度 26.4501、流利度 0.773356、完整度 1。`ReferencePhone`/`ReferenceLetter` 为空，Stress 与 DetectedStress 均为 false，没有据此声称完成重音检测。片段毫秒需要加原声裁剪起点才能用于回听。

这证实句子模式与自由说能力不同。给了参考稿后返回相同词，并不是独立转写正确率；返回音素序列也不能证明已经可靠识别本人每个实际误音。当前没有独立音素听审或分数校准，不因低分判定本人发音差，也不因有 68 个条目就认定诊断合格。

结论：腾讯保留为可选的句子专项评测候选，暂不进入正式自动判断。将来若要验证音素纠错，优先针对已有回听争议的短句，经过听审确认它确实增加可用信息后启用；本轮不要求自动拆整段逐句调用。

两次调用的原声和全部原始包保存在忽略目录，旧结果未覆盖。未写正式作答、生产数据库、VIX、正式课程或 PWA，没有新建云端测试资源。本次腾讯实际扣费未在账单核验，不编造消费金额。安全摘要见 `outputs/tencent-speaking-retest-2026-10-03.json`。
