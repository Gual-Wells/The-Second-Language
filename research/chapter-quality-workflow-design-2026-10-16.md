# 章节质检：分析体系与工程实施设计

2026-10-16，北京时间。接续 [可行性研究](chapter-quality-feasibility-2026-10-16.md)。本文件是供实施和校准使用的设计，未启用线上质检接口或认证。

## 1. 产品承诺：证明做过什么检查

质检对象是固定版本教材，不是学习者，也不是生成后的任意关联资产。目标是发现会误导学习的真实错误、来源漏项、虚假用法覆盖及误译，并留下可反驳的依据。

必须分开回答三个问题：

1. **有无依据**：章节的语言断言能否在指定资料中得到支持，或有明确的补充依据？
2. **有无遗漏**：应教的材料是否被漏掉、错误合并、排除或没有进入相应部分？
3. **运用是否成立**：例句和范文是否在实际上下文中使用了所标记的义项？

只检查已写出来的句子是否正确，会漏掉没有写出来的 Oxford 独有义项。只检查来源覆盖，会错过用法出现了却用错了。只检查编码齐全，则三者都不能保证。

内部“质检通过”只能表示：在列明资料、标准、范围和当次审阅下，必检工作已完成、未发现尚未关闭的阻断问题。不能表示语言知识绝对正确、出版商背书或学习者已经掌握。

## 2. 采用成熟方法，但不照搬一个指标

### 2.1 来源支持：借鉴 AIS

[AIS](https://research.google/pubs/measuring-attribution-in-natural-language-generation-models/) 将“输出能否被指定来源支持”作为评估对象。对本项目有价值的是明确来源与断言，避免把模型常识当证据。应用时保留上下文，先判断待审语句究竟表达了什么，再判断来源是否支持；不能只凭两个片段语义相似就打勾。

“符合这份教材”与“反映最新学术结论”是两个范围。教材本身有疑义时，可以给出来源冲突，但不能暗中改用新来源后仍声称完全保真于旧来源。

### 2.2 细粒度断言：借鉴 FActScore

[FActScore](https://arxiv.org/abs/2305.14251) 拆分可核验事实并判断来源支持。这适合避免一个段落大部分正确掩盖一处关键错误。但词典里的限制条件、语域和否定不能拆丢，普通叙事性虚构也不应该被当作现实世界事实逐条查真假。

因此不把原论文分数当作本项目现成质量分：它主要解决已生成事实的支持度，不自动解决教材遗漏、义项运用或教学效果。

### 2.3 译文：借鉴 MQM 的错误分类

[MQM 官方框架](https://www.themqm.org/mqm-pillars/typology/)区分意义准确、语言规范、术语、风格等问题。项目采用其“先识别具体错误再讨论严重度”的思路，重点核查遗漏、增义、错义、数字/否定、指代、时序和语气。不追求一句英文只有一种中文译法，不把风格喜好伪装成错译，也不声称已取得 MQM 或 W3C 认证。

这三种方法互补，不能靠一个总分替代。模型自评偏好和提示敏感性仍存在，已见前份研究中的原始论文；本设计不宣称换一个提示词就取得真正独立专家审查。

## 3. 取证包：先解决能查，再解决怎么判

### 3.1 固定身份

申请保存 `requestId、chapterDigest、policyId、policyDigest`。原正文以服务器历史版本回读并核验摘要，不接受前端上传一段文字充当正式章节。

来源依据从 `chapter_revisions` 的运行/VIX/协议身份追溯，读取现存来源锁、教材字节与生产材料。VIX 选词输入提交和标注发布提交可能不同，必须依据教材文件摘要核对，不能错误要求两者永远是同一 SHA。

证据包至少包括：

- 固定章节原件及由现有解析器生成的 WORD/USE/例句/范文句清单；
- 两份教材各自的文件 SHA、来源版本与有关原始片段；
- 重复标题、编号词条、交叉引用和相关派生的收集范围；
- 逐词工作文档、原例句去向和语义审阅记录，作为待审生产材料；
- 实际缺失项，不用后来补写的说明冒充过去已存在的证据。

完整教材只按固定字节保存/取得一次；每份质检读取本章相关范围。不得把约 33 MB 的两本全文每次全部塞进模型，也不先建立庞大的全书知识图谱才能审一章。

### 3.2 来源定位需要能重新读取

建议定位为 `bookDigest + entryOccurrence + 原始范围 + excerptDigest`。同名标题可出现多次，不能只有 `word=robot`。解析视图如果统一 CRLF、空白或 Unicode，须保留回到原字节的定位依据，不能拿规范化后的摘要冒充原件摘要。

教材片段引用先由程序核对字面和摘要；片段支持了什么仍是语义判断。`etymology_links`、参考书名或工作文档的一句“已核实”都不自动升级为原证据。

### 3.3 来源闭包是有边界的任务

先获取全部精确及编号同名条目，再沿明确引用和确属词族的派生拓展。词族归属由语义判断，不能将所有同前缀词自动合并，也不能为了防膨胀在固定 N 层处静默截断。

每条引用明确分为已读取、真实重复、不属于本范围、尚不能确定。达到合理运行限制时返回未完成/缺证；“范围已闭合”是带证据的审阅结论，程序仅能验证引用清单是否已处理，不能证明模型绝无漏看。

## 4. 分阶段分析

| 阶段 | 主要输入 | 必须回答 | 检查点 |
|---|---|---|---|
| 0 固定资料 | 章节、来源锁、策略 | 材料是否同一版本、哪里缺失 | evidence manifest |
| 1 结构 | 真实解析对象 | 三部分、编码、排序、配对是否成立 | 完整目标清单 |
| 2 来源优先的逐词审阅 | 原教材先于生产映射 | 应教哪些内容，实际上去了哪里 | 每个主词/自然词族的结果 |
| 3 用法对应 | USE、全部例句与所指范文句 | 在这句里是否真的用了这个义 | 每条实际引用结果 |
| 4 作品及译文 | 全文、上下文、跨词发现 | 事件、指代、语域和译义是否连续 | 全文审阅结果 |
| 5 反证复核 | 拟阻断问题、来源冲突 | 能否定位、是否误报、有无反例 | 发现的确认/撤回/待核实 |
| 6 收尾 | 所有已验证阶段 | 是否完成、什么结论、哪些限制 | 不可变最终报告 |

### 4.1 不让生产者的结论主导审查

第二阶段先以原教材整理预期内容，再查看生产者映射。否则模型容易沿已有 U 编码逐项确认，却看不到根本没分配 U 的漏义。原工作文档对“为何这么做”有价值，但不能兼任独立正确答案。

例如首章 `adversity`：来源含一般逆境及一次不幸等区分，审查需查看其归并是否合理、可数/不可数及例句是否体现相应意义；只看到两个 USE、两条例句齐全不够。该例仅说明检查方式，不在此文件给全章通过结论。

### 4.2 必检单位不是只有 40 个词

当前已测单章有 66–473 个 USE、68–571 条例句、49–240 条范文句。每个例句都必须检查；同一个 USE 有三条句子，其中一条正确不能替另外两条免责。范文句同时关联多个 USE 时分别判定。

推荐用不可变检查身份：

- `source:<bookDigest>:<locator>`；
- `use:<useId>`；
- `example:<useId>:<ordinal>`；
- `article:<sentenceId>:<useId>`；
- `translation:<part>:<sentenceIdentity>`；
- `global:article`。

这是审阅包中的任务索引，不是在 D1 建上千行热数据。界面可按词条聚合，完整证据仍保存。

### 4.3 不错杀项目接受的取舍

词密度高、体裁特殊、少见义项、一定编排感，都不是独立错误。只有具体语义、语法、语域、译义、指代或结构确有问题才列缺陷。对于模型不熟悉的罕见用法，先查来源；不能因为“不像平时见过”就判错。

若减少自然感是完整覆盖的结果，记录为已接受取舍；若某一句本身不成立，则仍需修正。两者不能混同，也不能为改善故事删去难义项。

## 5. 分析结果与合格判定

### 5.1 每项结论

逐项使用 `supported / issue / unresolved / not_applicable`，并给出位置与理由。`not_applicable` 需要真实适用范围说明，不能作为绕过必检工作的默认值。

发现另记：`severity、category、location、exactQuote、sourceRefs、rationale、suggestedAction、verificationState`。分类包括来源漏项、误归并、语义/语法/词性、搭配、标签、音标、例句错义、范文假覆盖、译义及全局连续性。

同一根因在几个阶段被发现，合并到一个 finding 并保留受影响位置，避免重复扣分。建议与已确认错误分开；对已撤回的发现保留复核记录。

### 5.2 四个结论维度不能互相抵消

- **来源可用性**：必要资料和引用是否可取得；
- **审阅完整性**：必检目标是否全部完成；
- **语言质量发现**：已确认错误、疑义及建议；
- **项目内部资格结论**：是否具备签发通过状态的条件。

确定性程序只能验证前两者的一部分及数据一致性，不能代替第三者。模型的“100% 已审”也不自动证明前两者。

### 5.3 不抢先锁定分数

原报告 30/25/20/15/10 权重和 90 分阈值没有本项目校准依据。首版推荐以规范评语、完成范围和缺陷分级交付，不显示伪精确总分。

通过门槛是：必要来源可回读；必检对象没有缺项；没有未解决的阻断缺陷或必检疑义；阻断发现已反证复核。高分不得冲掉重大误导。完成检查但缺证，返回 `needs_evidence`；处理故障返回 `incomplete`，不评教材失败。

## 6. JSON、检查点和恢复

模型一次只返回当前工作块的结构化结果，后续由程序合并。每块固定 `requestId、evidenceDigest、policyDigest、stage、targetIds、attemptId`，验证未知/重复/遗漏 ID、引用原句、来源定位和摘要。格式 schema 只是第一层验证。

工作块大小按实际资料和已测执行表现调整，不规定每词一个进程或固定“每五词”。第三部分整体审阅必须得到完整文章；不能仅依赖各块摘要拼成全局结论。

检查点保存已完成结果的内容摘要和所覆盖对象。续作仅复用匹配同一证据/策略/阶段的已验证产物。对新的上下文或策略变化不能直接继承旧结果。

重试区分三类：

1. 结果已生成，上传/回推失败：重试传输，不重新推理。
2. 未完成或结果无效：明确记录尝试，用户继续后处理该块；未知计费继续受保护。
3. 完整复审或新证据：新申请、新活动，保留旧报告。

不安排模型余额不足后的跨日自动重试。只记录结论、证据、产物、实际模型及执行状态，不要求或导出隐藏思维链。

## 7. 后端具体落点

### 7.1 模块边界

建议 `worker/src/chapter-quality.js` 独立业务；现有 `questions.js` 共享领取器纳入 `kind=chapter-quality`。本机新增质量执行模块，由现有监测入口分流，复用身份、心跳、模型执行和末尾额度能力；不先抽象重写全部问答和测试。

模型进程只读，拿不到发布凭据和 Microsoft 刷新凭据。阶段输入由确定性取证器提供。章节及第三方资料是待审数据，不能改变执行指令、访问账户或要求写入文件。

### 7.2 数据库

首版可用一张 `chapter_quality_requests` 保存紧凑状态：

| 字段组 | 建议内容 |
|---|---|
| 固定身份 | request ID、章节 digest 外键、policy ID/digest、证据 manifest digest |
| 排队运行 | status、claim hash、lease、attempt ID、创建/更新时间 |
| 进度 | 当前阶段、已完成/预期目标计数、短错误码 |
| 完成 | decision、report digest/字节数、受限长度摘要、完成时间 |

章节 ID 可经 revision 关联取得，避免重复身份漂移。完整报告、阶段结果、来源包和模型返回不进 D1。不要为了将来可能统计就先建每原子断言一行的多表体系。

同章同策略只允许一份活动申请；终态之后用户明确复审才新建。同 request ID 的不同正文身份必须冲突，不能返回另一章的旧申请。最终 SQL/迁移需在实施时按实际存储接口验证，本表目前只是设计。

### 7.3 接口

读接口按当前章固定 digest 给出概览与历史；申请 POST 使用客户端幂等 ID；详情/报告按 request ID；失败后显式 retry；publisher 独立 claim/heartbeat/checkpoint/complete/fail。

浏览器只提交正式章身份，不提交“权威教材全文”。报告由服务端按摘要读取，隐藏内部凭据、完整私有教材和不必要执行日志；返回文本安全渲染，不执行模型 HTML。

### 7.4 领取权和签发

不能只在模型启动前检查一次 claim。检查点提交及终态签发都应检查实际 status、claim、attempt 和租约；完成时在同一 D1 事务内再次约束所有权。已完成同摘要回调幂等，不同摘要冲突。

OneDrive 原件先写并回读摘要，再提交成功指针。若期间失去领取权，原件可以保留待复用，但旧进程不得签发。D1 不成功不能让前台看到通过；OneDrive 不成功不能把元数据写成完成。

Cloudflare 官方说明 `batch()` 为事务，语句失败会使整个序列回滚；这能保证数据库状态一致性，但不能跨服务替 OneDrive 提供分布式事务。[D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)

## 8. 调度、公平性与成本

质检通常比普通答疑长。沿用每分钟普通脚本检查，不再加一套轮询；无任务不启动模型。质检在自然检查点释放工作权，让待办答疑获得处理机会，再以同一证据续作。已有一次模型执行不承诺瞬时抢占，不能靠杀掉进程改善体验。

详细恢复状态在本机 D 盘与永久文件中，D1 只保存进度摘要。暂时离线的产品显示等待或中断；其他已发布章节、点读与答卷照常使用。

默认依托现有 Codex 服务，不新增第三方推理月订阅，不重复合成 TTS。模型实际分析仍消耗 Codex 额度；以后若用异源模型只针对确有价值的疑难，不把多模型多数票当事实依据。

发布/修复文章与质检保持独立：报告可以提出修订申请，但只读质检不直接改章。真正修订后新 digest 需新审，未改句子继续复用原付费音频。

## 9. 前端与状态语义

入口采用标题区紧凑“质检”按钮，打开同系蓝银窗口；不挤占现有常驻顶栏，不改变长按答疑、句子点读、双击沉浸及绝对阅读位置。

初始展示“尚未质检”和申请；处理中显示实际阶段及完成范围，不报虚假倒计时；完成后先看简明结论、阻断问题和缺证，再按词条查看细项。完整原始报告可独立读取，不把上千检查行全部铺到默认手机页面。

新章修订后旧状态显示为“旧版本记录”，不沿用合格。定位问题时打开正确历史版本、保持原画面直至目标稳定，之后静态揭示；关闭报告回到原阅读位置。

点击查看不能悄悄触发复审；明确“重新质检”才产生新的模型工作。没有检查完成的范围不显示绿色通过，缺证不使用红色教材错误的语义。

## 10. 校准和验收计划

### 10.1 对照集

采用最早短章与高密度章真实片段，包含正确但编排密集的内容；另建立人为已知缺陷，覆盖教材漏义、错误合并、派生误归、语域、错例句、假 USE、译文否定/数字、指代及整体连续性。每项独立保存原版、修改版及真实标签，执行模型看不到修改位置和答案。

先验证语义识别能力，再测试全章运行与恢复。只在精挑的几个明显错误上成功，不足以证明全部章可靠；也不能把尚未人工核实的自然发现一律计作误报。

### 10.2 分开统计

- 已知重大缺陷的召回与精确定位；
- 正确/已接受取舍上的错误指控；
- 发现严重度分歧与复核后撤回；
- 必检对象完成率、证据缺口与运行中断；
- 同一证据重复执行的稳定性；
- 各规模章的实际输入/输出、运行量和等待情况。

样本少时呈现实际计数，不把百分数包装成总体准确率。通过阈值待试运行决定；当前不凭空指定“95% 就可上线”。

### 10.3 故障闭环

必须覆盖请求丢响应、重复申请、租约转手、旧 attempt 回调、上传成功但签发失败、报告故障、电脑重启、资料变更、策略升级、队列等待，以及当前已出现的 D 盘联接归档恢复。章节测试/答疑及付费原件不得被覆盖或重新生成。

## 11. 当前决定与下一步
