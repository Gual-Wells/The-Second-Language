# 2026-10-04 KV 写入额度事故

用户在 iPhone 试听页提交评分时收到 `KV put() limit exceeded for the day`。Gmail 中 Cloudflare 于北京时间 16:39 发出的邮件确认：账户免费每日 1,000 次 put 已耗尽；API 返回 429、Worker 内 put 失败，至 2026-10-05 00:00 UTC（北京 08:00）恢复。

## 原因与责任

本次 220 个音频，原设计每个片段写入启动、请求、原声、返回、归一后的播放版，共 1,100 次；37 批余额记录加一次 manifest，共约 1,138 次，还未计算之前试验和真实项目写入。独立 namespace 只隔离数据，无法隔离整个账户配额。事前未按账户级额度控制测试设施，是实现疏漏；模型费很便宜不能用来推断存储设施没有限额。

## 实际核实的影响

读取 Cloudflare 现行各 Worker 绑定及课表、VIX 现行部署源代码；只做正式项目只读请求，没有向正式 KV 写探针，没有领取生产运行或修改学习标记。

| 项目或通路 | 本项 KV 写入限额的影响 |
|---|---|
| 第二语言已有页面、登录和学习设置 | 正式首页、health、auth/status、发布身份的反馈快照查询返回 200；D1 身份与设置不受本项限额封锁 |
| 已有章节和音频读取 | KV 本次只封锁 put；get 仍可使用；没有把此判断冒充已逐章完成手机端阅读测试 |
| 新章节、临时页、练习音频写入 | 依赖 KV put，会受阻；不应宣布新内容已推送 |
| 口语原声上传、采集结果存储 | 使用 PRACTICE_MEDIA 的 KV put，会受阻；查询正式 speaking_jobs 当前为空，无正在付费采集的任务受本次故障中断 |
| 写作文字答题及 D1 操作 | 不受这项 KV put 配额直接影响，D1 自身仍有独立限制 |
| 课表服务 | 现行 neu-schedule-push 绑定 D1、无 KV，部署源中没有 KV REST 引用；不受本项限额直接影响 |
| VIX 服务 | 现行 vix-bridge / vix-private 无 KV 绑定，部署源中没有 KV REST 引用；不受本项限额直接影响 |

明日 03:00 早于 08:00 的重置。实际 Windows 定时入口所在 checkout 已加入额度故障续作说明：保留同日期产物，发布失败不能重选、重标、假报完成。没有改动用户既定 03:00 时间，没有宣称已安排 08:00 自动续发。

## 已修复的试听设施

- 沿用原页面地址、访问 cookie、本机评分存储键。
- 220 个既有音频迁为 Pages 静态部署文件，没有重新生成音频或调用收费模型；直接静态目录不可访问，授权音频接口处理 Range。
- manifest 来自固定计划，不再读写 KV。
- 反馈写新建独立 D1：`tsl-kokoro-lab-feedback`，按会话/提交 ID 幂等；正常试听与提交不再消耗 KV 写入。
- 增加本机 JSON 导出。用户已输入的评分、备注和合格判断在刷新后沿原键恢复。
- 自动验证模拟恢复 17 项反馈，逐项核对数值、合格判断、备注；在 KV put 封锁时成功写 D1，重发同一提交没有重复行，JSON 导出保真。验证单词播放、匿名 401、直接静态文件 404、Range 206 和窄屏无横向溢出。删除自动检查的 D1 评分行。
- 17 张原截图及结构化反馈保存于私有缓存；单独注明截图来源保存至私有反馈库。未选择的数值保留 null，不补零分。后续手机原始提交与截图记录分开，原始提交优先。

当前截图只有 16 个词汇音色和 Alloy 的一项句子反馈。Bella、Heart 词汇均 5 分；Nicole 也是 5 分，但用户指出 ASMR 风格与非标感。Michael、Fenrir 各 4 分，分别有低沉/沙哑和噪点/清晰度问题。Alloy 句子 3 分，用户认为缓慢且听着不舒服。其余句子及三类对话不能从这些截图推断。尚未完成四个女声音色的截图反馈，也不据此改动正式声音默认。

## 后续方式

少量试听直接在聊天提供本地音频，反馈在聊天收集。较多音色或需要切换男女的试验保留轻页面，用已有静态文件、低频整份 D1 反馈和本机导出。Cloudflare 可以继续承担已验证可用的 API 代理；代理本身不必附带 KV 过程存储。完整请求与输出存于 Codex 本地中间文件，避免复刻此逐片段 KV 写入方式。

没有自动升级订阅或扣费。Workers Paid 官方最低 $5/月是解除免费每日写入上限的一条选项，不是本次试听修复的必要条件。正式项目目前仍在免费写入恢复窗口内，应明确说明不能立刻通过新增 namespace 或删除文件恢复已耗尽的每日 put。
