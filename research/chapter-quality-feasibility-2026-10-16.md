# 章节质检申请：真实可行性、执行设计与上线边界

日期：2026-10-16（北京时间）。本文件是研究和实施设计，**没有新增线上质检入口，也没有给现有章节签发合格证明**。源报告和对话已在远端 `565d3dac8db471642d21527bd46a9762fa4d89e9` 固定读取。

## 结论

这项功能可以成立，且比新增一般性的模型评价更有价值。现有异步任务、固定章节版本、逐词工作文档和永久存储已提供主要基础，不需要重构数据库或另建一套调度器。

但它必须是**对照原材料的独立审阅**，不能把“请评价本章”包装成质量认证。本轮独立核查修正了报告的一点判断：普通答疑确实只收到整章和会话，**但双教材原件及逐词工作文档并没有全部缺失**。真正要补的是“按历史版本取证、证明覆盖、独立复核和结果发布”的业务闭环。

建议先上线“申请质检 → 逐项报告 → 有据修订”的能力。合格状态可以保留，但只能在证据和审阅范围完整时签发；不预设未经校准的 90 分通关，也不先给小数点评分制造精确感。

配套：[词源权威化研究](etymology-authority-feasibility-2026-10-16.md)；[本轮实测证据](feature-study-evidence-2026-10-16.json)。

## 一、先纠正对象：这不是原 PR #1 的代码审查

用户希望在章节内部申请教材质量审查。此前维护工作误把它理解成旧 PR #1 的代码 review，只修复了套卷发布/批改领取权竞争，并验证历史来源跳转；这些修复有效，但没有实现本功能。

同样需要区分：

- **章节测试**：考查学习者理解，目前 20 道、13 文字 + 7 听说；
- **章节质检**：考查教材内容、来源保真和跨部分用法；
- **学习者认证及纪念币**：另一个尚未正式采用的方向。

质检不能授予学习者认证，测试满分不能证明教材无误。本文只研究正文质检；后续随机测试、声音和词源也不自动获得正文结论。

### 2.2 可直接复用的代码和资料

- `worker/src/questions.js`：身份、同源限制、章节固定摘要读取，以及答疑/正式测试/临时测试的任务路由。
- `scripts/question-worker.mjs`：普通脚本轮询、有任务才启动 Codex、隔离目录、只读模型、结构化返回、心跳及末尾额度步骤。
- `worker/src/chapter-tests.js`：独立任务业务、提交/复用/失联语义的参考实现；不是把质检伪装成测试。
- `web/annotations.js`：WORD、USE、EXAMPLE、SENTENCE 对象、三部分顺序、引用和翻译配对。
- `chapter_revisions`：已保存 `run_id`、`vix_commit`、`protocol_commit` 和正文 digest，具备固定来源身份基础。
- `work/runs/<date>/vix-source.json`、`words/`、部分日期的 `source-manifest.json`、`review.md`/`semantic-review.md`：取证入口。不同日期文档格式不同，不应要求历史任务补造一套看似整齐的证据。
- `scripts/lib/work-archives.mjs`、`recovery-snapshot.mjs` 和 `protocol/STORAGE.md`：任务目录分组压缩、摘要和历史恢复；需扩展新类型，并非所有新目录天然被归档。

本次还读回 OneDrive 最新恢复索引所指向的清单并验证其摘要：时间为 2026-10-15 21:29（北京时间），清单内的 `runs/` 工作组仅到 10-10；因此**不能据它宣称 10-11 以后逐词证据已具备云端恢复副本**。继续检查已定位一个真实根因：10-11 至 10-15 的任务入口是通往 D 盘实际目录的联接，Node `Dirent.isDirectory()` 返回 false、`isSymbolicLink()` 返回 true；`archiveSingle` 的首层分组仅接受 `isDirectory()`，因此跳过了这些运行。C→D 分工本身合理，是归档枚举未兼容该实际部署方式。本机材料仍在，这不等于正式正文或已保存音频丢失。

实施时应优先补齐**已批准 D 盘任务目录**的枚举和恢复验证：核对真实目标、去重并防止循环，不无条件遍历任意外部联接。修复后应回读新快照中的 10-11 至 10-14 等来源包并验证文件摘要，再宣称有完整云端证据。本研究只定位和记录问题，没有改归档代码或删除数据。

### 2.3 一项实际验证：结构通过不等于语义通过

在内存副本植入缺陷，原章及线上数据完全未改：

| 实验 | 现有结构检查 |
|---|---|
| 原章对照 | 通过 |
| 第二部分英文换成明显无关内容，保留编码 | 仍通过 |
| 第二部分译文换成不相干中文 | 仍通过 |
| 第三部分原句换成不对应标注用法的句子 | 仍通过 |
| SENTENCE 引用不存在的 USE | 拒绝 |
| 去掉配对译文 | 拒绝 |

这不是现有 validator 的缺陷：它本来负责结构。实验说明 CQA 必须新增语义审阅，而不是再套一层同类脚本。本轮没有运行一个新 CQA 模型去识别这些缺陷，所以没有虚构其 precision/recall。

## 三、审什么：用固定目标清单，而不是一句“全章已审”

质检身份为：

`chapterDigest + sourceEvidenceDigest + qualityPolicyDigest + auditRunId`

不依赖日期或标题相同就复用结论。用户明确复审会产生另一份记录；网络重发复用同一申请 ID。

### A. 来源内容保真

每个主词及实际相关派生，从固定双教材词条及交叉引用建立来源清单，逐项记录纳入、真实重复合并、排除理由、未解决。核对原有例句去向；不能把“每用法至少一个例句”偷换成“全部教材相关例句均提取”。

原词条必须按原始材料重新取回，逐词工作文档是受审材料和辅助导航，不能自己证明自己完整。检查 `See main entry at`、编号同形词、重复标题、无独立标题的派生，以及 Oxford 独有义项。教材格式确有这类结构，按正则命中第一个标题就停止会漏读。

现有检索版的源文件版本和物理字节可验证，但电子检索版是否对出版纸本一字不漏，未在本轮证明。首版应诚实表述“按项目固定双教材资料核查”，不对未核对的原书版次或出版商作额外保证。

### B. 第一部分语义及标签

检查释义、词性、搭配、真实词族、独立细用法、音标及口语/书面/正式/旧式/古义/历史/地域等标签的作用范围。少见不等于错误，正式不等于书面，历史义不等于现在不能描述历史。证据不确定的美式音标列为待核实，不因为 TTS 已有音频就视为正确。

### C. 每个 USE 与所有标注例句、范文句的语义对应

为每条实际 EXAMPLE/SENTENCE 引用建立检查项。确认“该处以所指义项使用”，不是只出现了同一词形。多个用法共句允许，但必须分别成立；一句正确不能替同 USE 的其他错误例句免责。

所有必检 ID 来自程序解析出的冻结清单，模型必须逐项给出结论和位置。程序核对缺项、重复和未知 ID，但它不能仅凭记录写了 `supported` 就证明模型判断正确。

### D. 译文和整体作品

逐句检查译义、语气、否定、数字、指代和事件连续性；再通读完整第三部分。全量词义覆盖造成的密集、特殊题材或一定编排感属于用户已接受的取舍，不能单独扣成重大问题。真实语义、语法或连续性错误仍须指出。

“读起来更像普通小说”不能成为删掉难义项的理由。建议与缺陷分开，质检不自动改正文。

## 四、如何减少模型自评自证

新会话只能实现执行上下文分离，不能把同一个模型变成统计独立的第二专家。相关研究说明模型评审存在对熟悉表达及模型生成文本的偏好，但其具体比率不能直接移植到本项目。[Self-Preference Bias](https://arxiv.org/abs/2410.21819)、[G-Eval](https://arxiv.org/abs/2303.16634)

建议流程：

1. **先固定证据**：从生产章节摘要、原始教材摘要、来源片段和当前审计策略建立 manifest。无法取回就明确缺证，不拿当前 main 替代历史材料。
2. **独立提取来源义项**：先看教材，形成该词实际内容清单；之后才对照生产映射文档。避免生产者的归并判断先入为主。
3. **逐词/自然词族审阅**：对应本章正文、例句及其上下文；按实际材料划分可恢复的工作块，不强制每词一个进程，也不把全章粗略看一次当作逐项完成。
4. **全文审阅**：专门看文章及译文全局连贯，避免分块后失去跨句信息。
5. **复核阻断项**：对拟判严重错误、来源冲突和遗漏重新取证。必要时独立二次判断；不能凭同模型投票宣称独立共识。
6. **确定性收尾**：校验引用、原句、来源定位、必检对象覆盖、证据摘要及最终状态。仍保留模型判断局限。

重复运行不是天然提升：缺少新证据时，同一偏差可能重复出现。初版无需固定引入额外收费模型；真正有争议的个案再考虑异源复核，也不得突破 Cloudflare 后端模型调用约束。

## 五、结果应该怎么表达

### 5.1 执行状态与教材结论分开

执行：`queued / running / completed / interrupted / failed`。

审阅结论：`passed / revision_required / needs_evidence / incomplete`。

网络断开、模型未完成或回读失败不是教材不合格。`needs_evidence` 可以是本次已完成的诚实报告，不应永久处于运行中，也不因此偷偷换来源或重新调用模型。

首版以“检查完成范围、可定位发现、阻断项、待核实项”为核心。满足以下条件才可给出内部合格记录：必检范围已覆盖、必要原材料可回读、无未解决重大缺陷、没有未关闭的必检证据缺口。显示绑定版本与标准版本，不声称机构认证或保证零错误。

未校准时不采用原报告建议的固定 90 分阈值。若以后保留评分，应先用实测样本建立有例证的评分档位，展示各维度和范围限制；重大错误不能靠其他分项高分抵消。

### 5.2 缺陷不是所有可改进之处

每条发现包含类型、位置（WORD/USE/句子及例句序号）、准确引文、教材定位、解释、证据状态、建议动作。重要错误在签发前复核；可选措辞和风格建议不阻断。

不同意某条质检结论时，可以记录复查活动与修订结论，保留原报告。不得静默删除曾经的错误质检或把旧报告改成新的“从未出错”。

## 六、工程接入：小而完整的独立业务

### 6.1 前端

章节标题工具区与“章节测试”相邻放紧凑“质检”入口，打开同系蓝银窗口；不加新常驻顶栏、不增加正文长按/双击语义、不破坏沉浸几何。以现有 iPhone 17 标准视口验收，标题长时应允许既有工具组自然排布，不能挤压成难点的小按钮。

窗口展示当前版本状态、申请、处理情况、摘要和报告；历史版本分开。重复点击/丢响应沿用申请 ID。已完成后明确区分“查看结果”和“重新质检”，不让用户误触产生新模型工作。

报告位置使用现有稳定跳转：保持原画面、提示定位、目标稳定后静态揭示；不产生滚动眩晕。跨版本先打开报告所绑定旧章；旧结论不能在新章冒充当前合格。

### 6.2 队列和执行器

建议增加独立 `chapter-quality` 路由/业务模块，由现有普通监测器支持新 `kind`，复用成熟的身份、心跳和幂等操作。不要把长报告插进问答消息，避免破坏一问一答和上下文。

完整质检比普通答疑长，应支持**工作块检查点 + 主动让出任务**。同一进程仍可顺序工作，但每完成一个自然块回看队列，及时处理较早短问答，再继续质检；模型执行本身没有无损抢占保证。空队列检查不启动 Codex，不另加一套每分钟监测。

申请、租约、重试、实际模型尝试和最终签发分开。完成写入必须在最终事务检查领取权，而不是只在处理前检查——PR #36 刚修复过同类套卷竞争。旧领取者不能发布报告、新申请不能消费旧报告。

额度不足或未知调用结果时保持现有保护，等待用户明确继续；不恢复自动跨日付费重试。失败之后若已有核验通过的模型结果或完整报告，只重试回推/归档，不重新推理。

### 6.3 数据和永久存储

建议 D1 每次申请仅存身份、digest、状态、进度计数、短摘要、报告定位和当前领取权；完整来源包、逐项发现、模型返回、检查点和最终报告存 OneDrive 内容寻址。不要每个 USE/每个语义断言都建永久 D1 热表。

证据包不能只包含本地绝对路径。教材使用固定 VIX commit/文件摘要和服务端允许的来源定位；恢复时按摘要核验。仅取本章需要的词族和交叉引用，不复制整个人的全部历史或把全文搬进高频数据库。

`archiveWorking` 目前只显式收集指定目录；若新用 `work/quality/`，必须扩展其白名单、恢复与凭据过滤。也可在已有每请求任务目录内存质量子目录，但必须实际检查归档清单，不能仅因路径长得像旧任务就声称被备份。

报告需不可变存储并回读 SHA 后再提交终态；回读失败不签发成功。即使同一申请收到重复完成回调，也只认相同结果摘要；不同结果返回冲突。OneDrive 失败、电脑离线不影响既有日课、点读或测试。

正文修复另起版本，不能让审阅进程直接覆盖。修订若改变句子会产生新音频身份；未改句子继续复用已有付费声音。用户没有要求质检顺便全量重新合成。

## 七、容量、代价和实际风险

- 按每章 1 MB 完整报告作**容量情景**，400 章一次约 400 MB；若 5 MB 则约 2 GB。它们不是实际模型报告测量，更不是 D1 占用。复审和完整返回还会增加文件量。
- 词典固定版本只存一次、来源包按内容摘要复用。D1 申请记录增长主要随质检次数，不随全部用法数乘倍增长；最终物理量仍需新表实测，不能保证“永不触限”。
- 默认不新增 OpenRouter/腾讯/TTS 调用，不需要新订阅。实际 Codex 审阅工作消耗账号额度；无任务的轮询不等于审阅免费。
- 473 USE 的章节显著比 66 USE 的章节复杂，不能按“都是 40 词”给统一完成时长或调用次数承诺。先测真实运行再显示合理估计。
- 最重要的风险是漏检和误报，其次才是上下文、来源恢复、队列公平性和签发竞争。JSON schema 能约束格式，不能保证这些语义问题。

## 八、实施前的最小有效验证

先建立小型离线校准集，而不是直接给所有旧章贴标：

1. 最早短章与最新高密度章；正确但编排密集的段落作为误报对照。
2. 人为植入漏掉 Oxford 独有义项、错误义项映射、词性/语域错误、错用例句、虚假 USE、误译、数字/否定颠倒和跨句指代错误。分开统计识别、定位、严重度，不以格式通过充数。
3. 植入来源缺失/旧教材版本，必须报告缺证而非认证。
4. 模型看不到植入位置和预设答案；结果和已知缺陷对照，检查误报及漏报。对照样本未经核验的自然问题不能简单计为模型误报。
5. 最终业务验证包括：重复申请、请求丢响应、租约转手、回推失败、旧结果复用、电脑离线、主动继续、短问答等待、归档恢复和版本升级。
6. iPhone 窗口/长报告/定位及沉浸位置回归；真机 Safari 和自动化浏览器结果分别说明。

本轮已完成的是取证可行性、全章结构检查和内存缺陷实验；**尚未完成语义审阅器校准、完整报告生成、前端入口和正式部署**。下一步最有价值的是用上述两种实际章规模做离线质检试运行，确认可信度后再将同一链路接入申请窗口。词源资料层不必成为这个入口上线的前置条件。
