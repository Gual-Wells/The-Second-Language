# 词源权威化：独立复核、实测与接入选择

日期：2026-10-16（北京时间）。研究阶段；未启用产品功能、未采购词典或授权。

## 结论

值得建设，但当前没有找到同时满足“现代专业编纂、覆盖整个 VIX、允许自动提取及永久保存、免费”的单一数据源。最佳路线是分开解决两个问题：开放词典提供系统性的可追溯资料，专业历史词典提供疑难核验。不能把前者自动改名为权威认证，也不应等待商业整库授权才开始做资料整理。

建议采用 **Wiktionary/Wiktextract 作为主要候选资料层，GCIDE 作为历史补充；OED/专业词源词典作为核验层**。初期向用户显示的是“词源资料及出处”，只有实际核验过的具体断言才显示核验状态。AI 可以做对齐、翻译和教学解释，不能填造原资料没有的历史。

更低成本但更严格的替代方案是只显示专业来源已核实的条目，其余留空。这比混合来源方案更接近“全部展示内容均经专业来源核验”，代价是覆盖率较低、建设较慢。二者是产品承诺的区别，不能在后台悄悄互换。

配套研究：[章节质检可行性](chapter-quality-feasibility-2026-10-16.md)。本轮汇总实测数据见 [feature-study-evidence-2026-10-16.json](feature-study-evidence-2026-10-16.json)。

## 二、两项真正做过的数据实验

### 2.1 GCIDE：整个 VIX 的完整匹配

下载并检查官方 GCIDE_XML 0.53 ZIP：14,333,424 字节；SHA-256：

`02a57fc9057d7f790dd5773af66c85e687ab8950b832dd9c0e1fda8749e4fcbb`

ZIP CRC 检查通过。逐个解析全部 26 个字母 XML；使用包内字符实体定义，移除外部 SYSTEM 实体声明，不从网络展开实体。逐个 `<p>` 读取直接子元素 `<ent>`，提取同段 `<ety>`。按词头大小写折叠匹配，**没有词干化、模糊检索或擅自归并异体词**。

| 指标 | 实测 | 含义 |
|---|---:|---|
| VIX 身份记录 | 15,644 | 整个固定词池 |
| 词头命中 | 13,632，87.14% | 存在同形词头候选 |
| 对应段落有非空词源字段 | 10,095，64.53% | 可以提取词源文字候选 |
| 未命中 | 2,012 | 此精确策略下没有候选 |
| 命中但未取到词源字段 | 3,537 | 可能无词源、另有交叉引用或需更细解析 |

解析得到 124,186 个带直接词头的段落，其中 55,290 个含词源字段。这与官网宣传的 131,566 词头不是同一种计数，不用后者掩盖解析口径差异。短语、嵌套结构、变体、交叉引用可能影响结果，64.53% 不能解读为该词典理论上的最大覆盖率。

缺项包括 `airport`、`email`、`DVD` 等，也包括 `favourite`、`neighbour` 等拼写/变体问题；不能都归因于历史年代。追加英美拼写对齐可以提高命中，但必须保留原关系和单独统计，不能假装是原词直接命中。

本轮候选结果 JSON 约 5.43 MB，gzip 约 1.58 MB，**只是此解析器保留的候选字段，不能当作最终产品整库体积**。这已说明该功能不需要把几十 GB 上游原始资料塞入 D1。

GCIDE 有真实系统性价值，但底本年代较早，现代词缺漏与旧词源解释都需要处理。官方包内字母文件的声明为 GPL v3-or-later；网页说明仍有 v2-or-later 文字，接入时应逐文件保留实际声明，不能只抄网页的一句许可概括。历史来源与官方文件下载依据见 [GCIDE_XML](https://www.ibiblio.org/webster/)。

### 2.2 Wiktionary/Kaikki：22 个高风险诊断样本

取回 22 个确在本 VIX 的词条 JSONL，每份保存 URL、字节数和 SHA-256。样本包含同形词、容易错误拆词的词、借词和近期日课词；这是**目的性诊断样本，不是随机抽样**。

22 个均有词源文字，10 个具有多个编号词源组。这不意味着整个 VIX 的匹配率或正确率是 100%。`bank`、`sound` 各有四组，`cleave` 两组；即使字面完全一致，也不能给所有义项挂同一段词源。`record` 名词/动词材料、`robot` 的多个历史或特殊语境也必须继续按词性和义项筛选。

具体风险已经可见：

- `female` 不能按照表面形式解释成 `fe- + male`；拼写类推与真实来源是不同关系。[Wiktionary 条目](https://en.wiktionary.org/wiki/female)
- `salary` 的资料明确区分盐相关词根和“罗马士兵用盐领薪”的流行解释；后者不能自动变成确定历史。[Kaikki 条目](https://kaikki.org/dictionary/English/meaning/s/sa/salary.html)
- `cleave` 的分开与黏附必须按不同词源组处理，不用“一个词具有相反含义”的记忆故事替代来源对齐。[Kaikki 条目](https://kaikki.org/dictionary/English/meaning/c/cl/cleave.html)

这些例子用于设计错误防线，并未经过本轮专业词典逐断言交叉核验，不签发“权威已认证”。

官方英语页面本次显示约 139 万不同词形、提取日 2026-10-03、上游 dump 日 2026-09-02。网站后处理导出正在弃用；正式构建应优先固定原始 Wiktextract 数据。**本轮未完成 Kaikki 对全部 VIX 的覆盖扫描。** 尝试获取英语压缩导出时实际传输很慢，已停止该下载，没有把开头的一段数据当作全集统计。HTTP 探测得到英语后处理 gzip 523,331,798 字节、全语种 raw gzip 2,981,058,381 字节；后者展开约 23.9 GB，不能在当前 D 盘余量下直接整包展开。

后续采用边解压边筛选，仅保存英语目标词及必要关系；峰值空间不等于解压总体积。保存数据版本及提取器版本，更新时构建新版本，不覆盖历史章节关联。依据：[英语数据页](https://kaikki.org/dictionary/English/)、[原始下载页](https://kaikki.org/dictionary/rawdata.html)、[Wiktextract 官方字段说明](https://github.com/tatuylonen/wiktextract)。

### 3.1 报告遗漏的有价值方向：OED 研究工具

OED Researcher API 与普通 Oxford Dictionaries API 是不同产品。官方研究页列出词、义项、引文、词根、派生等端点并接受研究意向登记。另有 OED Text Annotator，可输出词源类型、直接/间接来源语言、历史使用时间和 revised 状态；但官方也明确其不做义项语义消歧。因此它可能提供权威元数据，不能直接代替逐用法词源讲解，更不能据公开介绍保证可批量永久导入。本轮未提交申请或上传项目文本。[OED 研究 API](https://languages.oup.com/oed-researcher-api/)、[Annotator FAQ](https://oed-text-annotator.oxfordlanguages.com/docs/faqs.html)

UTA 官方数据库目录的检索结果列出 OED，值得用户凭现有学籍检查查阅资格；本轮未登录验证个人权限，也未确认研究 API 资格。学校能打开 OED 不等于允许导入整库。[UTA 数据库目录](https://libguides.uta.edu/az/databases)

普通 Oxford Dictionaries 的官方 FAQ 区分其与 OED，并写明学术研究免费授权最长三个月、到期后不能继续使用相应数据；缓存/离线需 Enterprise。普通条款也限制系统性提取及与 AI 工具结合。这与本项目永久资产目标存在直接冲突，因此“用学生免费期抓完以后永久留用”不是已成立方案。[Oxford FAQ](https://developer.oxforddictionaries.com/faq)、[普通 API 条款](https://developer.oxforddictionaries.com/api-terms-and-conditions)

Merriam-Webster 免费查询额度不意味着自动任务许可；Etymonline 本次核查的官方条款未赋予整库重用权。因此两者保留为参考候选，不按免费批量后端设计。[Merriam-Webster 条款](https://dictionaryapi.com/info/terms-of-service)、[Etymonline 条款](https://www.etymonline.com/legal/terms)

Chambers 官方出版说明为超过三万条目，符合系统性材料要求；不引入几百词的词根表充数。[出版商页面](https://www.hachette.co.uk/titles/chambers-2/chambers-dictionary-of-etymology/9780550142306/)

### 3.2 既有两本教材不能顺手充当完整词源库

本机 Oxford 检索版有 91,549 个二级词条块，但其完整性目标是释义、例句、语法、语域和交叉引用。针对明确语言/来源关键词的方括号探查，仅发现 18 个“像词源说明”的块；该数是启发式探查，不是词源总量。`island`、`salary`、`robot` 等实际材料也没有完整词源段。

因此既有 Oxford 材料不能当作系统性词源数据库。其文件标题和原始电子书文件名也只是当前资料自述，未在本轮完成纸本版次逐页核验；不能仅因文件名有 Oxford，就升级为 OED 或任意其他牛津产品的权威证明。

## 四、建议的数据与发布模型

### 4.1 一份原资料，多种独立用途

最小身份包括：`provider + sourceVersion + originalEntry + language + partOfSpeech + etymologyGroup`。另存来源 URL/修订线索、原资料摘要、适用许可、提取器版本与必要片段；VIX entryId 是关联，不取代来源词条身份。

分别保存三层：

1. **来源文字/结构**：已有词典原材料，不由模型补写。
2. **对齐与核验记录**：为何该词性/词义对应这一词源，是否存在争议、缺证、跨源冲突。
3. **中文学习解释**：引用第一层并受第二层约束；有原文不代表译文必然正确，中文解释另作检查。

“未知”“争议”“拟构形式”保留原性质；星号形式不是有书证的真实词。继承、借入、合成、派生、词性转用、拼写类推、同源关系不混为一个箭头。`etymology_links` 是关系线索，不自动当作学术文献。

资料状态不要只有一个 `verified` 布尔值。至少分别记来源是谁、对齐是否核查、解释是否核查，以及具体断言的证据状态。某本权威书被列在参考书目，不意味着本条已读取该书。

### 4.2 与正式章节保持增量关系

词源先作为与章节固定版本关联的补充资产，按照 `chapterDigest + WORD/USE + etymologyRevision` 保存。旧章节不用为了新增词源重写正文、重置答疑或重新生成音频。词源修订创建新资产版本；读者可以查看当前解释与历史依据。

第一部分可增加紧凑的“词源”展开入口；展开内展示来源与简洁解释，不给所有段落强塞来源标签，不新增手势，不恢复已取消的词汇 TTS。第二、三部分既有句子点读及标题跳转照旧。

词源更新也不改变 VIX 加权推荐，不把缺少词源的词自动降权，更不为了好讲故事删义项。词源对记忆的帮助不能代替现代语义、搭配和语域学习。

### 4.3 存储与许可

D 盘保存上游下载和离线构建；OneDrive 保存原资料中允许保留的版本与提取结果；D1 只存小型关联和状态。可按章节打包补充材料；不用每个字根发一个网络请求，不把完整上游全文入库 D1。

Wiktionary 衍生的文字及其译文应保留来源、链接、适用许可和修改说明；第三方引文/音频不可机械套同一许可。数据隔离便于履约，但“独立 JSON 文件”本身不构成规避许可的依据。本轮未对现有项目许可作未经验证的整体改写。[Wiktionary 许可说明](https://en.wiktionary.org/wiki/Wiktionary:Copyrights)

## 五、现在应该怎么推进

1. **已完成**：真实词池固定、GCIDE 全量字段覆盖、22 个 Kaikki 风险样本、官方接口/许可适配复核。
2. **下一研究关口**：完成 raw Wiktextract 的全 VIX 覆盖；分别列出直接命中、变体命中、缺词源、同形异源、来源不明。完整扫描不是当前已完成成果。
3. **教学小样**：先选本项目真实词条，包含多源、借词、合成、拟构/争议等情况，形成有原文和来源的学习卡；只对实际完成专业核验的断言做核验标识。不能用模型多数票填上空缺。
4. **产品接入**：使用独立补充资产，先让用户评判信息价值与可读性，再决定是否日课默认附带。词源不阻塞现有日课和音频。

无需现在新增持续订阅。开放资料获取和确定性提取不消耗推理 API 额度；翻译、对齐和疑难分析会消耗实际 Codex 工作额度。专业整库授权的价格、可接受保存范围仍未知，未给出虚构报价或先行购买。

**推荐优先级：章节质检先行，词源资料层并行研究；完整专业词源认证等待真实资料和授权。** 两项功能共享版本和证据能力，但任何一项都不因另一项存在而自动合格。
