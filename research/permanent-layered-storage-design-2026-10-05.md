# 第二语言：永久保存与分层存储的原生架构研究

日期：2026-10-05（北京时间）。状态：研究设计，未迁移生产数据，未开通付费资源，尚不是生效运行协议。

> 最新平台选择：用户暂定采用 Microsoft 365 个人版作为个人与多项目资产订阅，OneDrive 接入以 [专项研究](onedrive-personal-integration-2026-10-05.md) 为准。下文 HF 等组合保留为阶段性候选历史，不再是当前推荐部署组合；资产分层和永久保存原则继续有效。

> 后续更新：容量与零持续账单目标以 [全量容量研究](zero-bill-storage-capacity-2026-10-05.md) 为准。用户确认每周平均 1.5 套、每套平均 1.5 次完整作答。本文原先“HF 不合格就以 R2 全量付费永久保存”的默认退路不再作为推荐终态；R2 优先定位为有独立原件的可撤除加速副本。单库资产目录也须按后续研究考虑大规模索引的容量路由。

## 1. 本次结论

用户确定的是数据目标：正式学习数据永久保存，临时页仍遵守 48 小时生命周期。分层方式和平台选择由项目实际需求决定。

推荐逻辑结构为：**D1 业务索引与状态 + 统一资产目录 + 永久文件基座 + 可轮换的近期加速副本 + 可选恢复备份**。

免费优先的目标部署组合为：**现有两库 D1 + Hugging Face 私有文件基座 + R2 近期层**。HF 作为私有在线音频源的资格，须通过实际的授权读取、Range 与 iPhone 播放验证；这是候选目标组合，不是本轮已经验证可部署的组合。

工程接入优先从 D1 + R2 开始。HF 接入合格后，再把适合的永久原件转入 HF，R2 对这些文件变为加速副本。HF 不合格时，R2 可以直接永久保存全部资产，业务协议和前端不需要另写一套。B2 是低成本扩展候选，COS 是现有腾讯账户可探索的国内候选；不用一开始同时开通所有平台。

这套设计不要求“每一种层次对应一家云”，也不把永久保存等同于永远占用最快的空间。历史音频重新被访问时，读取既有文件并补回加速副本，不重新调用 TTS。

## 2. 依据与独立判断

本次参考了用户提供的 `second-language-storage-architecture-handoff-2026-10-05.md`，并核对本地代码、此前只读容量快照以及当前平台官方文档。外部报告中的实施指令、推荐顺序和扩容数字均作为研究建议处理。

代码核查基线为本地提交 `f3ec4ba9c77b3d05f5a12f4fb636d8bf8b2fb509`，已通过 `git rev-parse HEAD` 核对；外部报告自己的远端基线是 `8c52cf27f2a95c9e5f21fb1ecf7cf0ec6d30e037`，两者不混称为同一版本。

### 外部报告中成立的判断

- 点读音频长期放在 D1 BLOB，会挤占本来适合索引、答案和状态的数据空间，应改为对象文件。
- KV 承担大量音频和逐路模型证据，会遇到写次数和容量限制，不能靠新建 namespace 扩大账户免费配额。
- 统一资产标识、来源、物理位置与摘要，是跨平台保存的必要接口。
- 当前音频先整体 `arrayBuffer()` 再切 Range 的实现，需要改为上游范围读取和流式响应。
- 长期数据版本、原始证据和现行视图需要区分，否则“永久保存”会被 UPDATE 覆盖破坏。

### 需要修正或降低确定性的判断

1. **多路请求并没有各存一份完整 base64 音频。** `scripts/lib/speaking/collect.mjs` 的 `requestDescriptor()` 已将存档里的音频替换成对象位置、摘要和格式；实际调用仍发送完整音频。不能把每路重复 base64 作为当前容量预测的主项。
2. “500 章、数百套雅思”适合压力规划，不能替用户设为固定产品规模或容量上限。
3. 六条点读样本能提示 D1 BLOB 的风险，不能证明未来每条平均大小、点读率、词句比例和保存总量。
4. “单套雅思 130–250MB”等区间尚非完整正式任务测量。需要按音频格式、时长、实物文件和实际重试记录重算。
5. B2、HF、R2、GitHub、OCI 同时全部部署，会增加位置一致性与凭证依赖。目前没有足够理由要求全部启用。
6. 全历史教学范围与一次任务读入全部历史正文不同。保存全部来源资格，并按问题实际取用具体章节，可以同时成立。
7. 用户本轮明确临时页有生命周期，不能在“全量归档”中偷偷把临时页永久保存。

## 3. 永久保存具体指什么

| 数据 | 保存方式 | 更新规则 |
| --- | --- | --- |
| 正式日课正文、关联编码、译文、章节音频清单 | 永久文件与章节版本索引 | 新版本不覆盖旧正文；当前版本指针可以更新 |
| 雅思题目、刺激材料、参考答案、评分依据 | 永久版本文件与关系索引 | 题目修订保留旧版本，历史答卷仍引用当时版本 |
| 每次答卷、口语原声、模型分析过的 WAV | 永久文件与 attempt 索引 | 重新作答新建记录，不覆盖上次答案 |
| 每次模型返回、请求描述、解析结果、费用与错误 | 永久证据文件 | 同模型补听另起 call；重解析不覆盖原始返回 |
| 点词、点句、考官音频、听力片段与成品 | 永久文件 | 按生成描述复用，已有声音不因缓存淘汰而重新生成 |
| 学习备注、完成反馈、正式批改与疑问答复 | 当前视图加历史记录 | 有意义的修改保留旧值或历史版本 |
| 词典来源快照、提取材料、选词决定、重要创作过程文档 | 永久私有文件 | 保留来源 pin、版本和内容去向 |
| 临时测试页、临时复习页及其专属附件 | 48 小时 | 到期停止访问，随后可靠清理专属文件与引用 |
| 登录挑战、会话令牌、运行租约、网络缓冲 | 有效期内 | 正常过期与清理，不作为学习档案 |
| 手机缓存、边缘缓存、近期文件副本 | 可轮换 | 只允许删除副本，永久原件另有验证位置 |

“全部数据”在此解释为正式业务产物及其可追溯历史；不是永久保存每次空轮询、屏幕滚动事件、凭证或内存缓冲。

点读的永久保存单位是**实际生成的音频**。多次点击同一生成描述只新增必要使用关系，不重复生成或复制音频。未点过的词句不因永久保存目标而强制批量合成。

生产中的旧稿、用户交付过的测试反馈和既有正式研究材料不因后来的临时页规则自动删除。新增临时页专属资料则不得混入永久库。共享正式文件只解除临时页引用，不能随临时页删除其永久原件。

## 4. 分层应该怎样理解

| 层 | 放什么 | 访问方式 | 物理资源建议 |
| --- | --- | --- | --- |
| 业务关系与控制 | 章节目录、题目索引、答案状态、资产引用、任务锁、余额记录 | SQL 定点查询 | 保留现有主 D1 与练习 D1 |
| 当前正文与小型读取缓存 | 当前章节正文、适量结构化视图 | 直接读取，缓存失效可从原件恢复 | 现有 CHAPTERS KV 可渐进保留 |
| 近期媒体 | 新章节点读、当前雅思音频、近期原声 | 私有流式读取、Range | R2 Standard；作为原件或加速副本 |
| 永久文件基座 | 全历史正文、音频、答案、证据与重要中间文档 | 资产编号定位文件；历史也可随时取回 | HF 私有 Bucket/Dataset 候选，R2 可直接承担；B2/COS 可扩展 |
| 稳定材料 | 词典快照、提取库、已封存任务材料 | 按需取得指定文件或批次 | 与永久基座共享平台，适合 HF 私有 Dataset |
| 可选恢复备份 | 数据库导出、资产目录、文件校验清单与必要文件副本 | 恢复时读取 | 先做本地分批导出，其他载体另选 |

“近期”和“历史”是读取策略，“永久”是保留策略，“备份”是恢复策略，不能互相替代。同一个 HF 文件可以既是永久原件，也是低频历史材料；其 R2 副本可以随着复习重新成为近期文件。

不采用必须等待数小时解冻的归档存储作为 PWA 唯一历史音源。学习者应当仍能读旧章节、听旧声音。

## 5. 平台资源与适配结果

### 5.1 Cloudflare D1 / KV / R2

D1 继续承担关系数据。Free 单库 500MB、最多十库、账户合计 5GB；这些不是一个可以自动跨库 JOIN/事务的 5GB 数据库。现在不能因为未来预测就拆成很多库。[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)

R2 Standard 提供每月 10GB-month 免费存储及一定读写操作额度，超额存储 $0.015/GB-month，直接出站流量免费；Infrequent Access 有取回费用和最短存储要求，不适合本项目频繁轮换的近期层。[R2 价格](https://developers.cloudflare.com/r2/pricing/)

R2 Worker API 支持范围读取与流式 body，直接匹配 iPhone 播放需求。[Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)

Cloudflare 当前官方支付说明列明 UnionPay 和 Mastercard 等方式。**列明卡组织不等于已经验证用户这张银联储蓄卡能完成开通。** 此前本项目账户的 R2 API 返回未开通，需要实际控制台开通验证；本轮未操作。[支付方式](https://developers.cloudflare.com/billing/understand/faq/)

KV 留给低写小正文，不再保存新增批量媒体。近期 R2 的建议软预算是 8GB，为同账户其他资源、迁移和临时写入留余量；不是宣称任何情况下都零费用。

### 5.2 Hugging Face：免费大基座的优先验证候选

官方 Free 私有空间为 100GB，模型、Dataset、Bucket 等共享，不是每建一库再得 100GB。建议先用 80GB 作为本项目规划线，实际按账户总占用与增长率调整。[容量政策](https://huggingface.co/docs/hub/storage-limits)

选型区分：

- **Dataset**：适合词典快照和按批次封存的研究/课程材料，记录固定 commit 与路径。
- **Bucket**：更适合独立音频文件，S3 接口只适用于 Bucket，不适用于 Dataset。应用自己按摘要生成不可变键，避免依赖服务端历史版本。

Bucket 的 S3 兼容性有边界：GET 通常重定向至 CDN；不保存任意用户 metadata，不提供对象版本和生命周期等功能。摘要、访问范围、保留规则由本项目数据库维护。官方这页不足以证明我们的私有 Range 通路已经合格。[S3 兼容说明](https://huggingface.co/docs/hub/storage-buckets-s3)

因此 HF 可以成为正式永久基座候选，不必仅作备份。但在授权下载、Range、过期链接和真机播放验证前，不能删除仍可用的 R2/KV 原件。账户超额后也不能假设去重、开新仓库或组织能无限扩大免费空间。

### 5.3 Backblaze B2：便宜的永久容量扩展候选

当前主价格页列出 $6.95/TB/月；前 10GB 免费，按实际存量计量，不要求先购买整 TB。较旧帮助页仍有旧价格，应以当前账户和报价核对。[主价格页](https://www.backblaze.com/cloud-storage/pricing)

B2 的标准对象可直接读取且支持 Range；与 Cloudflare 的官方合作可减免符合条件的传输费。实际私人 Worker 通路仍应核实账户计费结果，不能把任何网络路径都算成免费。[GET Object](https://www.backblaze.com/apidocs/s3-get-object)、[Cloudflare 集成](https://www.backblaze.com/docs/cloud-storage-cloudflare-integrations)

目前没有本项目账户的实际充值/绑卡验证，也不能确认用户的银联储蓄卡、微信或支付宝被直接接受。因此它是**价格有优势、支付待验证**的候选，不作为唯一已确定永久原件仓。

### 5.4 腾讯 COS：国内通路候选

用户已有腾讯云账户，但语音评测套餐不会自动抵扣 COS。大陆标准存储示例为 0.118 元/GB/月，普通外网下行 0.5 元/GB，地区与套餐会改变报价。[价格页](https://buy.cloud.tencent.com/price/cos)

COS 到 Cloudflare 通常仍是外网流量，不等于腾讯内网免费传输。它适合 HF/B2 账户、支付或读取不合格时补位；目前尚未为本项目开通并验证。[流量说明](https://cloud.tencent.com/document/product/436/53863)

### 5.5 GitHub、OCI、Telegram

GitHub 保持代码、协议和必要版本清单的职责；私有目录可以索引其他存储的位置。多仓库能形成逻辑文件库，但不能由此推断音频容量与服务承诺无限增长，不将其设为主在线音频仓。

OCI 的 200GB 是启动卷与块卷共享额度，适合自建服务，不是托管对象存储的免费 200GB。Codex 可以配置维护它，但实例、系统、补丁、磁盘及恢复都成为额外依赖；官方也保留回收闲置免费实例的机制。本项目优先托管存储，不将 OCI 放进必须依赖的生产读取通路。[Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)

Telegram 可以讨论个人手动保存加密备份文件，但不能直接用 Bot 给 PWA 建外部云存储后台；Bot 开发者条款明确限制此用途。个人文件上传与 Bot 云盘方案不是同一项能力。无论放在哪里，备份必须能校验和恢复。[Bot 条款](https://telegram.org/tos/bot-developers)、[个人文件说明](https://telegram.org/faq)

## 6. 项目需要的统一资产目录

不让章节或答卷长期绑定某家服务的下载 URL。URL 会过期、换域名或暴露访问能力。业务引用的是 `asset_id`，后台再定位可用文件。

建议增量加入下列关系，字段名称为设计示意，不是本轮 SQL 迁移：

| 关系 | 主要字段 | 用途 |
| --- | --- | --- |
| assets | asset_id、sha256、bytes、mime、kind、created_at、retention | 文件的身份与保留类别 |
| asset_locations | asset_id、provider、namespace、key、revision、role、state、verified_at | 一个文件可以有永久原件、近期副本、备份或旧位置 |
| asset_refs | owner_type、owner_id、owner_revision、purpose、asset_id、expires_at | 章节、题目、答案、调用和临时页分别使用哪些文件 |
| artifact_revisions | artifact_id、revision、body_asset_id、previous_revision、created_at | 保留正文、反馈与重要工作文档版本 |
| generation_records | descriptor_hash、model、voice、parameters、asset_id、state、call_id | 相同生成描述复用既有结果 |
| history_events | entity、revision、event、payload_asset_id、created_at | 保留有意义的学习反馈与操作结果变更 |

统一目录建议放主 D1，练习 D1 保留现有题目、答卷、音频调用与评分关系。跨 D1 只是应用关联，不宣称 SQL 外键或事务能跨库。

文件摘要只负责同一字节文件的身份；声音复用还要匹配文本、模型、音色、速度、格式和协议版本。不能因为文本相同就把 Bella 音频当成男声使用。

同一录音用于四路分析，只保存一个原声及一个实际分析 WAV，每次调用引用它们并独立保存返回。两个内容相同但语义上独立的答卷仍然是两个业务记录，底层文件可以去重。

低频历史 JSON 和重要工作文档可以按任务封存为压缩批次，清单仍指向各原始成员与摘要。压缩可逆，不能以摘要报告替代原始返回，也不能为了合并文件而丢掉原始字节。活跃音频保持可独立范围读取，不强行塞进必须整包下载的巨大归档。

现有口语请求描述已经不重复 base64，应保持这种表示：精确文本、参数、音频摘要与文件关系可还原实际输入；不需要为“全量保存”增加四份冗余编码文件。原始响应按实际收到内容保留；Whisper binding 没有 HTTP envelope，不能补造一个。

## 7. 写入、发布与重新读取通路

### 写入与发布

1. Codex 或上传接口保留本地/暂存产物，计算文件摘要和大小。
2. 写入选定存储；网络返回不明确时，通过固定键和摘要核对，不重复生成付费声音。
3. 验证目标文件字节或可靠校验结果；对象 ETag 不一概等于 SHA-256。
4. 登记资产与验证位置，再提交业务索引，将章节、音频或反馈设为可用。
5. 更新当前视图和通知；任务末尾更新既有余额页。文件归档与存储占用一并记录，不每次浏览都查询云账单。

对象存储和两库不能做一个分布式事务，采用上述先文件、后发布的顺序。中途失败可能留下未关联文件，但不能让页面指向一个尚不存在的文件。确定已生成的音频写存储失败，应重传现存文件，而不是再次 TTS。

每日文字课程不因可选整章音频缺失被阻断；雅思听力的必需音频仍须完成再发布，沿用原产品要求。

### 用户点击播放

1. 保留当前 PWA API 形态，Worker 先鉴权并核对该章节/题目/答卷是否可访问。
2. 查询资产位置，优先读可用 R2 副本，否则读永久原件。
3. 转发正确 Range，并流式返回 `206/Content-Range`；HEAD 不下载整段原声，无效 Range 返回合适状态。
4. 永久原件命中而近期无副本时，可以启动一次补缓存；并发拖动不触发多次整文件复制。
5. 文件已有但存储暂时故障，展示加载或重取状态，不默默重新调用声音模型。

短点读可整文件读；长听力与原声必须流式读取，避免把历史仓储的低价格消耗在反复整文件下载上。

HF CDN 重定向由后台处理，只接受预期域名和协议；不能将私有源凭证转发到任意重定向目标，也不能将长期源凭证返回手机。

所有隐藏参考答案、原声与模型证据继续私有。缓存不能绕开现有鉴权或答案显式揭示条件；即使底层有文件，未揭示接口也不得返回参考答案。

## 8. 近期与历史轮换

R2 近期副本优先照顾当前学习章节、未完成练习、最近申请复习和近期作答。历史文件不会因日期变旧失去资产编号、章节关系和永久位置。

不设机械“超过 30 天删除全部音频”。依据近期层实际预算、当前任务、近用情况和文件大小选择副本；活跃听力套题可以临时保留完整音频，重要旧复习可以重新回热。

迁移顺序为：复制 → 摘要校验 → 登记新位置 → 验证后台读取 → 调整位置角色 → 删除可淘汰旧副本。没有已验证永久位置，就不能删最后一份文件。迁移失败不影响仍可用旧位置。

“转历史”不改变文本、音色、人物分配、答案或分析证据，不触发内容重生成。不把冷文件批量读入 Codex 上下文，只按资产索引取具体材料。

近期访问记录按必要的粗粒度/批次更新，避免每次播放进度、每个 Range 都永久写一次数据库。长期学习记录与加速缓存命中统计分开。

## 9. D1 容量与长期教学范围

2026-10-05 前序只读快照：主 D1 192KiB、练习 D1 484KiB，合计 676KiB；点读六条音频合计 188,616 bytes。正式音频长期规模尚未实测。本轮没有重新查询生产账户，也没有把这些历史快照冒充本轮新观测。

优先把 BLOB、完整模型证据和较大历史文档移到文件基座。D1 保留查找必要字段、摘要、答案关系和简短当前视图；可直接 SQL 查询的答案字段不因抽象分层被无理由全部搬走。

当某库按真实增长率预计会触限时，再选择升级或按完整练习套题分片。一个套题的题目、作答与评分关系尽可能在同一库内，主库记录其所在分片。不能简单按表拆库而破坏原子提交。

**雅思范围继续为第一章至当前章节，本章显著加权。** 容量优化不改成只教最近几章：

- 保留每次申请时的全历史来源资格与当时正文摘要。
- 使用关系化成员或不可变清单表示来源集合，避免每次在多个表重复大段 metadata。
- 出题时根据题目实际需要取得少量具体正文；任何旧章仍然有被取用资格。
- 出题范围快照与实际使用来源分开记录，历史可解释。

这是保存与读取方式调整，不能私自改变用户原有选词协议或雅思覆盖范围，也不要求本轮加 learner model 才能完成存储升级。

## 10. 容量公式与人民币对比

不能沿用“每套固定 18 份回答”或“每天自动朗读整章”的错误假设。计划占用应计算：

`正式正文版本 + 实际点读文件 + 听力成品/片段 + 考官音频 + 每次原始录音 + 实际分析 WAV + 各路返回/解析/请求描述 + 有价值工作文档 + 历史修订 + 实际保留副本`

已生成片段和合并成品如都要求留存，两项都计入；请求中引用既有 WAV 则不再加四份 base64。判断前先测正式任务文件清单，外部报告较大估计仅保留为压力情景。

## 11. 临时页与备份

临时页到期先禁止访问，再清理索引和独占文件；清理任务失败保留重试记录。不能仅删除目录而让带旧地址的文件仍对外可读。

永久备份默认排除临时页正文和专属附件，以免“到期销毁”变成从永久备份仍可找回。正式内容共享引用另算。基础数据库备份也应分离或排除临时正文、登录令牌；既有备份若含临时内容，需说明保留窗口与清理方式，不能宣称它已经彻底销毁。

用户将全项目容灾列为可选，因此本方案不强制增加第二家云的全量镜像。但建议保留轻量恢复能力：

- 按一个明确截点导出数据库、资产目录、清单和协议/schema 版本。
- 恢复清单包含文件摘要、位置和所需版本；导出期间产生的新事件可在下一批续入。
- 小型索引与唯一原声优先保留额外副本；大文件可以增量分批备份，避免每次重传全部项目。
- 存储凭证不写公开仓库或普通备份清单，恢复密钥单独保存。
- 抽查能恢复一个含旧版本、音频和作答的完整业务记录；“上传成功”不等于能恢复。

品牌可靠性降低硬件故障风险，不替我们恢复程序误删、账号丢失或错误覆盖。是否扩大到全量异地副本，可依真实规模与预算再决定。

## 12. 分阶段接入与必要验证

### 第一阶段：稳定接口和对象存储接入

在现有架构上增加资产目录、统一存储接口和流式读取；将新点读、原声和证据改为文件引用。历史 KV/BLOB 保持可读，迁移前不删除。保持现有 PWA 风格、声音路由和任务协议，不引入大型数据库重构。

已有代码存在 `PRACTICE_R2` 与 `SPEAKING_ASSETS` 两种接口，且 `practice-media.js` 配置 R2 后就优先只读 R2。实施时不能只加 binding 就切换所有旧读取：必须先建立位置记录或显式旧库回退，并保留点读 BLOB 旧读路径。生成描述和既有 id 保持稳定，否则升级本身会造成重复计费。

迁移采用增量字段与双读路径，新文件只写选定对象层，不把每次写入长期同时复制 KV。逐项校验完成后再切读和清理旧副本；回退仍能读取已迁到对象层的文件，而不是只能读取迁移前的 KV。

先验证 R2 实际开通与支付。若 HF 未准备好，小量文件可以先永久留在 R2，少量付费不比临时凑很多未经验证平台更糟。

### 第二阶段：验证免费大基座

HF 验证只需真实业务闭环：私有写入与摘要回读、Worker 下载重定向、正确 Range/拖动播放、过期链接重取、iPhone PWA 播放、批次上传后定位旧文件、临时专属文件删除。无需搭一整套形式化测试工程。

若 HF 只能完整下载而范围播放不合格，可用于稳定材料或封存证据；旧大音频不能依赖它直接快速播放。将其作为音频原件时必须有可接受的 R2 完整回填路径与冷启动等待体验，不合格则不承担该角色。

验证通过后渐进转入永久原件，R2 保留近期副本；不在尚未回读时一次性搬空旧库。

### 第三阶段：按实际增长扩展

HF 按剩余容量与增长速度提前安排新增落点；B2 先验证支付与私有读取再选。支付不通可继续 R2，或验证 COS。新增存储供应商只改变物理位置，不改变 asset_id 与历史教学关系。

额度不足不删除最后原件，不自动充值，不自动跨日重新生成。用户完成的上传/答题必须先可靠保存或明确告知尚未保存；后台任务保留已有文件与具体待完成步骤，延续既有用户明确恢复规则。

存储占用和预测随实际任务末尾发布记录，不能每次打开余额页触发收费查询。模型余额低于三次最大完整用户任务时的既有提醒规则保持；存储容量另按剩余空间与实际增长提醒，不与美元余额混为一项。
