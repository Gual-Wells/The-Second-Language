**关键事实：**最终纸面没有调用 v2 的 `ageSkin()`，没有保留 v3 的花饰，也没有保留 v4 那套折线相关的正文磨损。v6 的主要折痕网络大多在颜色原稿里；最终原始 v12 没有后来第五章 v14 的两道专用折痕几何。印章颜色、印模接触和压痕又是三种不同数据。

### 1.2 三种“深度”不能混为一谈

| 层次 | 第一章实际实现 | 不应声称的能力 |
| --- | --- | --- |
| 整张皮膜卷绕、边部回卷、轻微非均匀起伏 | Paperlab 卷绕映射；v5/v6 GPU 顶点形变；同函数计算法线与投影深度 | 不是材料标定的有限元、碰撞布料或实体羊皮扫描 |
| 细微皮面起伏 | v4 引入的 Leather Red 02 扫描 normal；v6 小幅复用 | 不是该纸胚每一条折痕、每一处污痕的实测高度 |
| 章印局部压痕 | v8+ 的独立线性灰度 relief，通过 bump 影响受光 | 不改变轮廓、不形成可测厚度，也不是完整压印力学 |

由此可知，新作品不能只换一张“看起来旧”的图，也不能把所有痕迹转换为位移。应先决定哪种痕迹属于颜色、微表面、压印还是实际形态，再让它们在同一件作品里协调。

## 3. 纸胚图像是怎样做出来的

### 3.1 原件谱系，而非一个从 v1 累积到 v12 的滤镜栈

```text
cron 社区纸纹 → v1 / v2（程序旧化试验）             [最终未沿用]

v3 独立生成无字正面 ── 编辑 → v3 反面               [花饰/双面差异后被替换]
       ↓ 编辑：去装饰、加强材料年龄、修单张连续轮廓
v4 纸胚
       ├─ 编辑：去掉所有水痕与脏斑 → v5 过净稿        [未作最终母材]
       └─ 编辑：重做手裁边与强旧化 → v6 候选一         [霉变读感，未采用]
                     ↓ 编辑：去菌落/黑斑，保留手工轮廓、折藏与年龄
                 v6 最终无字纸胚 → v7…v12 沿用
```

v3 的生图不是“一张完整手稿页面”，v4/v5/v6 的编辑也没有让模型画正式英文。素材以透明外缘无字皮膜进入代码，字迹、印迹、边画与动画保持可分工。**WebP 编码步骤未重画污斑、未锐化、未凭空补出纤维。**

### 3.3 各次图像修订的具体职责

**v3 → v4：**去掉花卉、藤叶、金/蓝/红装饰和双红线；连续皮膜不能有两侧成对横缺口而像三条拼片；中心可书写但应仍旧；水损/手持变色集中于暴露部与角部；折谷、薄损与擦磨有位置关系。图像编辑负责这些材料外观，不负责字迹。

**v4 → v5：**原提示实际要求移除全部 ring stains、tide marks、greasy patches 和烧边读感，转向干燥纤维、细折和薄损。这说明过净不是渲染器唯一责任，源稿本身也做了错误取舍。不能只调灯期待恢复已经从母材里删掉的年龄。

**v4 → v6 候选一 → 候选二：**同时处理整圈轮廓和年龄。最终保护的是：长段近直手裁边、少量不对称斜角/小缺尖、短裂口、局部浅缺损；不同位置的接触变色、浅淡旧潮线、折谷少量尘积与浅磨。明确排除均匀圆角、重复波浪边、整圈焦黑焦褐脆边、织物组织、黑点菌落与灰黑霉块。第二轮保留第一轮的轮廓和折藏网络，只去生物腐败读感，不能用“不要霉”把历史全部擦净。

**证据限制：**v6 候选一被拒绝的事实和编辑输入关系有日志；原件只说明保留在任务缓存，没有发现可固定 pin 的发布原件。本文不伪造其文件名、散列或逐像素测量。最有权威的已存结果是候选二 `source-art/charter.png` 及其提示词链。

### 3.4 年龄不是纹理噪声的数量

实际形成的标准是让痕迹可解释：制作痕、储藏折线、展开/卷起应力、反复手持、暴露端磨耗、偶发旧水损之间有差异。它没有要求皮膜每个角落都脏，也没有要求微痕均匀可见。旧痕在实际展示里应读得出来，近看有层次，远看仍是庄重而完整的文书，不能变成破布或一圈烧焦地图。

新作品需要重新设计它自己的这组关系。第一章成功的可迁移对象是**痕迹体系和修订能力**，不是那几块潮线的坐标。

## 4. normal / roughness 的真实来源与演变

### 4.1 最终来源：确实是扫描资源，但不是羊皮纸扫描

**VERIFIED：**v4 的 `.cache/scroll-v4-setup.mjs` 读取 Poly Haven `leather_red_02.json` 元数据，取 `nor_gl['1k'].jpg` 与 `Rough['1k'].jpg`，直接下载字节写到两张 `skin-*` 文件。没有在此脚本中从纸胚颜色生成法线或另行烘焙。脚本只属于当时本地制作证据，未假装它是 tracked 的正式构建入口；正式 manifest 同样保存了来源、用途与散列。

- 原作者/资产：Rob Tuytel，**Leather Red 02**。
- 官方资产页：[Poly Haven Leather Red 02](https://polyhaven.com/a/leather_red_02)。许可 CC0；本项目只取微结构通道，没有使用它的红色皮革 albedo 染整张纸。
- OpenGL normal 原文件：`https://dl.polyhaven.org/file/ph-assets/Textures/jpg/1k/leather_red_02/leather_red_02_nor_gl_1k.jpg`。
- roughness 原文件：`https://dl.polyhaven.org/file/ph-assets/Textures/jpg/1k/leather_red_02/leather_red_02_rough_1k.jpg`。
- `skin-normal.jpg`：1024×1024 RGB，1,033,319 字节；SHA256 `d0057cdbee5be6223b35f0a463441404144fcdae699f69ff610eec4d86d48970`。
- `skin-roughness.jpg`：1024×1024 灰度，879,217 字节；SHA256 `dd3b860a9510a44fd857c04e0c8cc63ea1f944c25abe9bdcbf844cc4a22c88d8`。

**LIMIT：**皮革扫描微结构只是受控艺术近似，不是已测得的羊皮纸 roughness、不是第一章纸胚同位置的 normal，也不是写着“羊皮”就具备对应真实性。它在这里的价值是小幅、独立且有实物微结构参照，避免以污斑亮暗制造强假凸起。新作品可以复用这种分层思路，资产是否合适仍要看实装，不应把这个单一资源奉为必选。

### 4.2 每代实际用什么

| 代际 | 高度/法线实际输入 | 幅度、采样和粗糙度 | 是否进入最终第一章 |
| --- | --- | --- | --- |
| v1 | 背面纸颜色图直接作 bump | `bumpScale=.022`，roughness .96 | 否；颜色中的污斑不是高度。 |
| v2 | 768×1056 独立程序 heightMap | 中性值 128，两个小幅正弦纤维、随机 ±1.5 灰阶、边部起伏；bumpScale .032 | 否；独立高度的思想有价值。v2 木轴的 Wood Table Worn normal/roughness 属于木件，不能误说已用于羊皮。 |
| v3 | 独立反面颜色图作 bump | .009，roughness .84，sheen .16 | 否；这是分层上的退步，不是一路单向进化。 |
| v4 | Leather Red 02 normal + roughness | RepeatWrapping，repeat `(1.4,2.1)`，normalScale .065；粗糙度 shader 为 `.86 + .12*g` | 两张源图进入最终链；较高幅度后来被下调。 |
| v5 | 同 v4 扫描文件 | normalScale .035；粗糙度 `.88 + .10*g`；sheen .06 | 小幅扫描及粗糙度公式保留，照明还需 v6 修正。 |
| v6→v12 | 同 v4 两张源图 | repeat仍1.4×2.1，normalScale仍.035；roughness 实际 .88–.98；sheen0、specularIntensity0 | 是。v8 另叠章印 relief，二者不是二选一。 |

normal/roughness 作为数据图不设 sRGB；正背面 CanvasTexture 设 sRGB。线性中性灰的 relief 也不是颜色图。粗糙度公式由 shader 重写，不能只读构造器 `.97` 就声称每处 roughness 都是 .97。

历史 v6 原提交直接写死 v4 两张材质路径；后来 `6f170a44e49111759e9c77afb5cbdf1c6acd9cd6` 为第五章加了 `template.paperNormal || oldMap` / `paperRoughness || oldMap` 扩展。**v12 模板不提供 override，所以第一章仍走旧扫描图。**第五章以及被否决项目使用纸图高频生成 map 的脚本，不能倒写成第一章原始制作方法。

### 4.3 不存在的“纸张多轮烘焙”

找到的第一章纸张实现是以上独立图像编辑、源图编码、扫描微通道复用、几何与 shader，不是几十张复杂程序烘焙层。v19 对皮革/金属的多程序材质烘焙属于后来扣具，不应算成第一章纸张从头到尾的历史工艺。也没有证据证明第一章把所有大折痕都做成了图像对齐的 displacement。

## 5. 真实纸膜、法线、深度与连续性怎样改革

### 5.1 卷绕来源与适用边界

采用 Noor Mtir 的 [Paperlab 固定版本](https://github.com/NourMtir0722/Paperlab/tree/41914833cb9ae12b32a8cbbdee4723f5b12158af)，Apache-2.0。原路径为 `packages/paperlab/src/deformers/roll.ts` 及 `behaviors/unroll.ts`；本项目移植为 `chapter-scroll/vendor/paperlab-roll.js`，保留许可/NOTICE，去掉 React/schema 依赖。

`rollRadius = sqrt(core² + woundLength * layerThickness / π)` 根据卷入长度变化；卷角使用逐渐减小半径和最小半径保护 `.08`。它是可逆、可计算的卷绕映射。不是给整页贴图做透视缩放，也不是仿真所有接触、摩擦和皮材弹性。

### 5.2 网格与运动的实际代际

| 阶段 | 纸膜/显示实现 | 收获与边界 |
| --- | --- | --- |
| v1/v2 | CPU 48×480 segments；23,569 顶点；每次改 position 后重算法线与包围球；正交镜头 | 动作真实来自同一张膜，性能开销随每帧 CPU 计算。v2 完全展开仍留 .20 世界单位在木轴附近，属于当时木轴方案。 |
| v3/v4 | CPU 40×300；12,341 顶点；普通轻起伏和末段 .055 高度小唇卷 | 不等于已实现长时间卷藏后的自然整体微卷。 |
| v5 | GPU 52×280；14,893 顶点；绕卷 + 上下不同宽度的残余卷曲 + 横纵非均匀波动；同函数有限差分法线与自定义深度材质 | 性能与几何表达进步；末段分支仍制造不连续。 |
| v6 | 保持同网格；残余位移在绕卷切线两侧共同计算，修最终一圈；纸不接收自身阴影，另用 .20 opacity 后方软阴影面 | 不用“把白线遮住”掩盖顶点断层。修正法线闪带根因。 |

v5/v6 残余卷曲的关键量：下边 `.56`、上边 `.37` 世界单位范围；曲率半径分别约 `.64+.07*sin(x*1.5)` 与 `.78+.09*cos(x*1.2)`；叠加 `.043` 与 `.024` 两尺度形变和边部 `.09+.038*sin(...)`。这些是艺术定向近似，不能当羊皮材料常数。法线取同一 `parchment(position±.001)` 的双向差分，深度 pass 也调用同一 `parchment()`，而不是表面弯了、阴影仍按平面算。

最终 nominal300×420mm 对应世界4.5×6.3，coreRadius .145，layerThickness .035。layerThickness 控制绕卷间距，**不是已有完整有限厚度侧壁网格的证明**。边缘主要由透明剪影 + alphaTest .55 定形；没有微破口实体断面、散射或真实膜厚测量。

### 5.3 白线并非“纹理接缝”

v5 把 residual rest displacement 放在已展开分支 `else`，又在 `.91→1` 强行恢复最终卷边，导致切线两侧高度不同。v6 改为两侧共享计算，切线过渡从 `smoothstep(0,.45,-s)` 改为 `smoothstep(-.12,.45,-s)`。

**HISTORICAL 实际验证：**`scripts/check-scroll-continuity-v6.mjs` 读取两版真实 GLSL，使用 WebGL2 transform feedback，而不是另写一个看似相同的 CPU 替身；7 个进度 `.90,.93,.95,.97,.98,.99,.995` × 5 个横向点，切线两侧各偏 `.00002`。最大间距由 **.3158236314** 降为 **.00004694585** 世界单位。后值不是数学零；采样本来就有非零间隔。历史还保存 `.91,.94,.97,.985,.995,1` 的实际末圈截图。

迁移的是“同一个形变定义驱动顶点、法线、深度，并在危险边界实际验证”的能力，不是逐字复用这一张纸的边卷振幅。所有大痕都应看原稿/几何是否合理分工；原版也不是每条画出来的折线都有一条完全对应的真实几何。

## 6. 墨层、旧墨、压痕如何逐步成立

### 6.1 真字体一直是基座，但墨工艺不是一次完成

Aboensis 原 OTF 来自 Tommi Syrjänen，SIL OFL 1.1，依据1430年代瑞典 Codex Aboensis 法律书及相近材料的中古草书。来源：[CTAN Aboensis](https://ctan.org/tex-archive/fonts/aboensis)，原文件 `https://mirrors.ctan.org/fonts/aboensis/Aboensis-Regular.otf`；SHA256 `0ad00fb94899b3a8277680377eb7270c5fb3ee73dd9fefbd6fb31d9f94c4707b`。本项目未修改字体，也不能把它冒称所有欧洲中古正式文书的唯一字形。

原 app 先实际 `FontFace.load()`、加入 `document.fonts` 并等字体 ready，再 `createDocument()`；真实 `measureText()`、行高和溢出分支控制内容。不能以现代 fallback 完成后仅报告“设置了 Aboensis”。

| 阶段 | 正文墨的具体处理 | 后来是否保留 |
| --- | --- | --- |
| v1 | 58px 正文、73px 行高；整行轻微深浅和 x±.9/y±.7 抖动；14,000 个墨层微擦点，alpha .08–.36，约.4–2.4×.3–1.9px | 分层/真实字形保留；不是最终 v12 仍有同数量/强度。 |
| v2 | 同类微擦点；纸上先铺 `.16 alpha`、blur1.1px 的暖色吸收，再铺清楚字芯 | 旧墨吸收试验；整层模糊后来被减弱/取消。 |
| v3 | 真实 wrap，63→46 自适应；`.22 alpha`、blur.7px 吸收 + .92 字芯 | 后来继续改革，不能把红字和花饰当最终标准。 |
| v4 | 10,000 小擦点；用 `creaseY=h*(.419+.047*x/w)` 让折线附近更强磨损；.12 alpha blur.6px 底扩散 + .94 字芯 | 折痕关联值得研究，但这是手工代理，未延续为最终统一规则。 |
| v5/v6 | 2048×2868；正文93→68；整行alpha `.94+.018*sin`；3,100 个 .6×.9px、alpha.10小擦点；去全局墨 blur | 清晰度改革保留，最终 v12 排版/微擦又换成其自身代码。 |
| v7/v8 | 新章印试验；v7 混入 Uncial 引发不一致，v8 恢复一致 Aboensis；加入独立印模/印痕 | 不能因章印是矢量就默认为风格成功。 |
| v12 | 标题146、正文106、落款66（必要时到60）；正文`#30251b`、rubric`#58372d`；2,300 个 .6×.8px、alpha.075 仅墨层微磨，按内容摘要固定 | 最终真实实现。没有重新加回 v2 所有 blur 或 v4 旧折线磨损。 |

这里微擦的作用是打破过分完美的数字边缘，不是让每个字残缺。很多擦点落在没有字的透明位置，数量不能解释为有同数量的可见损坏，更不是“做旧强度”质量分数。

### 6.2 印模、落墨与材料压痕分开

v8 先建立白色印模 `mask`，再生成受接触影响的墨，另给纸保存中性灰 relief。v9/v10/v12 逐步改进：

1. **模具**：非完美边线和少量固定划痕；不是整章随机变形。最终 v12 长方藏记在896方画布制作，轮廓8.5px，实际字宽测量限制620px；裁成784×360，再放到纸面330×152px。风格是小藏记，不能复制回早期大权威圆徽章。
2. **落墨接触**：最终用 v10 `transferMasks()`。百像素尺度 broad field、约3.5px grain、三个不等椭圆缺墨区、小量 pinholes；clamp .14–1。最终墨色约 RGB(19–24,13–16,8–10)，远深于 v9 的浅棕方案。具体变化保存在源码，不是完美墨图整体调低 alpha。
3. **浸晕**：在章印四周小幅扩散；先从 halo 减去原印模再叠墨芯，避免扩散把故意缺墨处重新填实。最终 halo blur2px、alpha.25。
4. **余墨**：独立 `ink-shoulder.png` 被转为密度 mask，最终斜置42×78px肩部，alpha.74；可以超出规整图案边界，避免“余墨只能沿章印线宽一圈”的贴图感。源资产由图像工具制作，代码负责其密度与合成，不是假称完全程序物理渗墨。
5. **纸上墨色**：`opticalInk()` 以墨密度乘性削弱原纸 RGB，并从局部纸色梯度取小幅接触修正。纸纹保留在印迹下，而不是盖一个不透明色块。它是视觉近似，不是铁胆墨反应或渗流化学模拟。
6. **压力**：最终 relief 全页中性128，印模以`#303030`、alpha.52、blur.7px形成浅压痕；依印模接触而非依最终缺墨去挖坑。压痕与墨的稀缺不是同一件事。

**最容易丢失的工程细节：**Three 原有 normal/bump 分支通常优先 normalMap。v8 不仅把 relief 赋给 bumpMap，还在 `normal_fragment_maps` 之后追加条件内的 `perturbNormalArb(... dHdxy_fwd() ...)`，让局部印压真的叠加到扫描微 normal。v8 bumpScale .0025，最终 v9/v12 为 .0045。只复制 `bumpMap=relief` 而漏掉 shader 合成，参数和资源看似齐全，实际印压却可能无效。

### 6.3 最终构图也参与了材料真实感

v12 的独立边画并未画满纸：原件 `river-margin.png`，以 `(255,915,300,900)`、opacity .82 进入底材；正文在 x652、宽1134 的另一区域，行高145，段间65，正文最低点须≤1920。章印位于较低左侧，身份信息另列。边画、真字、藏记与留白共同让纸像一件纪念手稿，而不是把有纹理的底当 UI 背景。

此处应学的是作品内部的层次协调与实际字形测量，不是每份新作都左边画一条、右边抄同版式。文书艺术和纪念性仍需新方案单独成立。

## 7. 为什么“高清”改革必须包含实际照明

### 7.1 v3/v4 的具体显示风险

v3 引入 MeshPhysicalMaterial，ACESFilmicToneMapping/exposure1.08、暖key2.8、冷fill.9、金色edge.7、sheen.16、环境强度.22；v4 虽降低 sheen并换扫描，仍继承这套显示。纸图已经带有图像层面的微受光，再叠较强光泽和色调映射，实际画面会变亮、变平或像漂亮新皮纸，导致细节在原图能看见而实装被洗掉。

环境文件是 Sergej Majboroda 的 [Studio Small 09](https://polyhaven.com/a/studio_small_09)，Poly Haven CC0；实际1k HDR 1,615,248字节，SHA256 `e7cfda5f4e98e623db12b8bfd0184e048488e4855d9c83e2751fb44a32e80c45`。Three HDRLoader r186 + PMREM 用于材料环境采样，不是把摄影棚背景照搬到页面。它是环境资源，不是纸张扫描的一部分。

### 7.2 v5 的分辨率改革没有修好源色保真

v5/v6 renderer.setPixelRatio(1)，手动按设备像素计算 draw buffer，并限定3,500,000像素避免双倍 DPR 与无界显存；纸面颜色纹理 anisotropy 上限8。v5取消正文整体 blur 并在 lab 选择器移除旧 drop-shadow CSS 合成滤镜。**drop-shadow 并不等于对整张图做 blur，不能误记为删除了一层整页高斯模糊。**

这些改善字形锐度与采样，不会恢复被清洗掉的源材质，也不会自动抑制高光。移动端几百万像素与 source 原生1060×1484是不同预算。历史截图/帧率来自模拟环境，不能宣称实体手机已保证某帧率。

### 7.3 v6 真正保住了原来的年龄痕迹

- NoToneMapping，exposure1；不再 ACES 重新分级已有纸图。
- 灯色改中性白；hemisphere .9 / ground`0xc5bfb1`，key2.4，front fill .35，back edge .12。
- sheen0、specularIntensity0、envMapIntensity .07；粗糙度仍由独立扫描压在.88–.98。
- 近正面处将最终照明颜色和原 diffuseColor 混合：权重 `.45*smoothstep(.65,.98,abs(normal.z))`；最大45%保护已烘入图像的材料信息，卷曲部保留动态明暗。
- 不让自身阴影把整张皮面打脏，改用后方独立软投影；并修正几何/法线白线。

这是为固定近正面、图像细节丰富的器物做的**实用保真取舍**，不是完整物理 PBR。其价值不是“关掉所有立体感”，也不是“越亮越清楚”，而是让可见擦伤、折谷、斑驳在照明后仍保留，并让弯曲轮廓继续受光。

### 7.4 历史 GPU 检查究竟证明了什么

`scripts/check-scroll-fidelity-v6.mjs` 不是拿两张导出的2D纸面自比：它读取 `exportDocument()` 与**实际渲染 `exportObject()`**，取展开内部相同 UV、相同物理面积的7×7平均，剔除墨边等高反差区。本轮读取的历史结果：

| 指标 | 历史值 | 解释 |
| --- | --- | --- |
| 有效样本 | 260 | 内部皮面，不覆盖每个边缘缺损 |
| 原图/渲染亮度均值 | 205.1718 / 206.9074 | 亮度增量约+1.7357，而不是大片漂白 |
| 局部对比标准差比 | 1.04536 | 宽尺度年龄色差没有被明显压平 |
| 配对亮度相关 | .979873 | 该取样范围内图案色差仍对应 |

阈值是sampleCount≥50、brightnessShift≤18、contrastRatio≥.8、correlation≥.94。代码仅约束正向过亮，**没有绝对亮度差或过暗阈值**；取样用世界平面近似投影，并非对完整变形面逐像素反投影。它不测每根纤维、真实粗糙度、艺术是否庄重，也不能直接覆盖后来透视镜头的 v12 或新作品。它真正迁移给后续的是“源图与实际渲染配对检查”的责任，不能原封不动复制数值就宣布新作品也通过。

当代项目脚本中将 `exportDocument()` 与冻结PNG比，能证明未重新排印/原件身份，**不能替代以上受光后保真检查**。两类检查都需要，各自说明自己证明什么。

### 应先完成的制作准备，尚未在本轮实施

1. 先写新作品自己的材料职责与创作目标，明确哪些公共技术保留，哪些纸面/边画/墨迹需要重新设计；不得把新主题贴在第一章胚上即宣告完成。
2. 建立无字新纸的原件、源像素、真实剪影、编辑分支及拒绝理由；需要年龄强度时先区分源稿被清空还是显示被洗掉。
3. 明确微表面来自扫描、程序或图像导出，各自局限；大折痕是否需要几何对齐另定，不能假设现有纹理自动产生对应空间结构。
4. 真字库完成纸面、章印与独立压痕后，先看整页平面，再看实际受光与卷曲；所有中间层保留以便定位问题。
5. 冻结经实际验收的原件及版本，再把技术步骤固化。冻结是保护作品，不是把失败方案变为不可讨论。

## 10. 尚未证明与不应再重复的误认

- 没有证据表明第一章最后是实物羊皮全通道扫描、真实厚度建模或化学旧化模拟；扫描皮革微纹理是近似，图像工具也参与了母材设计。
- 没有一份隐藏的纸张“数十道算法”可直接执行。确有多次材料编辑、失败回退、着色和几何改革，但应逐项指向真实源码；后代扣具工艺不能补写进纸张历史。
- v6原稿有许多绘制出来的细褶/折线，原始v12实际几何是公共残余卷曲，不是逐条测绘。后续作品要求对应结构时，应明确新增哪种能力，不声称原版已经有。
- v3正反面并非逐像素互逆；v4以后正背共用纸材解决了剪影匹配，但没有模拟真实羊皮肉面/毛面的全部不同。
- 高resolution、固定hash、无404、无越界、2D导出一致、GPU保真、开合连续、内容与艺术审阅，各证明不同事情，不能互相替代。
- 本轮未跑任何生成或GPU，未产生新的可验收纸张；只有可核的流程重建。后续新作品须经它自己的真实材料、受光和整件审阅，不能借第一章的成功或第五章的工程沿用取得批准。

**重建结论：**第一章的可贵成果不是一张应当复印的“合格旧纸”，而是形成了一条肯承认失败、能对材料各层分别动手、能把图稿与实装差异查清并实际修正的制作链。新的作品要继承这条能力链，在它自己的材料与纪念主题上重新完成，而不是只拿到一张相似参考图就跳到装配。
