### 第二语言项目：词源权威化的系统性资源研究

研究时间：2026 年 10 月 15 日｜研究对象：英语词源学、历史词典、结构化词源数据库及数字化授权

#### 一、初步结论：确实存在值得引入的成熟权威体系

经过第一轮资料核查，我认为，**词源权威化有可能成为第二语言项目一次真正有价值的内容升级，而且不需要让 AI 承担词源知识的原创生产。**

目前已发现四条有实质价值的资源路线：

1. **大型历史词典路线**：以 Oxford English Dictionary（OED）为代表，拥有数十万词条及长期积累的语源考证。
2. **专业词源词典路线**：以 Chambers、Barnhart、Klein 和 Etymonline 为代表，重点不是现代释义，而是词汇形成、历史演变、语言借入与意义变化。
3. **商业结构化词典路线**：Oxford Dictionaries API、Merriam-Webster API 可以直接提供经过词典编纂的词源数据。
4. **开放大规模数据库路线**：Wiktionary 及其结构化提取项目，允许不依赖 AI 生成词源说明，直接处理已有的语言学条目。

这里已经出现一个非常重要的区别：

**有权查阅一本权威词源词典，不等于有权把它的数万条词源内容批量提取、永久储存并纳入 PWA。**

例如 Oxford Dictionaries API 确实提供词源字段，而且英语数据集规模超过 35 万词条；但其普通授权明确限制缓存、系统性提取及与 AI 工具结合使用。对于第二语言项目的 Codex 自动生产、OneDrive 永久归档流程，这会构成实际障碍。

因此，本次研究需要同时判断两个不同目标：

- **权威参考体系**：确保词源内容的可靠性、可核查性。
- **可持续生产体系**：确保日后数万词条的覆盖、更新和归档有稳定合法的数据来源。

我还检查了你目前的 The-Second-Language 仓库。现行日课已要求逐词完整查阅 Collins 和 Oxford、保存工作材料、核查语义覆盖，每章 40 个主词，且存在不可变版本与永久储存机制。

这意味着新增词源模块最好采用**独立的、来源可追溯的事实数据层**，而不是重新让 Codex 为每个词临场撰写一篇词源说明。

目前又找到两类很关键的候选：一部由 OED 核心编纂者主持、覆盖约 3.8 万词的《牛津英语词源词典》，以及一套包含 13 万余词头、可以下载 XML 的历史词典数据。前者权威性强，后者工程化很方便，但两者的数字版权和学术年代问题完全不同。我正在进一步筛选哪些可以作为正式教材事实源，哪些只能作为辅助核查。

#### 二、重点候选资源：规模、权威性与实际可用性

我将候选资源分成两组：**具有专业编纂权威的词典**，以及**能够真正作为大规模数据基础的资源**。两组有交集，但并不重合。

##### A. 学术与专业词典

| 资源 | 已核实的规模 | 主要优势 | 获取方式 |
|---|---|---|---|
| Oxford English Dictionary（OED） | 超过 50 万词与短语 | 历史英语、词源、义项演变、最早书证；持续修订 | 在线订阅，通常通过机构访问 |
| The Oxford Dictionary of English Etymology | 约 24,000 个主词条，实际涉及 38,000 个词 | 专门编纂词源，首见年代、早期拼写、同源词、语义历史 | 纸质词典 |
| Chambers Dictionary of Etymology | 超过 30,000 词条 | 专业词源研究、借词路径、语义变化，阅读友好 | 纸质词典 |
| Shorter Oxford English Dictionary | 超过 60 万词、短语和释义的合计规模 | 在两卷内浓缩 OED 的历史语言资料 | 纸质词典 |
| Online Etymology Dictionary | 数万条词源；第三方历史提取曾达约 46,840 条 | 高度聚焦词源、形成过程与词义演变，免费在线查阅 | 网站 |

这里的“50 万”“60 万”等采用出版商自己的统计口径，词条、词形、短语和释义不完全相同，不能直接当作可导入词源记录数。

OED 的数量及其持续更新由牛津大学出版社确认；其 2026 年 9 月仍有新增和修订。专业《牛津英语词源词典》的 24,000/38,000 两级统计、Chambers 的 30,000 余条、Shorter Oxford 的综合规模，均有出版商记录。

**The Oxford Dictionary of English Etymology**

这本是我最建议专门考察的纸质词源书。它不是简单列出拉丁、希腊词根，而是以词的历史证据为组织原则，追踪进入英语的时间、词义演变和相关语言形式。

1966 年出版，资料编纂权威，但部分历史词源结论需要与新版 OED 对照。

**Chambers Dictionary of Etymology**

这是另一部值得长期使用的大型专业词源书。1999 年 Chambers 版本与 1988 年 Barnhart 词源词典有直接编纂渊源，**不能当作两个完全独立的证据源来重复计数**。

其价值在于与 Oxford 系列采用不同的编纂组织，可以辅助审阅疑难词源。

另外，Etymonline 也值得高度重视。编纂者 Douglas Harper 列出了 Barnhart、Beekes、de Vaan 等专业词源学资料作为主要参考。它非常适合阅读与问题定位，但我没有发现足以支持整库合法下载、永久存储并重新发布的官方许可。网上有第三方提取版，**其存在不能替代原作者授权**。

##### B. 真正可以规模化处理的电子数据

| 资源 | 数据规模 | 电子化成熟度 | 核心限制 |
|---|---|---|---|
| Oxford Dictionaries API | 超过 35 万英语词条的词典数据集 | 官方 API，直接提供 `etymologies` 字段 | 普通许可不允许所需的系统性复制、长期缓存或 AI 结合使用 |
| Merriam-Webster Collegiate API | 超过 25 万条释义，并提供词源 | 官方结构化 API | 免费条款限制自动化查询，批量接入须获得书面授权 |
| Wiktionary / Kaikki | Wiktionary 2026 年 10 月统计约 139.6 万英语条目 | 可下载 JSONL，直接提取词源字段 | 众包编纂，不能直接等同于学术权威 |
| GCIDE XML | 131,566 个词头 | 完整 XML 数据包，含 `<ety>` 词源标记 | 主要来源于 1913 年 Webster，研究结论较旧 |

Oxford API 的词源字段支持英式、美式英语，但官方明确区分它与完整的 OED。Merriam-Webster 的数量指释义，而非 25 万条独立词源。Wiktionary 的统计包含大量屈折词形，并不意味着 139.6 万条都有独立词源考证。GCIDE 的 XML、规模和历史来源均能直接核实。

#### 三、电子资源的真正突破口：Wiktionary 的结构化词源层

Wiktionary / Kaikki

139.6 万：英语条目，含词形

71.9 万：具有实义释义的英语条目

数据来自 Wiktionary 2026 年 10 月 1 日统计，不代表拥有词源的条目数量。

这是调查中工程可行性最突出的发现。

Wiktextract 项目已经把 Wiktionary 的词源结构转换为机器可读字段，例如：

```json
{
  "word": "example",
  "lang_code": "en",
  "pos": "noun",
  "etymology_text": "...",
  "etymology_templates": [],
  "etymology_links": []
}
```

其 `etymology_text` 是从原有词典词源章节提取的文字，`etymology_templates` 和 `etymology_links` 能进一步保留来源语言、构词关系等结构线索，**这不是 AI 现场生成的词源解释**。

Kaikki 官方原始数据下载页提供 JSONL 和压缩包，可在本地进行确定性提取。完整英语版 Wiktionary 的多语言数据压缩包约 2.8 GB；只取英语词条会缩小处理范围。

它的意义是可以把工作方式改成：

权威或既有词典资料 → 可重复执行的数据提取与词形匹配 → 权威交叉核对与疑难词源审阅 → 第二语言项目的词源资料层

然而，必须对这条路线作出精确限定：

**Wiktionary 能解决大规模数据来源问题，但不能单凭其众包身份解决最终学术权威问题。**

部分词条的词源极其优秀，也有引用专业语源学文献的完整研究；另一些词条则可能只有一两句、缺少充分引证、处于争议之中，或者根本没有词源。

它适合作为**大规模事实候选库和词源结构索引**。若最终教材希望展示的是“权威核验词源”，还需要独立的确认机制。

#### 四、两个容易被忽略的障碍

##### 1. 大型官方 API 不一定允许你的自动化生产方式

这次查到了非常明确的条款。

- Oxford Dictionaries API 普通协议对系统性复制、使用自动程序获取数据、与 AI 工具结合、离线保存等均有限制。可通过 Enterprise 或特别约定讨论授权，但不能默认购买普通套餐即可长期缓存全文。
- Merriam-Webster API 虽然对符合条件的非商业应用提供免费额度，却明确要求：**自动化或预录查询必须事先取得书面许可**。因此不能直接将其接入每日 Codex 定时任务。
- Wiktionary 允许按照 CC BY-SA 等许可复制、修改和再发布，但必须遵守署名、相同方式共享等要求。第二语言项目既有的专有协议不应直接覆盖这部分第三方资料。
- GCIDE XML 使用 GPL 授权，而且历史词源可能过时。它可以成为独立的辅助数据集，但要分别处理授权和正确性问题。

所以，合法查看、程序访问、批量复制、永久保存、面向用户展示，是五项需要分别确认的权利。

##### 2. 词源不能机械地等同于词根拆分

对于第二语言项目，这一点可能比选哪本词典更重要。

**词源学研究的是一个词如何形成、流传并改变意义，而不是单纯寻找可以拆开的字母组件。**

| 词源关系 | 教学含义 |
|---|---|
| 继承词（inherited） | 从古英语等祖先语言沿袭而来 |
| 借入词（borrowed） | 从法语、拉丁语等语言传入英语 |
| 派生词（derived） | 在英语内部通过词缀或构词方式形成 |
| 新古典构词（neoclassical formation） | 利用古典语言成分在较晚时期造词 |
| 同源词（cognate） | 具有共同语言祖先，但不一定是借词关系 |
| 民间词源（folk etymology） | 语言使用者重新解释、改变词形或意义的现象 |

同一个拼写还可能有多个互不相关的历史来源，比如 *bank* 的不同词义。这种情况下，如果程序只按 `word="bank"` 合并词源，就可能错误归因。

真正高质量的实现应该以**词条身份、同形异源词、来源证据以及不确定性**为核心，而不是按表面词形做一次字符串匹配。

#### 五、我建议第二语言采用的技术与内容方案

对于现在的项目，我倾向于将词源独立为一个第四种知识对象，而不是直接往每日第一部分追加未经核实的文本。

现有 Collins/Oxford 主导的释义组织可以保留，新增一个随词条关联的词源证据层。

```json
{
  "lemma": "example",
  "homograph_id": "...",
  "source": {
    "name": "...",
    "edition": "...",
    "entry_id": "...",
    "revision": "...",
    "url_or_page": "..."
  },
  "origin_chain": [],
  "formation_type": "...",
  "semantic_history": [],
  "uncertainty": "...",
  "verification": "unverified",
  "license": "..."
}
```

其中最重要的是 `verification`。我建议至少区分：

| 等级 | 实际含义 | 能否称为权威核验 |
|---|---|---|
| A | 经新版 OED 或其他专业编纂资料直接核验，证据定位完整 | 可以 |
| B | 经专业出版词源词典核验，但版本较旧或仍有争议 | 附带限定 |
| C | 仅存在于 Wiktionary 或历史开放数据库 | 不可以 |
| U | 来源冲突、词源未知或无法可靠匹配 | 不可以 |

这个分级不是说 Wiktionary 条目天然错误，而是把**数据可获取性与学术认证**严格分离。

对 Codex 的约束也可以非常明确：它可以负责导入、索引、词形关联、差异提示、版本追踪与展示编排；但不能创造一条原始词源事实，更不能因为两份资料表达类似就自行声称已完成学术核验。需要翻译的内容也应与原始证据分离，明确翻译不是新的词源学结论。

#### 六、实际应该先做什么

我不建议马上重构日课，也不建议先购买大量词典。

更有效的第一项实验是：**以完整 VIX 词池作为目标集合，对大型可获取数据源做一次覆盖率审计。**

需要产出几个具体数字：多少词能找到明确词源、多少只有机械构词说明、多少有多个不同词源、多少完全缺失；再从各组抽取代表性词条，用 OED、Onions、Chambers 等专业来源做质量复核。

这样才能回答一个比“这本书有多少词条”更有价值的问题：

**哪一套来源实际覆盖了你需要学习的词，并且其词源知识足够可靠？**

#### 七、最终筛选与推荐

**第一优先：OED + Onions《牛津英语词源词典》**

作为学术标准与长期核验依据。前者内容持续更新且覆盖大，后者是一部真正专攻词源的完整纸质工具书。这组适合决定什么内容可以正式标为可信词源。

**第二优先：Wiktionary / Wiktextract**

作为规模化电子数据基础，最值得立即做技术可行性验证。它允许避免 AI 批量编造，却还需要处理编纂质量和开放许可。

**第三优先：Chambers / Barnhart + Etymonline**

适合进行专业补充与疑难词交叉核对。不同文本不一定代表完全独立的学术证据，要注意它们之间的资料继承关系。

**第四优先：GCIDE 及历史公共领域词典**

可用于补全旧词、观察历史记录和构建可离线的数据索引，但不应以百年前的语源解释压过现代研究。

我的阶段性判断是：

**词源权威化值得做，而且很可能提升整个第二语言项目的知识深度。但它不应该以“让 AI 把英语词汇都解释一遍”的方式建设，而应当被看作一项小型历史词典数据工程。**

目前的资源生态已经足够支撑大规模词源检索、离线索引和逐条来源追溯；尚未找到的是一种同时满足**现代学术权威、全量机器可读、自动化处理许可、低成本永久储存**这四个条件的单一数据产品。

因此，真正值得继续深入的并非再搜一批词根书，而是两件事：**调查专业词源数据库是否提供适用于个人教育系统的正式数据授权，以及实测 Wiktionary 结构化词源对完整 VIX 词池的覆盖与可靠程度。**

这两项如果成立，词源就可以从附加知识演化为第二语言项目长期稳定的、可核查的语言历史知识层。

## A2｜助手研究回复（原回复由两个可见段落组成）

我会把它当作第二语言项目的一项正式产品能力来研究，而不只是加一个“让 Codex 评价本章”的按钮。先核对现有章节生成、测试、答疑、任务队列和存储机制，再设计可申请、可复核、可追溯、能给出合格认证的质检体系，并重点研究怎样避免模型自评自证。

### 第二语言项目：章节质检与质量认证体系研究

**我的结论是：值得增加，而且应当成为正式日课生产闭环中的一个独立监督系统。**

它不应该只是让 Codex 评价“这篇文章写得好不好”，而应该形成一个真正具有审计价值的流程：

**用户申请质检 → 锁定章节版本 → 独立审查 → 出具逐项证据 → 判定合格或不合格 → 永久保存质检报告。**

这里的认证对象是**教材章节的生产质量**，不是学习者对章节内容的掌握程度，也不是现有的章节测试满分认证。

#### 一、为什么现有项目特别适合做这个功能？

我核对了当前 The-Second-Language 仓库中的正式协议。

目前项目已经具备很多必要基础：

| 现有能力 | 对质检功能的意义 |
|---|---|
| 每章 40 个主词，三部分完整课程 | 有明确的质检对象 |
| Collins + Oxford 逐词内容交接 | 可以审计义项、派生、例句是否遗漏 |
| `WORD`、`USE`、`SENTENCE` 编码 | 可以精确定位问题 |
| 正式章节按摘要固定版本 | 质检结果可以绑定不可变内容 |
| 本机 Codex 异步任务 | 可以复用现有领取、处理和回推基础设施 |
| D1 + OneDrive 永久存储 | 可以保存质检状态、报告和审查证据 |
| 章节修订保留历史版本 | 可以比较修复前后的质量变化 |

这些能力分别存在于现有的 `QUALITY_WORKFLOW.md`、`ANNOTATIONS.md`、`CHAPTER_QUESTIONS.md`、`CHAPTER_TESTS.md` 和 `STORAGE.md` 中。

但有一处关键缺口。

**目前的章节质量审阅属于生产流程内部自检，而不是独立的发布后质量认证。**

当前协议要求 Codex 发布前核实 Collins/Oxford 内容去向、检查第三部分的实际用法覆盖、检查译文和文章自然度。不过，这并不等于已经建立了一份独立审计报告。打包程序也只能证明结构一致，不能证明教材语义正确。

你提出的功能恰好可以补齐这项缺口。

我建议把它定义为：

**Chapter Quality Assurance（CQA）——章节质量审计与版本化合格认证。**

发现一个决定性工程问题：现有答疑/测试 Worker 交给 Codex 的主要是固定版本章节全文，不是完整 Collins、Oxford 原词条和逐词生产记录。因此它能够检查正文内部是否自洽，却**不能仅凭章节正文就认证“已完整、正确地覆盖两本词典”**。正式质检必须增加来源证据交接，否则评分看似完整，实际上最核心的教材保真无法证明。

#### 二、质检最重要的设计原则：不是给分，而是发现真实缺陷

如果 Codex 只是重新阅读章节，再输出“内容优秀，评分 96/100”，那么这个功能的价值很有限。

原因是大模型自身并不是稳定、独立的评分仪器。

2026 年关于 LLM 自我偏好偏差的研究表明，即使使用逐项、相对客观的评分标准，模型在评价自身或同家族模型的输出时，仍可能错误地判定不满足的标准已经满足。

NIST AI 风险管理框架也强调：评价应记录具体指标、测试方法和证据，并适当引入独立评估。

因此，我建议质检体系遵循三个原则：

**证据先于评分，逐项审查先于总体评价，硬性缺陷优先于加权总分。**

#### 三、具体应该检查什么？

针对你现有的三部分日课，我建议建立五大质检维度。

以下权重是项目设计建议，不是行业标准，正式采用前应通过实测校准。

| 项目 | 权重 | 检查方向 |
|---|---:|---|
| 教材来源忠实度与完整性 | 30 | Collins / Oxford 全量义项、派生、交叉引用、原始例句的正确去向 |
| 英语语义与用法正确性 | 25 | 语法、搭配、音标、语域、词性、细微义项区别、语境适用性 |
| 三部分教学覆盖与对应 | 20 | 第一部分定义、第二部分例句、第三部分实际用法的一致性 |
| 中文译文与教学表达 | 15 | 释义准确、译文自然、跨句指代正确、解释可理解 |
| 长篇文章的整体品质 | 10 | 叙事或论证连贯、文体自然、用法融入合理、语言表现力 |

不过，这五项不能全靠相同的方法检查。

| 质检对象 | 应采用的检查方式 |
|---|---|
| 40 词、编码、顺序、译文配对 | 确定性程序，全量检查 |
| Oxford/Collins 内容遗漏 | 原词条与章节逐项语义对照 |
| 例句是否真的体现目标义项 | Codex 按 `USE` 逐项审查 |
| 第三部分文章质量 | 全文阅读、上下文连续性审阅 |
| 信息来源与版权 | 来源清单、版本、许可与证据核验 |

还有一个非常重要的设计约束：你的课程协议已经明确接受“为了覆盖全部用法而存在适度教学编排感”。因此，质检不能把第三部分略显密集地使用目标词视为天然缺陷，也不能强迫文章变成某种固定的朴素风格。

应该检查的是**语言是否成立、结构是否连贯、作品是否具有艺术或表达价值**，而不是检查它是否符合模型个人的文风偏好。

#### 四、比评分更重要的是缺陷严重程度

我建议将发现的问题分为四类：

| 级别 | 问题示例 | 对合格认证的影响 |
|---|---|---|
| P0 致命 | 把一个义项解释成相反含义；伪造权威来源；系统性错误用法 | 直接不合格 |
| P1 重大 | 漏掉应覆盖的义项；错误语域教学；`USE` 标记与真实用法明显不符 | 不合格，需修订 |
| P2 一般 | 个别译文不自然、说明不够清晰、表达有明显可改进之处 | 扣分，通常不直接否决 |
| P3 建议 | 更好的措辞、文章结构或文学性优化空间 | 作为建议，不自动视为缺陷 |

这个分类还要包含“证据不足”的情形。一个无法核实的词源或双教材记录，不应该被模型想象成 P2，也不应该无根据地判为 P0，而应该进入待核验状态。

##### 建议的认证判定

**章节质量合格**：证据齐全、全部规定审查完成，没有尚未解决的 P0/P1，且达到经实测校准的质量门槛。

**章节质量未达标**：发现有证据支持的重大内容缺陷，或分项质量未达到合格要求。

**待核验**：原词典不可用、审查未覆盖完整内容、重要来源存在争议，或尚无法得出可靠判定。

可以暂时考虑总分 90 以上作为合格候选线，但不应立即把它写成正式权威规则。应先用人工确认的错误与优质章节样本测试评分是否稳定、能否区分真正严重的质量差异。

尤其应当允许一种情况：

**一个章节得了 96 分，但其中有一个确定的 P0 错误，那么依旧不能取得合格认证。**

总分描述的是综合质量，认证证明的是满足一组必要条件。这两件事不能混淆。

#### 五、如何让 Codex 真正具备质检能力？

我建议将一次申请拆成五个可恢复的阶段，而不是一次巨大的提示词调用。

1. **建立质检快照**。冻结章节 digest、对应 VIX/教材输入版本、来源文件摘要、使用的质检协议版本及实际可用的原始材料。先确定什么可以核验，什么不能核验。
2. **确定性结构审计**。运行既有章节解析和验证能力，检查 40 个主词、`USE` 覆盖、三部分映射、例句、逐句译文、无效关联和缺失编码。结构错误立即形成定位明确的证据。
3. **逐词语义审计**。对 40 个主词分别对照 Collins、Oxford 和生产交接记录。检查所有真实相关义项、标签、派生、短语、例句有没有准确进入课程。每个词保存单独审核结果。
4. **跨部分与全文审计**。逐项判断第三部分是否真实使用目标义项，然后整体阅读长文，检查表达、语义连贯、文体、译文和教学价值。不能把一个单词在文章中出现过就当作完成了全部用法覆盖。
5. **反证复核与报告签发**。对已发现的疑点进行第二轮针对性复核，查找遗漏与相互矛盾的结论。最终由确定性程序核对证据完整性、严重缺陷和判定条件，再生成不可变报告。

这里尤其不应将多次调用同一个 Codex 模型冒充真正独立的专家共识。隔离审查上下文、采用反证式提示、对照权威材料，都有助于降低偏差，但它们仍不能完全消除模型误判。

建议**模型负责理解和判断，程序负责证明它实际检查了哪些对象、依据是什么，以及判定条件是否满足**。

#### 六、每一项质检结果都应该可以定位、反驳和复查

推荐采用下面这样的结构化缺陷记录：

```json
{
  "severity": "P1",
  "category": "usage_mismatch",
  "location": {
    "word": "example",
    "useId": "U027",
    "sentenceId": "S113"
  },
  "claim": "该句未正确体现指定义项",
  "chapterEvidence": "...",
  "sourceEvidence": {
    "sourceId": "...",
    "entryId": "...",
    "locator": "..."
  },
  "reason": "...",
  "suggestedAction": "...",
  "verification": "reviewed"
}
```

这只是结构设计示意，不是实际检查结果。

报告的价值在于能从缺陷跳转到章节中的准确句子，并根据来源定位复查，必要时申诉或纠正错误质检结论。

建议保存来源的定位、摘要和允许保留的证据片段；对有版权的词典全文，不应为了审计而默认建立一份可以在前端分发的复制数据库。

技术上可以参考 W3C PROV 关于数字实体、执行活动、责任主体和来源之间关系的建模方式，但无需照搬复杂的本体系统。

#### 七、页面应该是什么样？

#### 八、如何接入当前的 Codex 任务队列？

现在已经有一条相当适合复用的基础设施：

实际检查的实现：`question-worker.mjs`、`questions.js`、`chapter-tests.js`。

现有系统每分钟进行轻量队列检查，任务需要时才启动 Codex；有五分钟租约和心跳机制，任务失败后等待用户明确重试。

新增 CQA 不必重新造一个调度系统，但需要扩展一种真正独立的任务类型。

| 层级 | 推荐实现 |
|---|---|
| 前端 | `质检申请`、状态查询、结果阅读、历史报告 |
| API | 独立 `/api/chapter-quality` 业务接口 |
| D1 | 申请身份、章节 digest、审计策略、进度、结果摘要 |
| OneDrive | 完整质检报告、逐词结果、执行证据 |
| 本机 Codex | 独立只读审计任务，分阶段保存检查结果 |
| 队列 | 复用现有领取器，保留任务公平性 |
| 额度与归档 | 沿用已有 BALANCES、STORAGE 规则 |

由于完整章节可能拥有大量义项和跨段落用法，CQA 不能因为一个大模型调用中断就丢弃全部审查。应以逐词结果和审核阶段作为持久检查点，在完成后再做全局汇总。

申请端的去重和版本控制也非常重要：网络重发必须使用同一申请编号；如果用户明确要求第二次完整复审，可以建立新的审核记录，但应清楚提示这是一次新的 Codex 工作。

最关键的是，**不要让质检直接进入自动修订循环**。

首次实现只负责发现和证明问题，用户查看报告后再决定是否修订章节。修订产生新的 digest，之后才能进行新版本认证。这样能够避免 Codex 为了消除报告中的错误而随意改动已有教学内容，甚至破坏原本正确的义项。

#### 九、词源权威化以后，质检还能继续扩展

这与你上一条提出的词源权威化其实可以形成很好的配合。

我建议将完整的章节质量分成几个相互独立的审核范围：

| 质检范围 | 认证内容 | 启用建议 |
|---|---|---|
| 教材正文 CQA | 释义、用法、例句、译文、文章 | 优先实现 |
| 词源审核 EQA | 词源出处、历史演变、构词关系及证据真实性 | 词源资源确定后启用 |
| 测试审核 TQA | 题目是否无歧义、标准答案是否正确、是否真实考理解 | 单独设计 |
| 朗读审核 AQA | 发音、停顿、对应文本、声音缺损 | 单独设计 |

原因是你的正式章节测试是在章节发布之后独立随机生成的，朗读资产也有自身版本与生成身份。不能因为正文通过了质检，就让后来生成的试卷、音频自动获得相同认证。

词源部分更加特殊：AI 可以审计“词源说明有没有准确引用可靠资料”，但不能根据其自身常识认定一段未经考证的词源就是真实历史。

这会使后续项目形成两个非常清楚的认证方向：

- 学习者的章节认证：证明个人完成了一次符合要求的理解测试。
- 教材本身的质量认证：证明指定版本经过项目定义的可追溯质检流程。

二者完全可以独立存在，不需要互相绑定。

#### 十、是否值得实现？我建议按三个阶段推进

**阶段 A：离线质检样本实验**

先不改线上页面，拿几章实际日课建立质量审计程序，对照现有 Collins/Oxford 和逐词工作记录，检验是否能真正识别教材遗漏、语义错配及虚假的 `USE` 覆盖。再人为植入已知缺陷，观察误报和漏报。

**阶段 B：正式质检申请闭环**

在阅读器加入申请和报告，接入队列、永久存储、章节 digest 与完整证据。合格规则由实测结果确定，报告区分缺陷、建议和待核验内容。

**阶段 C：扩展其他资产的质量认证**

随着词源、章节测试和音频成熟，再增加对应的独立质检范围。最终形成一套可以跨版本回溯的课程质量档案。

#### 我的最终判断

你这个提议的潜在价值，比再单独扩展几个学习功能更大。

当前第二语言项目的内容生产机制已经相当完整，问题不再只是如何高效率生成足够丰富的教材，而是如何**长期证明生成的教材值得信任**。

正式 CQA 能够解决三个问题：让生成缺陷有机会在实际使用后被系统性发现；让用户不必亲自检查所有英语知识；让历史课程随着审查和修订逐渐积累可复核的质量记录。

但我不建议一开始就推出“96 分、S 级、权威认证”这样的漂亮结果。应该先证明质检机制能稳定发现真正的错误，并且不会因为文章风格、复杂义项或者某个模型的审美偏好产生大量错误指控。

**最值得实施的版本，是“按需申请、完整审计、证据支持、审慎认证、独立修订”的章节质检系统。**

它可以让第二语言从一个具有自动教材生产能力的个人学习系统，进一步发展成具有**可持续质量治理能力**的教育系统。

目前这是一份基于实际仓库协议与相关评价研究提出的设计方案，尚未修改仓库，也没有对任何正式章节进行真实质检。
