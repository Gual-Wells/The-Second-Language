# 第二语言闭环复查与修复（2026-10-06）

## 范围与结论

本次从当前代码、正式库只读查询、本机计划任务和协议重新核对，不以外部审计结论替代实际检查。范围是日课/临时需求、雅思申请建设、作答批改、原声采集、章节答疑、点读、永久存储、额度记录和发布。没有另建学习者模型、强制复习、专项训练或云端 Codex 任务。

目前核心工程链路具备闭环。复查发现并修正四个真实行为问题及任务收尾遗漏。完整/微缩试卷以隔离数据验证了机械流程；正式库目前没有完整雅思练习册及答卷，不能据此宣称整套真实题目、声音自然度或长期教学效果已验收。

## 本次实际修复

1. **文字答卷重试重复入库。** 原先每次 POST 都由服务器生成新 ID；回包丢失后重试会重复排队。浏览器现先固定 ID、正文与媒介，保留待确认草稿，成功才清除。服务器按相同 ID/题目/正文/媒介复用，同 ID 改内容拒绝；新 ID 仍支持真实重答。重发不改变首次的参考答案查看条件。
2. **音频缺钱后父申请仍可被自动重新领取。** 原先片段停在 waiting_credit，而父请求仍是 building，六小时后普通队列会重新领取。正式音频控制现关联 requestId 与 claimToken，固定本次 setId；额度不足、已知失败、未知计费时停止父建设，保存已有材料。普通 next/claim 排除停止申请。本人明确要求继续时才用 claim ID --continue，成功片段复用，未知收费结果仍不得自动重付。页面在原状态行显示建设停止及材料保留。
3. **原声作答后的揭示顺序记录错误。** 原先 reveal 只检查文字答卷；已提交原声后再看范例仍记为答前查看。现同时检查两种答卷。每份原声/文字答卷的首次条件继续固定，不被后来的揭示重写。
4. **旧发布请求可倒退最新章节。** 原先 commit 无版本顺序保护；较旧暂存版本重发能覆盖当前指针。现按不可变 revision 的插入顺序保护指针，落后请求返回冲突；日课运行和推送仅在对应版本仍为当前时更新。当前版本重发保留原发布时间。旧版本依然可以通过固定摘要读取。
5. **失败路径的收尾。** 音频合成/组装/核验及雅思文字发布/批改脚本将额度核对与归档排队置于 finally，错误不能跳过末尾记录；合成异常也尝试停止自己领取的父申请。ffmpeg 子进程隐藏窗口。旧定时脚本自身的任务末尾核对仍保留。

协议同步了文字重试身份、原声揭示顺序、明确续作、发布版本保护。LISTENING/VOICE_ROUTING 的旧 KV/D1 BLOB 永久存储描述已改为当前 OneDrive 基座、紧凑索引和故障保留副本。
