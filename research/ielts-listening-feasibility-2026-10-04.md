# 第四部分增加雅思听力：可行性与建设建议

研究日期：2026-10-04，北京时间。依据本轮官方资料、当前仓库实现、三音色试听及本人反馈。本文件是研究与建议，不启用正式功能，不迁移数据库，不修改日课或 VIX，也没有额外付费合成。

## 结论

建议将第四部分的产品范围扩展为按申请建设的“雅思练习”，允许单独申请听力，也允许与口语、写作组合申请。听力值得建设：已有支付通路、Cloudflare 推理通路与本人认可的音色，费用较小；新增工作主要在原创材料、题目及答案证据的闭合建设。

优先做一段单人讲话或讲座、约 10 题的完整短练习。它应包含真实的雅思任务方式、连贯音频、可判定答案、作答和精听反馈。短练习通过后再增加双人对话、配对与地图，最后建设四部分 40 题整套模拟。题量与时长是建议起点，不是已敲定的每日任务或永久配额。

声音 A 的本次合格结果可以支持继续建设，不能外推为长篇、多音色、多口音均已验收。费用足够低，无需为价格主动降低已达到的主声音质量。

## 1. 已有真实证据

独立试听共有九段 MP3，覆盖三个短题目片段、三个声音；均可完整解码，Whisper 不带题文提示的转写在忽略标点、大小写后与原文一致。最长片段约 15 秒，所以长讲座、拼写及金额等仍须实际核对。结果见 `trials/question-voices/result.json`。

本人的四项评分分别为：A 全部 5 分且合格，认为适合雅思听力；B 全部 3 分且不合格，认为低沉难受；C 全部 5 分且合格，认为对话感更适合口语。没有选单一偏好。反馈保留在私有云端及忽略的本机文件，不把私人答题记录提交公开仓库。

建议主分工：Microsoft MAI-Voice-2.1 / Harry 用于听力主讲话；Aura-2 / Apollo 用于口语考官提问。淘汰的是本次 Kokoro / George 组合，不把未试听的所有 Kokoro 音色都判为失败。C 可作为未来听力第二人物候选，但还没有听过 A 与 C 拼接的长对话。

Google TTS 首次及明确要求的重试均由 Cloudflare 后端执行，仍返回地区 403，故当前建设不依赖它。

## 2. 与真实考试对齐

听力为四部分，每部分 10 题、总计约 30 分钟，答案线索按题号前后出现，录音只播放一次。四部分依次涵盖日常双人交谈、日常单人讲话、教育或培训讨论、学术单人讲话。题型包括选择、配对、图示标注和多种填空；填写规则及字数上限属于题目本身。[官方听力形式](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-listening)

听力试卷与口语提问的呈现不同：听力题面、选项、空格、表格和地图必须可见；默认隐藏的是录音脚本、译文、正确答案及解析。口语 Part 1/3 的隐藏题文规则不能直接复制到听力。[官方样题](https://ielts.org/take-a-test/preparation-resources/sample-test-questions/academic-test)

不要把章节第三部分原文直接朗读后出题当作主要考试模拟：读过的情节会让记忆参与答题。可以另提供“章节听读复习”，但听力测验应重新建设独立场景、人物和信息，学习过的语言自然迁移进去。

课程来源仍为申请时第一章至最新已发布章，当前章显著优先。来源用于选话题、措辞与教学回链，不要求所有用法出现，也不要求每个小题对应一个课程词。与既有词义关联不强的时间、拼写、数字和方位能力可以作为真实听力训练目标；来源关联适合放在材料或题组层，不机械强迫每个空格都有 USE。

### 官方样例给出的具体启示

本轮回读官方选择题脚本及答案：材料区分“提到的研究资料”和“主要研究资料”，也区分“资料获取困难”和“整理资料困难”。这说明干扰项应在情境中合理出现，关系、重心或态度不同即可；不是把另外两个选项写得明显荒唐。[选择题脚本](https://ielts.org/cdn/computer-delivered-sample-tests-listening/ielts-listening-computer-delivered-multiple-choice-one-answer-transcript.pdf)、[答案](https://ielts.org/cdn/computer-delivered-sample-tests-listening/ielts-listening-computer-delivered-multiple-choice-one-answer-answer-key.pdf)

官方表格填空样例把讲话中的分类、重要程度和具体因素对应到表格，考查跟随信息结构，而非识别一个孤立高级单词。项目应有可见的组织结构及连贯讲解，让填空位置真正反映理解任务。[表格脚本](https://ielts.org/cdn/computer-delivered-sample-tests-listening/ielts-listening-computer-delivered-table-completion-transcript.pdf)、[答案](https://ielts.org/cdn/computer-delivered-sample-tests-listening/ielts-listening-computer-delivered-table-completion-answer-key.pdf)

## 3. 出题与材料应怎样建设

推荐相互修订的工作方式：先选择真实场景和大致信息推进，再拟材料与题组；同时建立每题的证据、转述、干扰和判分说明，回头修订材料与问法。完成后冻结文字版本，再合成声音。不是先确定所有空格，再让人物轮流报答案。

在 `work/expression/<request-id>/listening/` 自由建立材料草稿、题组、答案证据表、反向审题与音频核对记录，下一次直接读取这些文档续作。只保留有助于完成任务的中间产物，不要求额外流程计数或形式化审计。

每题的证据记录至少能解释：

- 题目实际问什么、正确答案及允许写法是什么。
- 哪段发言直接支持答案；为什么不靠课外知识或猜测得出。
- 题面如何转述发言；选择题其他选项为什么不成立。
- 字数限制、数量词和语法是否相互兼容。
- 证据出现在前一题之后、后一题之前；相邻题是否密集得没有合理填写时间。

Codex 需要故意寻找另一成立答案，检查多人观点混淆、早期计划与最终决定、否定和修正、日期金额等细节。检查得到不同答案时先判断是不是坏题，而非坚持答案表。反向审题可借已有 Qwen 或 Gemini 作一次独立试答：只给题面与材料、不给答案，但仍由 Codex 判定争议。同模型重复多次不能制造“独立共识”。这类校验适度进行，不把回答原声分析的固定四路套餐套用到每段合成材料。

难度通过信息结构、合理转述、态度识别、自然修正、连续跟随及合适阅读负荷提高，不靠专业背景、堆稀有词、故意糊音、极快语速或每题都反复改口来提高。为 7.5 方向教学时兼顾基础信息捕捉与较复杂理解，不把一整套材料都写成高难题。

### 可优先建设的题型

| 题型 | 初期建议 | 主要关注 |
|---|---|---|
| 笔记、表格、表单填空 | 优先 | 清楚的结构、唯一答案、词数和实际发音 |
| 单项选择 | 优先 | 三个选项均可理解；答案靠材料关系区分 |
| 配对 | 随后 | 信息顺序、重复选项规则、说话者与观点绑定 |
| 多项选择 | 随后 | 选择数量、答案集合、每个计分空位的处理 |
| 地图、平面图、流程图 | 可建设，但后于文字题组 | 原生 SVG 保持方位稳定；看图尺寸适合锁定缩放的 iPhone；每条路线回读核对 |

地图在复习中可点按放大到同风格独立面板，保留既有全局缩放锁定。不能只用一张图凑题而让路线存在两个合理位置。

## 4. 音频方案与现有能力边界

2026-10-04 实际重新读取公开 TTS 目录，MAI-Voice-2.1 当前价格为每百万字符 $22。英语目录含 Harry、Emily、美国及澳大利亚等音色；目录存在不等于这些音色均已试听通过。[价格与音色入口](https://openrouter.ai/microsoft/mai-voice-2.1)

首轮单人讲话用已通过的 Harry，保留正常英语速度与自然段落节奏。对话按人物分别合成连续发言，后处理统一音量、适当间隔并拼成一段音频；一个人物在同一材料内保持同一音色。优先试听微软另一英语音色，例如 Emily，再决定人物组合。不同品牌音色可组合，但须实际检查音量、节奏与对话衔接。

OpenRouter 的 MAI 接口用标准 input / voice / response_format，内部 SSML 被封装；本轮资料没有确认可直接提交任意 SSML、IPA 或多说话者控制，也没有给出可作为硬上限的 MAI 长文字符限制。目录里的 context_length=0 不能解读为无限长。暂按自然段或连续发言合成，具体片长用实际长材料确认。[TTS 接口](https://openrouter.ai/docs/guides/overview/multimodal/tts)

不在每句话之间切段制造突兀停顿，也不通过原始 MP3 字节简单串接假装完成混音。需要时解码到 PCM 统一参数，按发言或自然段拼接后编码一次，并保存构成清单。使用本机已有 ffmpeg 完成文件处理可行；所有模型调用仍在 Cloudflare 后端，本机后处理不等于本机推理。初期不必为低频文件建设新的云端转码服务。

合成后优先核对否定、单复数、名称拼写、字母、金额、日期和题目答案附近的实际声音，再核对开头、结尾与衔接。Whisper 全文回转写用于发现差异，不能证明字母拼写、所有发音和人声自然度正确。数字文本可以建立明确朗读表达，但必须保留其与脚本和可接受写法的对应关系。

复听定位以实际合成资产和测得的时间区间为依据。按发言合成可由解码后的实际片长计算段落区间；更细证据区间可用 Whisper 词时间戳并核对关键点。不用“第几个词 × 平均秒数”推算证据时间。没有核验的词级定位时，先给可靠段落回听。

短试听已足够支持 Harry 主声音继续建设；下一次有价值的声音验证应是完整几分钟材料、答案区域发音及第二人物，而不是再次横向测几十家模型。

## 5. 读者交互与反馈

进入第四部分，选择听力申请及练习需要。默认没有每日自动听力任务。申请显示来源范围和焦点章，可单独做听力，无须同时完成口语、写作。

打开练习时先显示情境说明、题组与可见题面。读者点按开始，经过明确读题时间后播放；答题时题面持续可见，底部保留轻量播放状态和提交按钮。实际播放时长决定进度，不把 TTS 响应耗时或估算时长用作考试计时。

建议有两种明确条件：

- **测验**：正常速度、材料一次播放、暂不允许自由倒回；不向浏览器下发脚本、译文、答案及解释。
- **精听**：可暂停、回听、慢放及主动查看脚本；记录本次已用的辅助条件。

收到来电、音频焦点丢失、页面退出或网络中断时保存答题草稿及播放位置，允许明确恢复并标记“中断后完成”，不能把故障当作学习者犯错。首次测验与后来精听分别保存尝试，不以更高的重答成绩覆盖首次结果。暂停、跳播和脚本揭示改变练习条件，不伪造真实考试成绩。

提交后由后端即时给出确定性对错、原始得分和题目证据，Codex 随后补充教学解释与下一次训练建议。每道错题可直接回听相关发言，展开句子和译文，再通过已有章节 / USE 索引回到词汇用法。无需把全部长文重新生成。

错题归因区分：实际填词拼写或词数错误、有证据的数字/态度/转述混淆，以及仅可疑的连读或信息跟随问题。仅凭一个错误答案无法断言本人“不会连读”或“听不出重音”；可提供重听问题或一次针对性复答，再做判断。

题组解析可包含简短正确答案、证据解释和干扰分析；这不是口语、写作的 7.5 范文。听力不需要再给一篇“7.5 参考答案”。

## 6. 评分与 7.5 方向

选择题按明确答案判定；填空仅做大小写、必要空白及事先确认的等价写法处理，保留本人原始输入。数字、日期和英美拼写可在建设时列出等价形式，不能运行时对任意词干、复数或错字做模糊放行。词数限制及所填内容是否语法合适要一并处理，多选保存答案集合和计分空位，避免顺序差异误判。

答案争议交给 Codex 审阅，先保留原判定；确认为题目或音频缺陷时标为争议/无效并生成更正版本，不悄悄修改旧题或拿新音频评价旧答卷。练习可以把有效题得分单列，不能把删题后的比例当成官方 40 题分数。

官方听力按 40 题正确数换算 band，示例平均门槛为 7 分约 30、8 分约 35；具体试卷可略有差异。官方题目经过预试和难度校准。[官方评分](https://ielts.org/take-a-test/your-results/ielts-scoring-in-detail)、[官方试题开发](https://ielts.org/organisations/ielts-for-organisations/how-we-develop-the-test)

因此原创十题练习仅显示“答对多少 / 有效题数”和具体能力证据，不乘四换算分数；原创整套也以模拟原始分为主。7.5 是长期训练方向，不是本项目原创题组已经校准的测量值。完整考试熟悉度与分数校准仍应定期参考官方或可靠正式练习材料；本项目主要增加个性化出题、错题回听及章节教学闭环。

## 7. 当前工程差距与建议通路

回读 `worker/src/practice.js`、`worker/practice_migrations/0001_expression.sql`、`web/practice.js` 与 `scripts/practice-job.mjs` 后，现状明确：

- 练习种类只接受 speaking / writing，发布还强制同时包含两种。
- 题目模型围绕单个长题文与参考答案，作答要求至少 20 字符；无法直接表示选项、单词空格及十题共享录音。
- 现有问题列表直接下发 prompt；如果把脚本放进 prompt 会泄题。
- 参考答案揭示目前是题目级永久记录；听力必须另外保存每次尝试前的脚本/答案揭示情况。
- 当前私有音频工程有预建设代码和独立试验资源；不能据此宣称正式 PWA 已完成媒体发布。

建议沿用独立 PRACTICE_DB 的账号、来源快照、索引及练习册，在其中增加听力材料、题组、答案键、资产清单、逐次作答及反馈关联。不新增一个彼此无关联的第三答题数据库，也不往现有口语文字字段塞 JSON 伪装支持。

建议最小内容身份：

1. **材料版本**：脚本、实际朗读文字、说话者、段落/发言编号、来源 digest。
2. **题组版本**：题型、说明、题面、选项、空格、正确答案及等价写法、字数约束、证据段落。
3. **音频版本**：材料 digest、实际发音文本 digest、模型和声音参数、原文件及最终播放资产 digest、已核对时间区间。
4. **尝试**：固定题组与音频版本、原始逐题作答、模式、播放/中断/揭示条件、首次判分。
5. **反馈版本**：争议和更正、Codex 教学解释、章节和 USE 导航、后续复听或练习需求。

采用整段共享音频，题目各有稳定编号，证据引用材料的段落/发言编号。复习时复用固定版本资产，不重新合成；章节编码使用 `章节ID#USE`，不与材料编号混用。长期练习与音频不沿用临时页 48 小时销毁。

工程闭环建议：

```text
PWA 按需申请听力
  → 后端固定来源范围、需求和焦点章
  → Codex 领取，建设材料、题组、证据与解析
  → Cloudflare 调用微软 TTS，保存完整返回及音频
  → ffmpeg 必要处理，Whisper 辅助核对，Codex 语义审阅
  → 私有对象存储 + PRACTICE_DB 发布匹配版本
  → PWA 播放作答，后端即时判分
  → Codex 领取错题及条件，分析、回听导航、下一次训练
```

正式媒体使用私有对象存储及登录同域接口，支持真实 MIME、Range 与按题组取得音频。试验九段音频使用小型独立 KV 是特例，不能直接外推为长期大文件策略。脚本、译文与答案在提交或明确揭示前不进入客户端 JSON、搜索摘要或离线缓存。

OpenRouter 钱包与既有口语分析共用：余额不足保存成稿和已有音频，挂起听力音频生产至北京次日核对充值后续作，日课与写作继续。已成功的片段按摘要复用；401/403 不当余额故障，不无限重试。Aura-2 只有在对应材料实际验收通过且代偿策略明确时介入；不为凑发布静默改变声音，更不把隐藏脚本显示出来假装音频完成。
